# The SMP seam as it stands with threads running on every core: the armv8a doorbell, the
# cross-core kernel lock, and the nine members the KERNEL supplies for a shared kernel's
# backend to call. tests/static/check_smp_sigdiff.sh compares the working tree against this file
# and tests/static/smp_seam_family.awk declares what a member is; the driver and the record
# format are documented in tests/lib/signature_diff.sh.
#
# WHAT MOVED IT, AND THE ONLY THING THAT MAY. The M7.0 set of ten records predated every
# backend and the first backend's commit added seven, the lock's six and KICKOS_KERNEL_CORES.
# This set adds eight and CHANGES NONE of the seventeen: kickos_switch_unlock, which ends the
# lock's span over a context switch; kickos_kernel_core_ready and kickos_kernel_core_start, the
# two halves of a peer core's arrival at the scheduler; and kickos_kernel_core_resched, the
# doorbell's scheduling half. All four are the direction the seam already carried
# kickos_isr_timer in, the kernel supplying and the backend calling, so no port owes an
# implementation. Every earlier record is byte-identical, which is what says threads on four
# cores were reached through the seam rather than by reshaping it.
#
# This set adds four and CHANGES NONE of the twenty-five. Three run in the direction
# kickos_kernel_core_resched already did, the kernel supplying and the backend calling:
# kickos_kernel_core_resched_owe publishes a reschedule owed to a peer ahead of the raise
# that wakes it, _owed reads that cell without consuming it, and _take is the one body that
# clears it. The fourth, arch_ipi_resched_self, runs the other way and is the first member a
# port owes an implementation for since the lock's six: a backend whose doorbell can be
# absorbed by its own acquire loop has to be able to raise one on itself again.
#
# This set adds two and CHANGES NONE of the twenty-nine. Both run in the direction
# kickos_kernel_core_ready already did, the kernel supplying and the backend calling, and both
# are one bring-up handshake: kickos_kernel_core_seated is the acquire half of the release the
# kernel makes once a core's control block is complete, and kickos_kernel_core_arrive is how
# that core publishes its commitment to its own scheduler. Neither reads the kernel lock, and
# no port owes an implementation.
#
# This set adds none and MOVES ONE DIRECTION. kickos_kernel_core_resched_owe was added above as
# a member the backend calls, and separating the doorbell's rendezvous half from its scheduling
# half left it with no backend caller: the kernel publishes for its own raise, in
# kickos::klock_resched_ask, and arch_ipi_send is a doorbell alone. Its signature and guard are
# unchanged, which is why no record below moves. _owed and _take still run the direction the
# note above records, called from klock_armv8a.cc and arch_arm64_gicv2.cc respectively.
#
# This set adds TWO and CHANGES NONE of the forty-one. Both are the one member an AMP node's
# backend calls, kickos_amp_node_service, in the direction kickos_kernel_core_resched already
# ran: the kernel supplies and the backend calls, from its doorbell SERVICE BODY and after the
# answer stores, so a payload drain cannot delay a rendezvous. It has ONE arm and no fold,
# being declared under the unshared model alone. That every earlier record is byte-identical is
# what says a second MODEL was built on this seam rather than out of it -- the same reading the
# RV64 backend's verdict carried for a second lowering.
#
# ADMITTING IT MOVED THE FAMILY'S PREFIX, AND THAT IS THE FINDING THIS ADDITION CARRIES.
# Membership is an ALLOWLIST of identifier prefixes, so a member named outside it is a member
# no verdict guards, and the group table's refusal of an unclassified member cannot see one the
# family never admitted. The first AMP member was named outside it and the differ passed over
# it in silence.
#
# This set adds NONE, removes NONE, and MOVES NINE, which is the verdict this addition wanted
# rather than one it worked around. arch_ipi_send, arch_ipi_wait and arch_ipi_counts widen
# their guard from the core count alone to the count OR the AMP posture, and each is recorded
# three times -- FUNC, FUNCNAMES, and the MACROFN carrying the negated fold -- so nine records
# carry one change. WHAT IT BUYS: an own-image node drives one core, so under the old guard the
# doorbell folded to an empty macro and amp::send published into the window and rang nobody, in
# silence. Declared, a port that raises the posture and ships no backend fails to LINK, which
# is the shape arch_cpu_id already had against the count. NOTHING ELSE MOVES, arch_cpu_id and
# arch_ipi_resched_self included: the identity still folds at one core because an own-image
# node reads its node from a build constant, and the reschedule half still folds on
# KICKOS_KERNEL_CORES because an AMP node schedules one core. The guards are PARENTHESISED at
# the source, which is why every record reads as one term: arch_ipi_counts nests inside the
# selftest guard, and the extractor joins nested guards with && and no parentheses of its own,
# so an unbracketed disjunction would have recorded as (A && B) || C where the preprocessor
# reads A && (B || C).
#
# REGENERATING THIS FILE DELETES THE FINDING THE GATE EXISTS TO PRODUCE. Rewritten outside the
# commit that deliberately moves a member, it measures a backend against itself.
# KOS_SIGDIFF_REGEN=1 rewrites it and takes no verdict; use it only in the commit that
# deliberately moves a member, never to quiet a red gate.
#
# Regenerated, when a milestone deliberately moves the seam, by:
#   KOS_SIGDIFF_REGEN=1 sh tests/static/check_smp_sigdiff.sh
#
# Four TAB-separated fields per record: <kind> <name> <detail> <preprocessor guard>.
