# Declarations for tests/static/check_trap_redzone.sh: WHICH symbols a trap prologue can reach,
# WHICH macro holds the figure it enforces, and WHAT the graph is allowed not to know. The macro
# names are resolved through the compiler under the flags the image was built with.
#
# A CLASS is one (FRAME, DEPTH) pair with its own root set. A trap prologue reserves FRAME plus
# DEPTH at the bottom of the interrupted stack and refuses the trap when less room than that
# remains below sp. DEPTH is the half this gate MEASURES, the worst-case bytes the kernel C
# dispatch descends on that same stack; FRAME is everything else in the zone, which on armv7m
# also carries the hardware frame a preempting exception stacks and no call graph can see.
#
# File format, one record per line, '#' starts a comment:
#   arch    <arch> header=<path-relative-to-source-dir>
#   preset  <arch> <configure-preset>
#   class   <arch> <CLASS> frame=<MACRO> depth=<MACRO> [stack=trap|stack=kernel] \
#                                                        [kstacks=0|kstacks=1]
#   root    <arch> <CLASS> [?]<symbol>
#   root    <arch> <CLASS> NONE reason: <text to end of line>
#   exclude <arch> <mangled-symbol> reason: <text to end of line>
#   unsized <arch> <symbol> <bytes> reason: <text to end of line>
#
# A '?' before a root or an `exclude` marks it OPTIONAL: the symbol is compiled out under some
# option, or absent from some boards' graphs, so its absence contributes 0 instead of failing.
# A root with no '?' that is missing is a hard failure. A '?' exclusion the graph does not have
# is reported as unused.
#
# NONE declares that the class runs NO C on the guarded stack, so its depth is 0 and there is
# nothing to walk. A class with no record at all is refused: an empty root set measures 0 and
# passes forever.
#
# A `root` symbol matches the graph as an exact name or as the mangled tail of a file-scoped
# one; the match must be UNIQUE, and an ambiguous name is refused rather than guessed at.
#
# EVERY PRESET OF EVERY ARCH BELONGS HERE. A `preset` record is what makes a (board, variant)
# pair measurable at all, and a variant is measurement-relevant when it changes any of
# KICKOS_BENCH (a syscall arm that prints), KICKOS_TELEMETRY (the trace emitters and the ring
# drain arch_shutdown runs), KICKOS_ENABLE_SELFTEST (syscall arms of its own), the memory model
# (MPU against FLAT moves the grant and commit chains BOTH ways), or the console backend (per
# BOARD, and the tail every printing chain ends in). A board's variants differ by exactly those
# knobs.
#
# The top-level CMakeLists derives the preset name from the board and variant it is configuring
# and asks THIS FILE whether that name is declared, so a new preset is declared once.
#
# lx6 carries one class. CHIP_ESP32 selects no HAS_MPU, so nothing on that part isolates one
# thread's memory from another's and the syscall classes have no one to protect. PREEMPT applies
# with or without an MPU -- whether the involuntary frame FITS the stack it lands on.
#
# stack=trap says the descent runs on a static kernel stack the arch owns. The SPAWN FLOOR
# clause does not apply, and neither does the declared `exclude` set, a panic tail being
# excluded only to keep a THREAD's red zone under the spawn floor.
#
# stack=kernel says the descent runs on the interrupted thread's PER-THREAD KERNEL block, one
# KICKOS_KERNEL_STACK_SIZE per thread slot in kernel .bss, so frame plus depth is a requirement
# on THAT knob and the gate compares it against the block. The lowest word of a block is its
# overflow canary, so the fit has to leave that word alone. Same two consequences as stack=trap,
# and it drops BOTH halves where KICKOS_KERNEL_STACKS is 0. stack=trap and stack=kernel are
# exclusive.
#
# kstacks=<n> says the class belongs to ONE of the two entry designs an arch can compile, the
# one KICKOS_KERNEL_STACKS selects at <n>. Where the knob disagrees the image does not contain
# the path, so check_trap_redzone.sh measures the class, PRINTS that it is not enforcing it, and
# drops both halves. stack= says which stack a descent lands on, kstacks= whether the image
# contains that descent at all. Only armv7m needs it; rv32imac, rxv3 and armv6m each
# static_assert KICKOS_KERNEL_STACKS != 0.

# --- rv32imac ------------------------------------------------------------------
# SEVEN classes. Two registers separate the six trap ones, both readable before the frame is
# built. mcause picks the entry: the .Lintr arms take TRAP, msip takes SWITCH, an ecall takes
# SYS or SYSPRIV, and any other exception takes FAULT. mstatus.MPP then picks the stack: an
# ecall from U-mode is SYS on the thread's kernel block, the same ecall from M-mode is SYSPRIV
# on the sp it interrupted, and every M-mode cause that is not msip or an ecall is NESTED on the
# kernel's own trap stack.
#
# EXIT measures the death path, which runs after the entry has handed control back: .Lfault
# relocates sp to the top of the dying thread's own stack and mrets into the exit stub, so the
# descent is privileged on the stack of a thread of any privilege. The SPAWN FLOOR clause is the
# only thing that bounds it.
#
# SYSPRIV is the SYS entry reached from M-mode: same FRAME_SYS, same roots, but the frame stays
# on the sp it interrupted, that thread's own stack, so it takes the depth macro with the panic
# tail excluded. With EXIT it is what sets KICKOS_MIN_STACK_SIZE on this arch. Its depth macro
# is the one posture-dependent figure in this file, resolving per KICKOS_BENCH in
# rv_trap_stack.h.
#
# FAULT is the accepted U-mode fault: .Lfault runs the reporter with sp on the frame the entry
# built, which is the kernel block, so the whole dump chain lands there. It is the KERNEL BLOCK
# it has to fit.
#
# SWITCH is the one class still on a thread stack and must not be deleted: .Lswitch and
# arch_start call kickos_arch_mpu_commit with sp = incoming->sp, which for a thread that has
# never trapped is the frame arch_context_init fabricated on its USER stack. Measuring 0 there
# is what says no privileged C frame stands on user memory. rv_trap_stack.h also composes this
# class INTO the syscall requirement.
arch    rv32imac header=arch/riscv/rv32imac/include/kickos/arch/rv_trap_stack.h
preset  rv32imac qemu-riscv
preset  rv32imac qemu-riscv-flat
preset  rv32imac qemu-riscv-bench
preset  rv32imac esp32c6-wroom
preset  rv32imac esp32c6-wroom-st
preset  rv32imac esp32c6-wroom-flat
preset  rv32imac esp32c6-wroom-bench
class   rv32imac TRAP   frame=KICKOS_RV_TRAP_FRAME depth=KICKOS_RV_TRAP_KERNEL_DEPTH stack=kernel
class   rv32imac SYS    frame=KICKOS_RV_TRAP_FRAME_SYS depth=KICKOS_RV_TRAP_KERNEL_DEPTH_SYS stack=kernel
class   rv32imac SYSPRIV frame=KICKOS_RV_TRAP_FRAME_SYS depth=KICKOS_RV_TRAP_KERNEL_DEPTH_SYS_NO_PANIC
class   rv32imac FAULT  frame=KICKOS_RV_TRAP_FRAME depth=KICKOS_RV_TRAP_NESTED_DEPTH stack=kernel
class   rv32imac SWITCH frame=KICKOS_RV_TRAP_FRAME depth=KICKOS_RV_TRAP_SWITCH_DEPTH
class   rv32imac NESTED frame=KICKOS_RV_TRAP_FRAME depth=KICKOS_RV_TRAP_NESTED_DEPTH stack=trap
class   rv32imac EXITK  frame=KICKOS_RV_TRAP_NEST_EXIT depth=KICKOS_RV_TRAP_KERNEL_DEPTH_EXITK stack=kernel
class   rv32imac RET    frame=KICKOS_RV_TRAP_NEST_EXIT depth=KICKOS_RV_TRAP_KERNEL_DEPTH_RET

# .Lfault, for a U-mode fault the entry ACCEPTED: the reporter and the stack-top query run on
# the frame the entry built, which is the kernel block. This charges the deeper of the kill and
# panic paths, so no claim about C control flow is needed.
root    rv32imac FAULT kickos_rv_fault_report
root    rv32imac FAULT kickos_fault_stack_top

# EXITK is the fault and slay stubs on the thread's own KERNEL BLOCK: .Lfault relocates sp to
# kickos_fault_stack_top, which answers with ctx.kernel_sp, and arch_ctx_redirect rebuilds the
# slay frame at that same top. RET is kickos_thread_return, which nothing relocates, so the
# SPAWN FLOOR clause is the whole of ITS enforcement. The frame term is the msip frame on both:
# the stubs reschedule, and an msip trap from M-mode keeps its frame on the interrupted sp.
root    rv32imac EXITK kickos_thread_fault_exit
root    rv32imac EXITK kickos_thread_slay_exit
root    rv32imac RET   kickos_thread_return

# What .Lswitch itself calls, below the frame it just saved.
root    rv32imac SWITCH kickos_arch_mpu_commit
root    rv32imac SWITCH ?kickos_trace_switch_done
root    rv32imac SWITCH ?kickos_bench_switch_done

# The four .Lintr arms again, an M-mode entry running them on the trap stack instead, plus

root    rv32imac NESTED kickos_rv_ext_dispatch
root    rv32imac NESTED kickos_rv_ext_dispatch_dev

root    rv32imac NESTED kickos_fault_stack_top
root    rv32imac NESTED ?kickos_rv_nested_witness
# .Ltrap_wild's containment call. A U-MODE entry and not a nested M-mode trap, so it is here
# for the STACK and not the cause: sp is the trap top at that label, which is the one this
# class measures. kickos_arch_mpu_commit below it is charged to SWITCH instead, the containment
# moving sp onto the incoming frame before that call exactly as .Lswitch does.
root    rv32imac NESTED kickos_rv_contain_wild_sp

# The two exclusions serve SYSPRIV and EXIT, the rv32imac classes on a thread stack. A

# --- rxv3 ----------------------------------------------------------------------
# FOUR classes. PENDSW is the deferred-switch vector (INTB[27]); the syscall trap then splits,
# kickos_rx_syscall_trap's `cmp #56, r1` picking between a generic arm that stashes the
# [userPC][userPSW] head and RTEs into svc_trampoline, and a fastpath arm that saves the whole
# 236-byte context and runs kickos_ipc_fastpath inline. Different frame AND different descent,
# so each is its own class.
#
# The generic arm's dispatch is SYSK, stack=kernel, svc_trampoline's first act being to move R0
# onto the calling thread's own kernel block.
#
# The SYS class must not be deleted, and it is the one class here with no root at all. The head
# the trap commits before its RTE still lands on the thread's own stack, because RTE pops PC
# then PSW from R0 and R0 is the USP while PSW.U is set, so the resume USP is that head's
# address plus eight. KICKOS_RX_TRAP_NEST_SYS prices the head plus the switcher zone a SWINT can
# put below it while svc_trampoline is still on that stack.
arch    rxv3 header=arch/rx/rxv3/include/kickos/arch/rx_trap_stack.h
# Every rxv3 preset, per the knob rule above.
preset  rxv3 rx72m
preset  rxv3 rx72m-st
preset  rxv3 rx72m-flat
class   rxv3 PENDSW   frame=KICKOS_RX_TRAP_FRAME_PENDSW   depth=KICKOS_RX_TRAP_KERNEL_DEPTH_PENDSW
class   rxv3 SYS      frame=KICKOS_RX_TRAP_NEST_SYS       depth=KICKOS_RX_TRAP_KERNEL_DEPTH_SYS
class   rxv3 SYS_FAST frame=KICKOS_RX_TRAP_FRAME_SYS_FAST depth=KICKOS_RX_TRAP_KERNEL_DEPTH_SYS_FAST
class   rxv3 SYSK     frame=KICKOS_RX_TRAP_NEST_SYSK      depth=KICKOS_RX_TRAP_KERNEL_DEPTH_SYSK stack=kernel
# THE DEATH PATH. The backend rewrites the stacked PC so the RTE lands in a stub with R0 at
# kickos_fault_stack_top, which answers with ctx.kernel_sp. EXITK is the two relocating stubs on
# the block; RET is kickos_thread_return, which cannot move.
class   rxv3 EXITK    frame=KICKOS_RX_TRAP_NEST_EXIT      depth=KICKOS_RX_TRAP_KERNEL_DEPTH_EXITK stack=kernel
class   rxv3 RET      frame=KICKOS_RX_TRAP_NEST_EXIT      depth=KICKOS_RX_TRAP_KERNEL_DEPTH_RET

root    rxv3 PENDSW kickos_arch_mpu_commit
root    rxv3 PENDSW ?kickos_trace_switch_done
root    rxv3 PENDSW ?kickos_bench_switch_done

root    rxv3 SYS    NONE reason: svc_trampoline moves R0 to ctx.kernel_sp before it calls anything, so syscall_dispatch and the tree under it are measured as SYSK. What is left on the thread's own USP at this site writes no C frame: the trap's [userPC][userPSW] head, which the RTE's resume-USP arithmetic requires there. KICKOS_RX_TRAP_NEST_SYS prices it plus the switcher zone a SWINT can put below it. THE SECOND DOOR runs no C frame here either: .Lsvc_nokstack reaches kickos_rx_no_kernel_stack, whose console chain is far past what this class reserves, and clrpsw u puts that reporter on the ISP before the call.

root    rxv3 SYSK   syscall_dispatch
root    rxv3 SYSK   kickos_ipc_fastpath

root    rxv3 EXITK  kickos_thread_fault_exit
root    rxv3 EXITK  kickos_thread_slay_exit
root    rxv3 RET    kickos_thread_return

# The taken fastpath switches, so it runs the same epilogue hooks the switcher does, and after
# the transfer that epilogue is ALL it runs on a thread stack.
root    rxv3 SYS_FAST kickos_arch_mpu_commit
root    rxv3 SYS_FAST ?kickos_trace_switch_done
root    rxv3 SYS_FAST ?kickos_bench_switch_done

# --- armv7m --------------------------------------------------------------------
# THREE classes, two of them the same dispatch under the two entry designs this arch compiles.
# KICKOS_KERNEL_STACKS picks which one an image links: at 1 svc_trampoline moves SP onto the
# calling thread's own kernel block before it calls anything, so the dispatch is SVCK,
# stack=kernel; at 0 it runs the dispatch on the caller's own PSP and the dispatch is SVC, on
# the thread stack. armv7m_trap_stack.h says which chips take which.
#
# Both classes are measured on every preset and only one is enforced on any given one. The call
# graph cannot say which design an object linked; the gate reads KICKOS_KERNEL_STACKS out of the
# board config it just generated, which is what the kstacks=0 marker on SVC and stack=kernel on
# SVCK are spent on.
#
# The SVC class is what the SPAWN FLOOR clause binds. PENDSV takes FRAME_MAX, its own worst-case
# push, and is the same under both designs and therefore unmarked, handler mode putting
# everything it calls on the MSP.
arch    armv7m header=arch/arm/armv7m/include/kickos/arch/armv7m_trap_stack.h

# frames between the trampoline and the preemption point, so the preempting entry's STKALIGN pad
# stops cancelling. Provisioning it in the frame is what makes the depth comparison below
# (measured <= depth) the right test for every parity.
class   armv7m SVC    frame=KICKOS_ARMV7M_TRAP_NEST_SVC_DISPATCH \

#
# EXITK is the two relocating stubs wherever a block is seated. kickos_fault_stack_top answers
# with ctx.kernel_sp, so the fault redirect and the slay rebuild both land at the block TOP.
class   armv7m EXITK  frame=KICKOS_ARMV7M_TRAP_NEST_EXIT \
                      depth=KICKOS_ARMV7M_TRAP_KERNEL_DEPTH_EXITK stack=kernel

# resolve KICKOS_KERNEL_STACKS 0, so all three stubs stay on the thread's own stack against the
# spawn floor. KICKOS_KERNEL_STACKS needs the chip's HAS_MPU, which stm32f103, stm32f302 and
# sam3x8e do not select.
class   armv7m EXIT   frame=KICKOS_ARMV7M_TRAP_NEST_EXIT \
                      depth=KICKOS_ARMV7M_TRAP_KERNEL_DEPTH_EXIT kstacks=0

# privileged thread's entry returning, with no fault and no redirect, so nothing relocates it.
class   armv7m RET    frame=KICKOS_ARMV7M_TRAP_NEST_EXIT \
                      depth=KICKOS_ARMV7M_TRAP_KERNEL_DEPTH_RET

What the MSP has to hold is a kernel-stack sizing question, not a privilege one, and no figure here bounds it.

# --- armv6m --------------------------------------------------------------------
# THREE classes, the same split as armv7m: both guarded pushes in switch.S happen in HANDLER
# mode, where ARMv6-M forces SP_main (ARMv6-M ARM B1.4.1), so the switcher's calls and the SVC
# fastpath's kickos_ipc_fastpath descend on the MSP. The SVC slow path leaves handler mode and
# svc_trampoline moves SP onto the calling thread's own KERNEL BLOCK, so SVCK is what measures
# the dispatch.
#
# The SVC class must not be deleted: the fastpath arm's callee block and the trampoline's eight
# scratch bytes still land on the thread's PSP, and NEST_SVC prices them plus the exception pair
# that can preempt the window between them. PENDSV takes the push itself. There is no FP term on
# this arch.
arch    armv6m header=arch/arm/armv6m/include/kickos/arch/armv6m_trap_stack.h
# Every armv6m preset, per the knob rule above.
preset  armv6m microbit
preset  armv6m picopi
preset  armv6m picopi-st
preset  armv6m picopi-flat
class   armv6m PENDSV frame=KICKOS_ARMV6M_TRAP_FRAME \
                      depth=KICKOS_ARMV6M_TRAP_KERNEL_DEPTH_PENDSV
class   armv6m SVC    frame=KICKOS_ARMV6M_TRAP_NEST_SVC \
                      depth=KICKOS_ARMV6M_TRAP_KERNEL_DEPTH_SVC
# The death path. EXITK is the two relocating stubs on the block; RET is kickos_thread_return,
# which cannot move and stays against the spawn floor.
class   armv6m EXITK  frame=KICKOS_ARMV6M_TRAP_NEST_EXIT \
                      depth=KICKOS_ARMV6M_TRAP_KERNEL_DEPTH_EXITK stack=kernel
class   armv6m RET    frame=KICKOS_ARMV6M_TRAP_NEST_EXIT \
                      depth=KICKOS_ARMV6M_TRAP_KERNEL_DEPTH_RET
class   armv6m SVCK   frame=KICKOS_ARMV6M_TRAP_NEST_SVCK \
                      depth=KICKOS_ARMV6M_TRAP_KERNEL_DEPTH_SVCK stack=kernel

root    armv6m PENDSV NONE reason: PendSV_Handler and the SVC fastpath arm run in handler mode, where ARMv6-M forces SP_main, so kickos_arch_mpu_commit, kickos_ipc_fastpath and the telemetry hook all descend on the MSP. What the MSP has to hold is a kernel-stack sizing question, not a privilege one, and no figure here bounds it.
root    armv6m SVC    NONE reason: svc_trampoline moves SP to ctx.kernel_sp before it calls anything, so syscall_dispatch and the tree under it are measured as SVCK. What is left on the thread's PSP at this site writes no C frame at all: the fastpath arm's callee block, in handler mode, and the trampoline's own scratch push. NEST_SVC prices both plus the exception pair that can preempt the window between them.

# svc_trampoline's only call, on the calling thread's kernel block. The fastpath is reached with
# lr still an EXC_RETURN, in handler mode, on the MSP, so it roots nothing here.
root    armv6m SVCK   syscall_dispatch

root    armv6m EXITK  kickos_thread_fault_exit
root    armv6m EXITK  kickos_thread_slay_exit
root    armv6m RET    kickos_thread_return

# The AEABI helpers are libgcc, with no .ci entry and none for anything they call, so each
# figure is the symbol's own prologue plus the deepest chain below it, from libgcc.a for this
# multilib (thumb/v6-m/nofp). On arm-none-eabi a frameless leaf costs 0, the return address
# arriving in LR. The chains: __aeabi_ldivmod pushes 16 and calls __gnu_ldivmod_helper (32)
# which calls __divdi3 (40) which calls __clzdi2 (8); __aeabi_uldivmod pushes 16 and calls
# __udivmoddi4 (48) which calls __clzdi2 (8).
unsized armv6m __aeabi_ldivmod  96 reason: measured, 16-byte head plus __gnu_ldivmod_helper's 80
unsized armv6m __aeabi_uldivmod 72 reason: measured, 16-byte head plus __udivmoddi4's 56
unsized armv6m __aeabi_lmul     24 reason: measured, pushes {r4-r7,lr} then {lr}, calls nothing
unsized armv6m __aeabi_uidiv     8 reason: measured, an alias of __udivsi3 at the same address
unsized armv6m __aeabi_uidivmod  8 reason: measured, tail-branches into __udivsi3, whose worst path is its 8-byte divide-by-zero tail
unsized armv6m __clzsi2          0 reason: measured, frameless register-only leaf
unsized armv6m __ctzsi2           0 reason: measured, frameless register-only leaf

Counting it takes PREEMPT to 608 and the zone to 864, which sizes this board's idle stack for a chain that ends in a halt rather than in a resume. Excluded on the same terms as rv32imac and armv7m; the residual is stated in lx6_trap_stack.h and the tool prints the without-exclusions figure so it cannot go quiet.
