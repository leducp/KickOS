# KickOS invariants

> Reference (code-synced). The cross-cutting properties a change must not break,
> extracted by the M1.x close-out review across the arch seam, kernel, per-arch
> backends, and docs. Each is a *checklist item* for future milestones (M2 above
> all): re-audit the whole arch/chip/board matrix against these, hunting both
> drift (one arch violates what the others uphold) and absence (a backend that
> forgot one). `source` cites where it lives in the code.
>
> **Cite symbols, not line numbers.** A `file:start-end` range is wrong the moment
> anything above it moves, and it fails silently -- the range still resolves, just
> to the wrong code. Several citations here pointed into `syscall.cc` at lines that
> no longer existed after the per-domain split (`syscall_thread.cc`,
> `syscall_ipc.cc`, `syscall_obj.cc`, `syscall_mem.cc`). Prefer
> `file (symbol / the thing it guards)`; keep a line range only for a fixed asm
> frame or a struct-offset pin, where the line IS the fact.
>
> The per-arch `applies:` lists below name armv7m / armv6m / rx / xtensa. The
> **rv32imac** (RISC-V: ESP32-C6 + QEMU `virt`) port implements the same
> context-switch, critical-section (`mstatus.MIE`), deferred-switch (CLINT `msip`),
> tickless-timer, and telemetry (`rdcycle`) contracts and must be audited alongside
> them; its FP-save invariants are N/A (soft-float, no FP register file). Treat a
> missing rv32imac mention in a specific item as "audit it too", not "exempt".

## Context switch & FP save/restore

- **`switch-frame-matches-init`** -- The frame fabricated by arch_context_init must be byte-identical to what the context-switch save path pushes/pops (same order, same slots), and the arch_context field offsets the asm hard-codes (sp@0, npriv@4, resting_npriv@8, trace_tid@12 on armv7m; sp@0/trace_tid@4 on rx; sp/ps/pc/resume_kind/trace_tid on xtensa) must stay pinned by static_assert. A silent struct reorder or frame-layout drift corrupts the saved SP/privilege on the first switch-in.
  - *applies:* context switch; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc (the arch_context offsetof static_asserts, arch_context_init); arch/arm/armv7m/switch.S (PendSV_Handler, under the saved-frame layout comment it must match); arch/rx/rxv3/arch_rxv3.cc (the arch_context offsetof static_asserts, arch_context_init); arch/xtensa/lx6/arch_xtensa.cc (the arch_context offsetof static_asserts, arch_context_init)

- **`npriv-banked-on-switch`** -- CONTROL.nPRIV is saved and restored per switch as if it were a register (ctx.npriv), NOT reset to the thread's resting posture: a thread blocked mid-syscall runs privileged (the SVC trampoline raised it) and must resume privileged. arch_context_init seeds ctx.npriv AND ctx.resting_npriv from the thread's resting privilege.
  - *applies:* context switch + privilege; armv7m, armv6m (rx uses banked PSW.PM the same way)
  - *source:* arch/arm/armv7m/include/kickos/arch/context.h (arch_context::npriv, arch_context::resting_npriv); arch/arm/armv7m/switch.S (PendSV_Handler's CONTROL save and restore); arch/arm/armv7m/arch_armv7m.cc (arch_context_init, which seeds both)

- **`fp-armv7m-lazy-frame`** -- On an FPU-equipped ARMv7-M part the extended FP state is saved/restored conditionally on EXC_RETURN bit4: PendSV must vstmdb {s16-s31} BEFORE stmdb {r4-r11,lr} (higher addresses) on save and vldmia AFTER the callee pop on restore, so a thread with no live FP context carries no FP frame. Breaking the bit4 test or the push/pop ordering corrupts FP state across a switch.
  - *applies:* context switch, FP save/restore; armv7m with __ARM_FP
  - *source:* arch/arm/armv7m/switch.S (PendSV_Handler's __ARM_FP vstmdbeq / vldmiaeq pair)

- **`fp-rx-full-context`** -- The RX SWINT switcher saves the full context each switch: R1-R15 (single-precision FP lives in the GPR file), FPSW, both accumulators, and -- under -mdfpu -- the DPFPU file (DR0-DR15 + DPSW/DCMR/DECNT via DPUSHM/DPOPM); arch_context_init fabricates exactly those slots with the DPFPU reset posture (DPSW=0x100, DECNT=1). Dropping -mdfpu must leave the slots carrying zeroes, not desync the frame.
  - *applies:* context switch, FP save/restore; rxv3 (rx72m)
  - *source:* arch/rx/rxv3/arch_rxv3.cc (arch_context_init's fabricated frame, the __RX_DFPU_INSNS__ slots); arch/rx/rxv3/switch.S (the dpushm/dpopm blocks in _arch_switch and _kickos_rx_restore)

- **`fp-xtensa-caller-saved`** -- On LX6 CPENABLE is global (CP0 enabled for all threads), so FP data registers are NOT banked by that enable. The cooperative (thread-context) switch relies on the compiler spilling caller-saved FP regs; only the preemptive level-1 interrupt frame saves f0-f15+FCR+FSR. A change that assumes the cooperative path saves FP registers is wrong.
  - *applies:* context switch, FP save/restore; xtensa lx6 (esp32)
  - *source:* arch/xtensa/lx6/arch_xtensa.cc (kickos_lx6_init's CPENABLE write); arch/xtensa/lx6/include/kickos/arch/xtensa_frame.h (F_F0 / F_FCR / F_FSR, the level-1 frame's FP slots); arch/xtensa/chip/esp32/startup.S (the level-1 entry's FP save and restore)

## Critical section & interrupt-priority bands

- **`irqlock-nesting-safe`** -- IrqLock must record the prior interrupt-mask state and restore exactly that on scope exit (never unconditionally unmask), so nested critical sections compose. Every arch's arch_irq_save/restore returns/consumes the full prior state (BASEPRI word, PSW.IPL field, PS, or the sim's SIGALRM/SIGUSR1 unblocked flags).
  - *applies:* critical section / IrqLock; all arches
  - *source:* kernel/include/kickos/irqlock.h (IrqLock); arch/arm/armv7m/arch_armv7m.cc (arch_irq_save / arch_irq_restore); arch/rx/rxv3/arch_rxv3.cc (arch_irq_save / arch_irq_restore); arch/xtensa/lx6/arch_xtensa.cc (arch_irq_save / arch_irq_restore); arch/sim/sim.cc (arch_irq_save / arch_irq_restore)

- **`basepri-write-needs-barrier`** -- On ARMv7-M, raising BASEPRI is not self-synchronizing: arch_irq_save must follow the msr with DSB+ISB, else an interrupt can still be taken under the old mask on the next instruction and preempt a critical section. (RX MVTIPL and Xtensa RSIL are self-synchronizing and correctly omit the dance.)
  - *applies:* critical section; armv7m
  - *source:* arch/arm/armv7m/arch_armv7m.cc (arch_irq_save, the msr basepri + DSB/ISB); arch/rx/rxv3/arch_rxv3.cc (arch_irq_save, the bare MVTIPL)

- **`device-irq-in-maskable-band`** -- A device IRQ line's priority MUST be programmed into the IrqLock-maskable band BEFORE the line is enabled, or an IRQ can preempt an IrqLock-held section and corrupt kernel state. Bands: armv7m PRIO_DEVICE=0x30 >= lock 0x20; rx IPL_DEVICE=4 < IPL_LOCK=12; xtensa masks levels 1-3. NVIC IPR / ICU IPR reset to 0 (highest), so the write is mandatory, not optional.
  - *applies:* ISR priority bands; armv7m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc (arch_irq_unmask, the NVIC IPR write ahead of the enable); arch/arm/armv7m/regs.h (PRIO_LOCK_BASEPRI / PRIO_DEVICE); arch/rx/rxv3/arch_rxv3.cc (arch_irq_unmask, the ICU IPR write ahead of icu_ier_set); arch/rx/rxv3/regs.h (IPL_LOCK / IPL_DEVICE); arch/xtensa/lx6/arch_xtensa.cc (KICKOS_IRQ_LOCK_LEVEL, the RSIL level arch_irq_save raises to)

- **`deferred-switch-lowest-band`** -- The deferred-switch mechanism (PendSV / RX SWINT / xtensa L1-exit) must sit at the lowest active priority AND below the IrqLock threshold, so a switch requested from an ISR fires only after every other exception tail-chains and only once the requesting critical section releases. armv7m PRIO_PENDSV=0xF0; rx IPL_PENDSW=1 (< IPL_LOCK=12).
  - *applies:* deferred-switch model, ISR bands; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/switch.S (PendSV_Handler); arch/arm/armv7m/regs.h (PRIO_PENDSV); arch/arm/armv7m/arch_armv7m.cc (kickos_armv7m_init's SHPR writes); arch/rx/rxv3/arch_rxv3.cc (kickos_rxv3_init's ICU_IPR_SWINT = IPL_PENDSW); arch/xtensa/lx6/arch_xtensa.cc (arch_switch's g_arch_switch_pending); arch/xtensa/chip/esp32/startup.S (the level-1 exit that consumes it)

## Deferred switch & blocking model

- **`arch-switch-may-defer`** -- arch_switch MAY not complete synchronously (ARM/RX pend an exception, xtensa flags g_arch_switch_pending when in ISR); the scheduler must not assume the register swap has happened when arch_switch returns. The switch target crosses only through g_arch_next/g_arch_current -- PendSV saves g_arch_current and ignores the `from` argument.
  - *applies:* deferred-switch model; all arches
  - *source:* arch/include/kickos/arch/arch.h (the arch_switch contract); arch/arm/common/arch_arm_common.cc (arch_switch, g_arch_current / g_arch_next); arch/xtensa/lx6/arch_xtensa.cc (arch_switch's g_arch_switch_pending); docs/reference/architecture.md

- **`no-block-from-isr`** -- Blocking (sem_wait, sleep, any detach_current/block_current path) is legal ONLY from thread context: it relies on arch_switch completing synchronously. From ISR context the switch would defer and the 'blocked' thread would keep running, so detach_current panics when arch_in_isr() is true.
  - *applies:* deferred-switch model, sync primitives; kernel + all arches
  - *source:* kernel/sched/sched.cc (detach_current's arch_in_isr panic, block_current); kernel/sync/sync.cc (wq_block, sem_wait)

- **`exit-parks-for-deferred-switch`** -- exit_current must not run off the end after committing the switch-away: on a deferring arch the PendSV/SWINT can only fire once the IrqLock releases, so the EXITED thread (off the ready set, never rescheduled) must park in an arch_idle_wait loop until the pended switch lands. Running past with the switch merely pending is a known-fixed bug class.
  - *applies:* deferred-switch model, thread exit; armv7m, armv6m, rx
  - *source:* kernel/sched/sched.cc (exit_current's arch_idle_wait park loop)

- **`wake-from-a-thread-that-will-not-run-again-must-not-switch`** -- `sched::wake` returns without rescheduling whenever `kernel().current` is EXITED. That state means `exit_current` is past its own `on_remove`, so the thread can never be picked again and a switch there would ABANDON the rest of `exit_current`: the join and wait-until-last waiters its pool scan has not reached yet would never be woken, and `kickos_terminate` would never run when the last non-idle thread leaves. The scan issues those wakes deliberately BEFORE its single final `reschedule()`, which is the one switch away. `Thread::dying` cannot carry this: a joiner may outrank the dying thread, and the priority clause beside it admits exactly that. The failure is silent and port-dependent -- ARM, RISC-V and RX pend the switch until the enclosing IrqLock releases and survive by luck, while the sim and Xtensa/LX6 take it immediately -- and both orders leave every waiter READY, so only the ORDER of the switch distinguishes them.
  - *applies:* scheduler core, thread exit; every arch
  - *source:* kernel/sched/sched.cc (sched::wake's EXITED clause, exit_current's waiter scan); tests/unit/schedwake/wake_dying.cc (the exit-sweep order arm); ../design-m4.8.2-host-unit-tests.md section 8.3

- **`cap-teardown-sweep-is-preemptible-and-must-resume`** -- `cap_teardown` may be switched out mid-sweep and must therefore be resumable rather than uninterrupted: it releases IrqLock between chunks, the dying thread stays on the ready structure and is not EXITED, so `pick_next` can return it again and the sweep stays TOTAL. Two things switch it out, and the difference matters: an RR slice expiry in `sched::tick_rr`, which reaches the switch from an ISR and so lands at a CHUNK BOUNDARY on every port because the chunk's own IrqLock defers delivery; and `sched::wake` of a strictly higher-priority peer from the teardown arms themselves, which is thread context and is not deferred at all, so on a backend whose `arch_switch` is immediate (the sim, and Xtensa/LX6 outside an ISR) it lands MID-chunk with the slot being closed still live. A FIFO dying thread is reachable only by the second. What makes the exposure safe is not the guard but the surrounding construction: each arm unlinks before it wakes, every object stays pinned by the dying thread's own not-yet-dropped cap, the cross-task reply mint has its own `dying` test, and `ThreadPool::alloc` reclaims only an EXITED slot.
  - *applies:* capability teardown, scheduler core; every arch
  - *source:* kernel/syscall/cap.cc (cap_teardown's chunk loop, obj_close_protocol's wake sites); kernel/include/kickos/cap.h (the cap_teardown declaration); kernel/sync/sync.cc (mutex_force_unlock); tests/unit/schedwake/wake_dying.cc (the chunk-boundary resume arm)

- **`arch-in-isr-truth`** -- arch_in_isr() must read true in ISR/handler context and false throughout syscall_dispatch and ordinary thread context. RX has no IPSR: its g_in_isr counter is bumped ONLY by the device-IRQ/timer first-level dispatchers, never by the syscall INT path, so dispatch reads false as the contract requires. **The SYSCALL TRAP is not ISR context for this purpose on any arch**, because the trap-handler IPC fastpath blocks and performs its own switch there: rv32imac and rxv3 satisfy that by not bumping their software counter on the trap path, and ARM by reading exception 11 (SVCall) as thread context.
  - *applies:* deferred-switch model, syscall contract, IPC fastpath; all arches (rx software counter)
  - *source:* arch/include/kickos/arch/arch.h (arch_in_isr, and the arch_syscall dispatch contract); arch/rx/rxv3/arch_rxv3.cc (g_in_isr, arch_in_isr, and the first-level dispatchers that bump it -- kickos_rx_timer_isr / kickos_rx_default_irq / kickos_rx_swint2); arch/arm/common/arch_arm_common.cc (arch_in_isr's IPSR read and its SVCall carve-out); kernel/syscall/syscall_ipc_fast.cc (the leaf that parks from inside the trap)

## Syscall, privilege & the user/kernel boundary

- **`syscall-in-priv-thread-context`** -- The arch MUST run syscall_dispatch() in privileged THREAD context on the calling thread's own continuation, never in handler/ISR context. A blocking syscall blocks by an ordinary synchronous context switch that freezes the mid-dispatch continuation on the caller's stack and resumes it inline when rescheduled. On ARM the SVC handler redirects to svc_trampoline (privileged thread mode); it does not dispatch inside the handler.
  - *applies:* syscall + privilege + resume-inline; armv7m, armv6m, rx (xtensa: plain call, trivially satisfied)
  - *source:* arch/include/kickos/arch/arch.h (the arch_syscall contract); arch/arm/armv7m/switch.S (SVC_Handler's redirect and svc_trampoline); arch/xtensa/lx6/arch_xtensa.cc (arch_syscall, a plain call); docs/reference/porting.md

- **`trap-return-atomic`** -- Trap/exception return must be atomic with respect to interrupts: no interrupt-takeable window may exist while the return-state (return PC + saved status/privilege) is staged but not yet consumed by the return instruction. Otherwise a nested trap overwrites the staged return PC and the outer return jumps back into its own epilogue at the caller's privilege with the frame half-restored. This is an end-property, not a code shape -- each arch satisfies it by its own mechanism, and a unique path still has to close the window: ARM's exception unstack is hardware-atomic and the syscall trampoline returns by ordinary `bx lr` (no return register live); RX pops PC+PSW in one `RTE`; xtensa sets `PS.EXCM=1` before writing `EPC1`; RISC-V restores `mstatus` (MIE=0) BEFORE `mepc` on the ecall-return path -- which alone reaches the restore with MIE=1, because `.Lecall` sets MPIE=1 to make `syscall_dispatch` interruptible.
  - *applies:* trap/syscall return, critical section; armv7m, armv6m, rx, xtensa, rv32imac
  - *source:* arch/riscv/rv32imac/switch.S (.Lrestore); arch/rx/rxv3/switch.S (RTE); arch/xtensa/chip/esp32/startup.S (PS.EXCM before EPC1); arch/arm/armv7m/switch.S (svc_trampoline `bx lr` + HW exception return)

- **`syscall-restores-resting-priv`** -- On syscall return the SVC trampoline must restore the caller's resting privilege (ctx.resting_npriv), NOT hard-code nPRIV=1: a privileged thread issuing a syscall must drop back to exactly its entry posture, never be demoted to unprivileged.
  - *applies:* syscall + privilege; armv7m, armv6m
  - *source:* arch/arm/armv7m/switch.S (svc_trampoline's CONTROL write from ctx.resting_npriv); arch/arm/armv6m/switch.S (svc_trampoline, the same restore); arch/arm/armv7m/include/kickos/arch/context.h (arch_context::resting_npriv)

- **`user-thread-return-via-syscall`** -- An unprivileged thread whose entry returns must route through kickos_user_thread_return (which traps out via the exit syscall); it must NOT run the kernel's kickos_thread_return directly, because exit_current with nPRIV=1 makes IrqLock/BASEPRI a no-op and the switch-path SCS write faults. arch_context_init selects the return address by privilege.
  - *applies:* syscall + privilege, thread exit; armv7m, armv6m, rx
  - *source:* arch/arm/armv7m/arch_armv7m.cc (kickos_user_thread_return, and arch_context_init's return-address selection); arch/rx/rxv3/arch_rxv3.cc (kickos_user_thread_return, and arch_context_init's return-address selection); kernel/thread/thread.cc (kickos_thread_return)

- **`privilege-escalation-gated`** -- Spawning a privileged thread must be gated on the CALLER being privileged (-KOS_EPERM otherwise), and that gate is deliberately a raw `Thread::privileged` test and not an authority bit (see `authority-word-narrows-only`): a capability to create privileged children would be equivalent to holding every authority forever AND being able to hand that on, so narrowing it is meaningless and delegating it is unbounded escalation. There is therefore no path by which an unprivileged thread obtains privilege, and the privileged population cannot grow after boot. The acts that merely need authority are gated on the authority word instead -- irq_attach on `AUTH_IRQ`, ram_alloc on `AUTH_MEMORY` (rejecting with NULL, out of the -KOS_E* scheme, see `syscall-return-abi`) -- so an unprivileged holder passes those and the whole-arena grant stays unreachable regardless.
  - *applies:* user/kernel boundary, syscall; kernel (all arches)
  - *source:* kernel/syscall/syscall_thread.cc (thread_spawn's privileged-child check); kernel/syscall/syscall.cc (the KOS_SYS_IRQ_ATTACH and KOS_SYS_RAM_ALLOC dispatch arms)

- **`root-unprivileged-idle-alone-privileged`** -- Exactly ONE thread in the system is privileged, and it is `idle`. Root is unprivileged on EVERY board, unconditionally: `ThreadAttr::privileged` DEFAULTS to `false` (`kernel/include/kickos/thread.h`), `kmain` sets `root_attr.privileged = false` explicitly, and `idle_attr.privileged = true` is the only assignment of `true` left. There is no build knob, no preset and no porting escape hatch that restores a privileged root: the knob that once selected the posture was DELETED in M4.5.6, and so was the `FATAL_ERROR` that refused a stale cache entry, so a stale `-D` for it is now SILENTLY IGNORED on an in-tree and an out-of-tree configure alike, with nothing but CMake's generic unused-variable warning. There is no incantation to clear, because there is no guard left to clear. Combined with `privilege-escalation-gated` (the privileged population cannot GROW after boot) the privileged population is therefore fixed at one for the life of the system. **There is no demotion instant**: privilege is a property of the frame `arch_context_init` fabricates and of the region set `thread_create` composes from it, so root is unprivileged from its FIRST instruction -- no window exists in which root runs privileged and then drops. Two consequences a change must not break. (1) Root's authority word is seated UNCONDITIONALLY with `CAP_AUTH_ALL` (`authority-word-narrows-only`): with no ring to short-circuit `cap_check_authority`, a root left at authority 0 would fail every authority gate including its own shutdown. (2) The kernel must never call a kernel-internal function that masks IRQs or touches kernel `.bss` from root's frame -- it faults there and LOSES the diagnostic. That is why returning from `main` panics THROUGH the `KOS_SYS_PANIC` syscall trap and never calls `kpanic` directly, and why the ungated `kos_panic` exists at all. A test asserting anything about a privileged CALLER is unwritable by construction: `idle` runs no tests, which is why `mpu_privileged_guard` was retired rather than fixed, and `user/apps/common/rootfault` makes the stronger claim instead (root TRAPS on a cross-domain write) on every `KICKOS_HAVE_MPU` image.
  - *applies:* kernel init, syscall, user/kernel boundary; kernel (all arches), every board
  - *source:* kernel/init/kmain.cc (idle_attr/root_attr privilege + the unconditional cap_seat_authority); kernel/include/kickos/thread.h (ThreadAttr::privileged default); kernel/syscall/syscall.cc (the KOS_SYS_PANIC arm and its noinline message-buffer helper); user/apps/common/rootfault

- **`fault-kills-one-unprivileged-thread`** - A fault kills ONE thread instead of the system exactly when three clauses hold together: the CPU was UNPRIVILEGED at fault time, it was in THREAD context, and the thread is not already dying. Every other fault panics as it did before. The discriminator is the CPU's privilege, NOT the thread's identity and NOT `ctx.resting_npriv`: syscall dispatch runs privileged on the thread's own stack (`syscall-in-priv-thread-context`), so a fault there is a kernel bug in code the thread merely called and must reach the panic dump. The arch half is `arch_fault_is_user_thread`, whose fallback TU declines, so an un-ported backend keeps the panic path with no edit; the core half re-tests what it can (no current thread, `idle`, `Thread::privileged`) so the rule does not rest on every backend's predicate being exact. `Thread::dying` is set at the top of `sched::exit_current` and NEVER cleared, so a fault taken anywhere in the death path (a re-fault on an overflowed stack is the case that matters) escalates to the panic path instead of looping through the redirect again. The rule is NOT scoped by MPU posture: privilege comes from `arch_context_init` and root is unprivileged on every board (`root-unprivileged-idle-alone-privileged`), so a flat board kills a faulting thread exactly as an enforcing one does and root itself dies thread-scoped; what differs on a flat board is only which accesses fault at all. Which backends may do this is a CONFIGURE-time classification, not an arch name a gate re-derives: `KICKOS_HAVE_PRIV_RING` (per BOARD, since the ARMv6-M privilege extension is optional and Cortex-M0 omits it) gates `KICKOS_FAULT_ISOLATION`, which both selects the seam TUs and, spelled `KICKOS_FAULT_OUTCOME`, is the token the fault gates parse. Reasoning: `../design-m4.7.9-fault-isolation.md` (section 3); porting contract: `docs/reference/porting.md`.
  - *applies:* fault handling, privilege, thread exit; armv7m, armv6m, rv32imac, rxv3, sim (lx6 and Cortex-M0 boards decline and keep panicking; lx6 by HARDWARE, having no privilege ring to read)
  - *source:* kernel/init/fault.cc (kickos_fault_kill_thread / kickos_thread_fault_exit); arch/include/kickos/arch/arch.h (arch_fault_is_user_thread / arch_fault_redirect_to_exit); arch/common/arch_fault_is_user_thread_default.cc (the declining fallback); kernel/sched/sched.cc (exit_current, where `dying` is set); kernel/include/kickos/thread.h (Thread::dying); CMakeLists.txt (the KICKOS_HAVE_PRIV_RING / KICKOS_FAULT_ISOLATION classification); user/apps/common/faultsurvive + tests/integration/check_faultsurvive.sh

- **`fault-kill-path-never-enters-panic`** - Nothing on the thread-kill path may print, and in particular it must NEVER call `kpanic_enter`: that masks interrupts, forces the synchronous writer and reclaims the console permanently and unconditionally-once (`panic-console-probe-independent`), which is exactly wrong for a system that is meant to survive this fault. So the arch handler asks `kickos_fault_kill_thread` ahead of its first output AND ahead of its `kpanic_enter`, `arch_fault_redirect_to_exit` hands the fault facts to `kickos_fault_record` instead of printing them, and `kickos_thread_fault_exit` prints them later in thread context through the ordinary `kprintf` path. A reporter that prints first would kill the console of a system that then keeps running. The rule is about the RECLAIM, not about staying silent: a published console still gets the record, over the driver rather than over the device, which is `fault-record-is-printed-only-by-its-owner`. Reclaiming instead was rejected on register facts, not on taste -- all four `arch_console_reclaim` bodies clear a UART TX interrupt enable AND reprogram baud (`chip_mk64f.cc` C2/BDH/BDL/C4, `usic_uart.cc` CCR.TBIEN/FDR/BRG, `chip_esp32c6.cc` and `chip_esp32.cc` INT_ENA/CLKDIV), so it is not reversible from the kernel side and a SCOPED reclaim would silence a live IRQ-driven driver's TX source and park it forever, which is the same hazard `console_on_driver_death` already defers around. A wedged console is strictly worse than a late one. A RAW pre-console localizer counts as output for this rule and moves below the kill test with everything else: `rxv3`'s `KICKOS_RX_MPU_TRACE` mark pokes the SCI6 transmit register directly, which is the very peripheral the console drains, and it interleaves with buffered console text rather than replacing it.
  - *applies:* fault handling, console; armv7m, armv6m, rv32imac, rxv3, sim
  - *source:* arch/arm/armv7m/arch_armv7m.cc (kickos_armv7m_fault_report, the kill test ahead of kpanic_enter); arch/riscv/rv32imac/arch_rv32imac.cc (kickos_rv_fault_report); arch/rx/rxv3/arch_rxv3.cc (kickos_rx_fault_report, the kill test ahead of both kpanic_enter and rx_mpu_mark); arch/sim/sim.cc (on_sigsegv / on_sigill); kernel/init/fault.cc (kickos_fault_record and the deferred print)

- **`fault-record-is-printed-only-by-its-owner`** - The fault facts live in ONE file-scope record, not in per-thread fields, because `Thread` carries no tail padding on any target, so another field would grow every TCB (on a 32-BIT target: 256 bytes where `KCAP_RUN_CHUNKS` is 1, 264 where it is 2, 248 on RXv3; the host sim is 2480 and the figure does not apply there). The `static_assert` pair beside `struct Thread` does NOT enforce those literals: it recomputes the expectation from the target's own `arch_context`, `arch_mpu_region` and `CapRun` sizes and pins only the scalar remainder, plus the absence of tail padding. That record is NOT protected by `fault-kills-one-unprivileged-thread`'s dying clause: `Thread::dying` is not set until `sched::exit_current` runs at the END of `kickos_thread_fault_exit`, so the whole window between the exception return and the print is PREEMPTIBLE and a second, unrelated thread's fault can overwrite the record first. The record therefore carries the `Thread*` it was captured for, and a stub that does not own it prints `PC lost to a later fault` and LEAVES IT VALID for the thread that does, rather than printing another thread's PC, status and address. Both threads still die correctly and both still announce themselves by name; the residual cost is that the first thread's PC is lost in a double-fault race, which is accepted (`../design-m4.7.9-fault-isolation.md` section 9.3). A change that widens the dying clause to cover this window would also make a re-fault on an overflowed stack unreportable, which is the case the clause exists for. **The record's TRANSPORT is not the ordinary one, and it may not be**: `console_emit` DROPS every kernel chip write while a userspace driver owns the console, so on the boards whose default service list carries a console driver (`frdmk64f`, `xmc4800-relax`) the whole record was lost while isolation itself worked perfectly -- measured both ways at one tree, `.session/logs/m483-fs-frdmk64f-faultsurvive.log` against `m483-fsk-frdmk64f-faultsurvive.log`. The five print sites therefore call `kprintf_fault`, which is `kprintf` plus one thing: while the state is USER_OWNED it also hands the formatted line to the published endpoint's ALREADY-PARKED receiver (`cap_console_deliver`), through the kernel's own identity reference on that endpoint rather than through the dying thread's cap table, which a thread spawned before the publish never had seated. It reaches the wire because the DRIVER prints it, which is the only agent permitted to touch a published device at all. Three properties are load-bearing and each rules out a cheaper variant. It NEVER PARKS, so no fault record can wedge a dying thread on a driver that is mid-write or gone -- which is why `endpoint_send` could not be reused even with a zero timeout, since `park_deadline_arm` floors any non-`KOS_TIMEOUT_NONE` deadline to `KICKOS_TIMER_MIN_DELTA_NS` and switches away. It is NARROW to this one caller, because routing all of `kconsole_write` would relight the kernel debug console post-handover and retire `check_sim_published.sh`'s negative assertion, which is the only proof that a handover happened at all. And ORDER survives without luck: the delivery pops the driver out of `recv`, so a later user `kos_send` finds no parked receiver and parks in `send_waiters`, leaving the driver to emit the record, return to `recv`, and only then take that line -- the `survived > killed` ordering assertion holds under a published console too. **What it still loses, deliberately:** a line dropped when NO receiver is parked at that instant (the faulter was the driver's last receiver, or the driver is mid-write), and a line handed over but never drained because the system shut down before the driver was scheduled (`kickos_terminate` flushes the KERNEL ring only). **A record is up to THREE separate deliveries from five call sites emitting four kinds of line, and only the first is unconditional**, because the first one pops the driver out of `recv` and the second needs it back: what puts it back is the pre-existing rule that a console service's `cfg->prio` is `>=` every stdout client (a rendezvous carries no priority inheritance, D9), so the woken driver preempts the faulting client and re-parks. A console provisioned below one of its clients -- already forbidden for that other reason -- would truncate every fault record to its banner line. RTT is ungated by ownership, so `xmc4800-relax`'s `CONSOLE_BOTH` posture always had the line on the second transport; `frdmk64f` is chip-only and had none.
  - *applies:* fault handling, diagnostics; armv7m, armv6m, rv32imac, rxv3, sim
  - *source:* kernel/init/fault.cc (FaultRecord::owner, kickos_fault_record, kickos_thread_fault_exit, the kprintf_fault sites); kernel/init/console.cc (kvprintf_route, the USER_OWNED arm); kernel/syscall/syscall_ipc.cc (cap_console_deliver, beside the endpoint_send arm it mirrors); kernel/syscall/cap.cc (cap_console_target); tests/integration/check_sim_pubpanic.sh (case 2) and check_sim_faultsurvive_pub.sh (the ordering claim)

- **`fault-frame-untrusted-until-proved`** - A fault fact read from a REGISTER (privilege, cause, fault-status, fault-address) is always valid; a fault frame that lives in MEMORY on the faulting thread's stack is not, and a backend must gate it on `kickos_fault_frame_trusted(frame, bytes)` before it reads a single word. Two failures hand over a frame the thread never legitimately produced: a wild SP, which the bounds test catches, and a stacking abort, which it cannot (hardware stacking decrements SP before it writes, so a stack overflow leaves the frame pointer naming memory that was never written) and which armv7m catches instead on the CFSR bits MSTKERR/MUNSTKERR (bits 4/3) and STKERR/UNSTKERR (bits 12/11), mask 0x1818, read out of the register first. NEITHER test subsumes the other and a backend needs both wherever both apply. `MLSPERR`/`LSPERR` are deliberately excluded from the mask: lazy FP preservation leaves the integer frame valid, so including them would panic a legitimate user fault. `kickos_fault_frame_trusted` fails closed on no current thread, on `idle` and on a thread with no recorded stack, and it is written on the room REMAINING inside the stack so a frame pointer near the top of the address space cannot pass by overflowing the addition. The hazard is not theoretical: an earlier implementation read the stacked IPSR field out of that stale RAM and declined only BY ACCIDENT, because those bytes happened to be non-zero. **A THIRD test exists for a core that cancels the faulting instruction**, where neither of the two above can see an overflow at all: RXv3 restores the cancelled instruction's architectural state (RXv3 ISA UM sec.5.3.1), so the USP reads as it did before the denied push, and the frame sits on the kernel ISP where nothing the thread did can invalidate it. `kickos_fault_below_stack(addr)` answers whether the faulting ADDRESS landed beneath the running thread's stack, which a downward-growing stack makes EXACT for the overflow class; it also fails closed with no recorded stack. Its converse is deliberately imprecise and the cost is measured: an operand access to an address BELOW the faulting thread's own stack base escalates to the panic dump instead of dying alone. A distance threshold instead of the stack base would fail in the UNSAFE direction, since a frame larger than the threshold puts privileged code back on an exhausted stack.
  - *applies:* fault handling, memory safety; armv7m, armv6m, rv32imac, rxv3 (sim: the resume context is the host ucontext on a dedicated signal stack, so there is no guest frame to fabricate)
  - *source:* kernel/init/fault.cc (kickos_fault_frame_trusted, kickos_fault_below_stack); arch/arm/armv7m/arch_armv7m.cc (arch_fault_is_user_thread, the 0x1818 early-out); arch/arm/armv6m/arch_armv6m_fault.cc (bounds test only, no CFSR on v6-M); arch/riscv/rv32imac/arch_rv32imac.cc; arch/rx/rxv3/arch_rxv3.cc (USP containment plus the MPDEA below-stack test, no CFSR analogue); tests/integration/check_faultsurvive.sh (asserts MSTKERR in the overflow arm rather than only that a panic happened)

- **`fault-exit-code-is-not-a-joiner-signal`** - A fault-killed thread exits with `KOS_EXIT_FAULT` (139, `user/include/kickos/sys/abi.h`): that is the process status when it was the last thread live, and it is distinct from `kfault_terminate`'s 132, so a capture tells a survived fault from a panic. A JOINER cannot read it. `sched::exit_current`'s waiter sweep hardcodes the join wake result to 0 for every exit, clean or faulted, and a clean `kos_exit(139)` aliases the code in any case. A supervisor must therefore watch liveness-by-activity rather than a cause: join the watched thread with a deadline, where 0 means it died and -KOS_ETIMEDOUT means it is alive but silent. Making the fault case distinguishable would be an ABI change to the join result, not a fix here.
  - *applies:* thread exit, join, fault handling; kernel (all arches)
  - *source:* user/include/kickos/sys/abi.h (KOS_EXIT_FAULT); kernel/init/fault.cc (the exit_current call); kernel/sched/sched.cc (exit_current's waiter sweep, `w->wait_result = 0`)

- **`every-syscall-caller-holds-a-pool-slot`** -- `idle` is the ONE TCB the thread pool does not seat, and it issues no syscall, so every thread that can reach `syscall_dispatch` occupies a `ThreadPool` slot and `threads.index_of(current())` is therefore never -1 at any syscall. Root is not an exception: `kmain` claims root's slot through `ThreadPool::alloc` before any spawn can run, so root is slot 0 at generation 0 and `handle_for(0)` is the bare handle `0`. Three mechanisms rest on the property and none has a fallback. (1) A `CAP_REPLY` entry names its caller BY POOL HANDLE (`cap_install_reply`), so a caller with no slot could not be named and `kos_call` could not answer it; that is why the non-pool refusal `endpoint_call` used to carry could be deleted rather than widened. (2) `kill_tag_of` derives a thread's kill-gate identity from its slot index and answers the shared `KILL_TAG_BOOT` for anything off-pool, so a second off-pool TCB would silently share one cancel identity with `idle`. (3) `ThreadPool::is_root` is the slot COMPARISON `t == &slots[ROOT_INDEX]`, and `KOS_SYS_EXIT` reads it to send root's exit to `kickos_terminate` instead of `sched::exit_current`; the alternative test, `spawner_tag == KILL_TAG_NONE`, is WRONG here because `ThreadPool::alloc`'s reclaim sweep clears an orphaned child's tag to `KILL_TAG_NONE`, so it would shut the system down on any orphan's ordinary exit. What keeps `idle` outside the property is STRUCTURAL, not its body: `kmain` creates it with `cap_run = CapRun{}`, an empty directory, so its capability capacity is 0 and every `cap_lookup` fails `-KOS_EBADF` ahead of any mint, park or send. A change that gives `idle` a run breaks this invariant even if `idle_entry` still only calls `arch_idle_wait`. **Enforcement is two `KICKOS_ASSERT`s and nothing else**: one in `cap_install_reply` for the slot itself, one in `kmain` pinning root's claim to `ROOT_INDEX` so an allocation slipped in ahead of root panics at boot rather than silently redirecting that thread's exit. Both are unconditional (`KICKOS_ASSERT` is not debug-gated), but there is no configure-time or link-time check. A new off-pool TCB is therefore a design decision, not an addition: it needs a kill tag of its own and a reply-naming answer before it can issue a syscall.
  - *applies:* syscall, capability object model, thread pool, kill gate; kernel (all arches), every board
  - *source:* kernel/init/kmain.cc (g_idle_tcb, its empty cap_run, root's ThreadPool::alloc and the ROOT_INDEX assert); kernel/include/kickos/thread.h (ThreadPool::index_of / kill_tag_of / handle_for / is_root); kernel/syscall/cap.cc (cap_install_reply, the other assert); kernel/syscall/syscall.cc (KOS_SYS_EXIT, the is_root reader); kernel/syscall/syscall_ipc.cc (endpoint_call, which no longer refuses a non-pool caller)

- **`user-args-validated-at-boundary`** -- Every user-supplied scalar must be range-checked or clamped at the syscall boundary before use, and an invalid one returns a negative -KOS_E* code (never panics): priority is bounds-checked before it indexes ready lists / shifts a 1u<<prio bitmap; console len is clamped to 4096; injected/attached IRQ lines are checked against [0,KICKOS_MAX_IRQ); an unknown syscall number returns -KOS_EINVAL. The MPU does NOT make this optional now that it enforces. `syscall_dispatch` runs PRIVILEGED, so it is on the wrong side of the very boundary the MPU checks: an unvalidated scalar becomes an out-of-bounds access by the KERNEL, which the region set permits by construction. Enforcement contains a bad *user* pointer only where it exists: on a flat posture, which is what a board with no MPU backend has and what any board's `flat` variant selects, there is no region set to check against, so `user_readable_ok` / `user_writable_ok` fall through to `arch_user_text_readable` / `arch_user_data_writable`, whose non-enforcing arm must be a WHITELIST of the chip's linker-defined memories (code/rodata extent, and static RAM up to the arena base -- `__kickos_rom_start/_end`, `__kickos_sram_start`, all STRONG references -- absent from `tests/static/weak_allowlist.txt` on purpose -- so a chip that omits them fails the LINK). Admitting "anything outside the arena" instead let an unmapped address through and HARD-FAULTED the kernel inside `kaccess_from_user` (MEASURED on mps2-an386 and mps2-an505: `kos_panic((char const*)0xCCCCCCC0)`, `BFAR=0xccccccc0`). Only these checks contain a bad user *index*.
  - *applies:* user/kernel boundary; kernel (all arches)
  - *source:* kernel/syscall/syscall.cc (KOS_SYS_KCONSOLE_WRITE len clamp; the KICKOS_MAX_IRQ checks on inject/unmask/attach; the dispatch `default:` -KOS_EINVAL); kernel/syscall/syscall_thread.cc (thread_spawn prio bounds vs KICKOS_PRIO_MIN/MAX); kernel/syscall/syscall_mem.cc (user_range_ok / user_readable_ok / user_writable_ok); arch/common/arch_ram_common.cc (arch_user_text_readable / arch_user_data_writable, the non-enforcing whitelist); user/apps/common/panicgate (the wire gate: message, null, wild, oversized)

- **`syscall-return-abi`** -- A syscall that can fail returns its error as the NEGATED code -KOS_E* (`system/include/kickos/sys/errno.h`); a success -- a handle, a count, or a byte-count -- is NON-NEGATIVE, so `rc < 0` is unambiguously an error and never aliases a valid handle/count. Magnitudes mirror POSIX errno (EPERM/ESRCH/EBADF/ENOMEM/EFAULT/EBUSY/EINVAL/EMFILE/EPIPE/EDEADLK/ENOSYS/EOVERFLOW/ETIMEDOUT/ECANCELED, plus EOWNERDEAD below); the sign is applied at the return site (there is no positive success-variant). KOS_ETIMEDOUT carries a promise beyond the POSIX name: a caller-supplied deadline passed and NOTHING happened FOR THE CALLER, so an expiring KOS_SYS_SEND_TIMED delivered no bytes, an expiring KOS_SYS_RECV_TIMED received none, and an expiring KOS_SYS_CALL_TIMED got no reply. It is NOT a promise that the whole transaction was undone: a call whose request a server had already taken leaves that server holding its one-shot reply capability, and the server's later KOS_SYS_REPLY consumes it and answers -KOS_ESRCH. That residue is bounded but NOT inert -- see `abandoned-reply-cap-cannot-reach-a-later-call`. Two exhaustion codes must not be collapsed: -KOS_ENOMEM is a supply that could not be ALLOCATED (an object pool, the thread pool, the RAM arena, the MPU descriptor budget), -KOS_EMFILE is ONE thread's capability table refusing a mint, either because its free list is empty or because it already holds KICKOS_CAP_REPLY_MAX live CAP_REPLY entries (the second fires with free slots) -- opposite fixes (more RAM against a wider declared table), and while they shared a code a full table surfaced as a mislabelled `pool too small` skip. EOWNERDEAD is the robust-mutex case: a mutex ACQUIRED while its prior owner died holding it is still returned negative (-KOS_EOWNERDEAD), which a caller must special-case as HELD. Five syscalls stay OUT of the scheme by return type: ram_alloc returns a pointer (every failure is NULL -- a negated errno cast to a pointer would be non-NULL); cpu_clock_hz/cpu_clock_set and KOS_SYS_PERIPH_CLOCK_HZ return a u32 Hz whose 0 already means unknown/no-silicon-clock; and the selftest-only KOS_SYS_GUARD_ADDR returns a raw address.
  - *applies:* user/kernel boundary, syscall ABI; kernel (all arches) + userspace wrappers
  - *source:* system/include/kickos/sys/errno.h; user/include/kickos/sys/abi.h (the return-type notes on the syscalls outside the scheme); kernel/syscall/syscall.cc (every dispatch return site) + the per-domain implementations it calls (syscall_thread.cc, syscall_ipc.cc, syscall_obj.cc, syscall_mem.cc)

- **`handle-not-pointer-across-boundary`** -- No kernel pointer crosses the user/kernel boundary: kernel objects (semaphores, threads, IRQ bindings) are named by small integer handles resolved through a single validate-and-resolve chokepoint. Semaphore access migrated to per-thread capabilities at M3 (see `object-access-via-per-thread-cap`); thread and IRQ-binding handles still pack index+generation, and the freeing path bumps the slot generation so a stale handle fails to resolve rather than aliasing a recycled slot (ABA). The kernel must never strlen a user pointer (kconsole_write takes explicit buf,len).
  - *applies:* user/kernel boundary; kernel (all arches)
  - *source:* kernel/syscall/syscall.cc (the KOS_SYS_KCONSOLE_WRITE buf,len arm); kernel/syscall/cap.cc (cap_resolve); kernel/include/kickos/instance.h (the generational slot pools)

- **`object-access-via-per-thread-cap`** -- A userspace-named kernel object (semaphore, PI mutex, or IPC endpoint) is reached ONLY through a per-thread capability, never a global id: KOS_SYS_SEM_WAIT/SEM_POST (and the mutex/endpoint send/recv syscalls) take a cap handle, and cap_resolve validates index/liveness/type/rights then WRAPs to the global object pool -- two generations guard it, the per-thread cap-gen (use-after-close) then the object's own object-gen (use-after-destroy), both u16. Resolve-and-use run under ONE continuous IrqLock, so a concurrent handle_close cannot free the object between resolve and use. An ISR NEVER resolves a cap: irq_attach resolves once (requires CAP_SIGNAL) and stores the GLOBAL object handle, which irq_sem_post re-resolves from the pool per fire (current() in ISR context is a random interrupted thread's table). B1 placement contract: a freshly spawned child table is all-CAP_EMPTY with cap-gen 0, so handle == index on a fresh table; a spawn-delegated cap i lands at child index i+1 (index 0 reserved), rights narrowed subset-only (child.rights = parent.rights & mask, never widened, requires CAP_TRANSFER), and the whole caps list is validated before the child slot is claimed. Cap handles are opaque, and the old global sem id is gone. The NAME `kos_sem_destroy` survives as a source-compatibility alias of `kos_handle_close` (`user/include/kickos/sys.h`) -- so it no longer means "destroy this semaphore" but "drop MY cap", and the object outlives the call whenever another holder remains. CAP_WAIT and CAP_SIGNAL are enforced at cap_resolve and NOWHERE else ((rights & need) == need); CAP_TRANSFER is enforced at the DELEGATE SITE instead -- thread_spawn's grant loop refuses a source entry without it with -KOS_EPERM -- and no cap_resolve call site anywhere passes it as `need`. That is not an inconsistency: CAP_TRANSFER gates the COPY of an entry into a child table, not any use of the object, so there is no resolve that would have anything to ask for. Memory R/W/X stays in the MPU descriptor, not the cap.
  - *applies:* user/kernel boundary, capability object model; kernel (all arches)
  - *source:* kernel/include/kickos/cap.h; kernel/syscall/cap.cc (cap_resolve/handle_close/cap_teardown); kernel/syscall/syscall.cc (the KOS_SYS_SEM_*/MUTEX_* dispatch arms); kernel/syscall/syscall_ipc.cc (endpoint_send/recv/call/reply); kernel/syscall/syscall_thread.cc (thread_spawn's B1 delegation -- the grant loop's CAP_TRANSFER check is the delegate site); kernel/sched/sched.cc (cap_teardown on exit)

- **`own-create-skips-reserved-cap-index`** -- The well-known cap indices [0 .. KICKOS_CAP_FIRST_DYNAMIC) (today [0..2): index 0 = KOS_CAP_STDOUT, index 1 = KOS_CAP_CLOCK) are reserved slots (`system/include/kickos/sys/cap_index.h`). An own-create (sem/mutex/endpoint create) takes the head of the run's free list in O(1) (cap_install -> cap_run_peek_free) and allocates nothing, refusing -KOS_EMFILE on a full table; it can NEVER land on -- and alias -- a reserved index, and the mechanism is NOT a scan floor but that the reserved plane is never THREADED ONTO the list at all (cap_run_free_build starts at KICKOS_CAP_FIRST_DYNAMIC, and cap_run_free_release / cap_run_free_unlink no-op below it), so no pop can hand back a well-known index. A release goes to the list TAIL, so with F free slots each slot's cap-gen advances once per F mints rather than one counter absorbing every mint. A reserved slot is written ONLY by the kernel (cap_install_defaults seats stdout and is the sole writer of index 0) or by explicit spawn delegation (delegated cap i lands at index i+1, so delegated cap 0 lands on the reserved clock index and every further one lands in the dynamic range); cap_install_at rejects index 0 outright. The range is NOT frozen, but every move of it is an ABI break and the two directions have different rules. Renumber DOWNWARD only for a slot NOTHING seats; the table width follows on its own, because the reserved range is one of the four terms ROOT's width is summed from at configure (cmake/cap_table.cmake; the others are the service list's RETAINED_CAPS, the widest app CAPABILITIES peak and the widest declared peak of concurrent INBOUND reply capabilities), and it is also charged to KICKOS_CAP_CHILD_WIDTH, which every SPAWNED thread gets and which no app declares: the width is per thread, not one number per image. So the usable dynamic count is unchanged with no board edit. Append by raising the last reserved index and KICKOS_CAP_FIRST_DYNAMIC together, which costs one slot on every table in the fleet -- so weigh it first against putting the state in the TCB instead, as the authority word does (`authority-word-narrows-only`). Either way the cap.h static_assert guarantees >=1 dynamic slot survives.
  - *applies:* user/kernel boundary, capability naming; kernel (all arches)
  - *source:* system/include/kickos/sys/cap_index.h; kernel/include/kickos/cap.h (cap_run_free_build / cap_run_free_release / cap_run_free_unlink -- the reserved plane's exclusion from the free list); kernel/syscall/cap.cc (cap_install -- the O(1) free-list pop; cap_install_at -- rejects index 0; cap_install_defaults -- the sole writer of index 0)

- **`authority-word-narrows-only`** -- Axis-3 authority is PER-THREAD STATE that only ever shrinks; it is NOT a capability and has no cap-table entry. Shape: `Thread::authority`, one uint8_t of `CapAuthority` (AUTH_*) bits, sited in the TCB padding before `quantum_ns` so it costs the TCB nothing. It shares no numbering with `CapRights` -- separate enums in separate fields, so neither constrains the other and nothing has to keep them disjoint. It names no pool object, holds no refcount and bumps no generation, which is exactly why it is not a table entry: an entry would spend a well-known index on every board in the fleet (`own-create-skips-reserved-cap-index`) to store eight bits the TCB already had room for. NON-DELEGABLE BY CONSTRUCTION rather than by a refusal: thread_spawn's delegation loop copies CapEntry fields and there is no entry to copy, so no forgery path exists to close and none has to be maintained. A child's word comes from exactly one place, `cap_seat_authority(child, p->authority)` on the spawn path. Monotone in both directions: a spawn seats only bits the caller itself holds (cap_check_authority, else -KOS_EPERM; bits outside CAP_AUTH_ALL are -KOS_EINVAL), cap_seat_authority masks to CAP_AUTH_ALL so a bit no gate reads can never be seated, and KOS_SYS_CAP_NARROW applies `word &= mask`, which can only CLEAR. KOS_CAP_AUTHORITY survives as a PSEUDO-HANDLE and nothing else -- the argument kos_cap_narrow takes to NAME the word, deliberately `0x7FFFFFFF`, whose index field is the all-ones value the codec's capacity rule keeps out of every table, so no table can mint it (cap.h static_asserts the index field, and separately caps KICKOS_MAX_HANDLES at 2^16 - 1). cap_narrow_authority refuses any other handle with -KOS_EINVAL (an object cap's rights are not narrowable in place: dropping CAP_WAIT from an endpoint cap would need obj_close_protocol's recv_holders accounting), and KOS_SYS_CAP_NARROW is deliberately UNGATED (an authority required in order to drop authorities could never be given up). Every gate is a cap_check_authority call site and is true when the caller is privileged OR holds every requested bit, so a privileged caller passes regardless of its word -- but `idle` is the only privileged thread (`root-unprivileged-idle-alone-privileged`) and it calls none of them, so in practice the BITS decide every gate. cap_check_authority is the ONE cap.h entry point that does not require IrqLock: it reads the subject's own TCB byte, written only by that thread or by its parent BEFORE the child first runs, so on a single core there is no concurrent writer -- an SMP kernel must revisit this with the rest of the IrqLock-as-mutual-exclusion contract. The kernel seats root UNCONDITIONALLY with CAP_AUTH_ALL, and the ordering is load-bearing twice: AFTER thread_create, which zeroes the TCB and would wipe the word, and BEFORE sched::start, so the seat precedes root's first instruction. -KOS_EBADF is still reachable and must still be tolerated: a narrow to 0 succeeds and leaves the word 0, so a SECOND narrow has nothing to give up and is refused -KOS_EBADF on a word the caller legitimately emptied itself. A privileged caller lands on the same refusal -- its permission does not come from this word, so narrowing it would be a lie.
  - *applies:* user/kernel boundary, authority model; kernel (all arches)
  - *source:* kernel/include/kickos/thread.h (Thread::authority); kernel/include/kickos/cap.h (CapAuthority, CAP_AUTH_ALL, the pseudo-handle static_assert); system/include/kickos/sys/cap_index.h (KOS_CAP_AUTHORITY); kernel/syscall/cap.cc (cap_check_authority / cap_seat_authority / cap_narrow_authority); kernel/syscall/syscall_thread.cc (thread_spawn's authority validation and its single cap_seat_authority call); kernel/syscall/syscall.cc (the KOS_SYS_CAP_NARROW arm + every cap_check_authority gate); kernel/init/kmain.cc (the unconditional root seat, ordered between thread_create and sched::start)

- **`privilege-only-boundary-m1`** -- The M1 posture: the user/kernel boundary was privilege-only (CONTROL.nPRIV / PSW.PM + SVC trap) with arch_mpu_apply a no-op on every MCU backend, so an unprivileged thread could read/write kernel memory. **SUPERSEDED at M2** (see below): the MCU backends now enforce -- K64F SYSMPU + XMC PMSA + RX72M MPU + ESP32-C6 PMP all proven on silicon (selftest under enforcement + a cross-domain mpu_fault trap on each; the C6 proof covers SRAM/domain isolation -- its peripheral APM open is a follow-on); xtensa/no-MPU parts stay privilege-only. Historical: code written before M2 must not assume isolation.
  - *applies:* user/kernel boundary, MPU; armv7m, armv6m, rx, xtensa (sim enforces via mprotect; xtensa has no per-thread MPU)
  - *source:* superseded -- see `mpu-apply-on-every-switch-in` for the enforcing backends

- **`mpu-apply-on-every-switch-in`** -- The running thread's MPU region set must be (re)loaded on every switch-in and at first start, replacing the whole active set; region granting must be fail-closed (a region not a page-aligned/pow2 sub-range the backend can describe is skipped, never applied). Mechanism: `arch_mpu_apply` stashes the set at the switch decision; the arch/chip `kickos_arch_mpu_commit` programs the hardware from the switch epilogue after the physical swap (the deferred-commit seam, `../design-mpu-commit-deferred.md`). A privileged thread gets a permissive background (the whole arena / supervisor-all); an unprivileged thread gets only its explicit set (app code RX + app-data RW-NX + domain region(s) + its private stack). ENFORCED on MCU at M2: SYSMPU (K64F), PMSAv7/v6-M (XMC4800, STM32F411, i.MX RT1062, RP2040 -- the shared armv7m/armv6m PMSA backend), PMSAv8 (RP2350, its own base+limit/MAIR backend), PMP/NAPOT (RISC-V), RX MPU -- K64F/XMC/RX/C6/RP2040/RP2350/RT1062 proven on silicon; sim via mprotect. A chip declares itself enforcement-capable twice, and the pair is checked: `select HAS_MPU` in `arch/Kconfig`, without which the enforcing posture cannot be selected at all, and `arch/<family>/chip/<chip>/mpu.cmake`, which also picks the PMSAv8 backend source. A posture that resolved enforcing on a chip shipping no `mpu.cmake` is a configure FATAL_ERROR, never a silent no-op. A chip MAY also declare thread-INVARIANT fixed regions (`kickos_arm_mpu_fixed`, programmed once into the LOW descriptor slots so per-thread grants in the high slots still override them) -- required on a speculating core, where an unbacked-but-Normal aperture stalls the core fault-lessly.
  - *applies:* context switch, MPU, user/kernel boundary; kernel + sim + the MCU MPU backends (M2)
  - *source:* kernel/sched/sched.cc (switch_to's arch_mpu_apply, and start's first-thread apply); kernel/thread/thread.cc (region-set build); arch/arm/common/arch_arm_common.cc (arch_mpu_apply stash + kickos_arch_mpu_commit/kickos_arm_mpu_program, PMSA); arch/arm/chip/mk64f/chip_mk64f.cc (kickos_arch_mpu_commit, SYSMPU); arch/riscv/rv32imac/arch_rv32imac.cc (arch_mpu_apply stash + kickos_arch_mpu_commit, PMP); arch/rx/rxv3/arch_rxv3.cc (arch_mpu_apply stash + kickos_arch_mpu_commit, RX MPU); arch/sim/sim.cc (arch_mpu_apply mprotect)

- **`mpu-bypass-windows-accepted`** -- PMSA enforcement is NOT total: two windows bypass it, both accepted residuals bounded by the reasons below, and a change must keep them bounded rather than assume the region set always applies. (1) MPU_CTRL is enabled as `MPU_CTRL_ENABLE | MPU_CTRL_PRIVDEFENA`, WITHOUT `HFNMIENA`, so the MPU is off inside HardFault and NMI handlers; accepted because that path is short and runs cached. (2) kickos_arm_mpu_program writes `MPU_CTRL = 0` to reprogram descriptors, reverting to the Normal-typed background map for those instructions; accepted because kickos_arch_mpu_commit brackets the whole disable/reprogram/re-enable in `cpsid i` and the window runs from already-cached fetches, so no NEW speculation is armed inside it. Both windows also drop any chip fixed regions' effect (`mpu-apply-on-every-switch-in`), which is what makes them matter on a speculating core: on Cortex-M7 an unbacked-but-Normal aperture stalls the core with no fault to report, so the anti-speculation wrap is off exactly where a stall is hardest to diagnose.
  - *applies:* MPU, context switch, fault/NMI paths; the ARM PMSA backends (armv7m, armv6m, PMSAv8), imxrt1062 above all
  - *source:* arch/arm/common/arch_arm_common.cc (kickos_arm_mpu_program / kickos_arm_mpu_fixed_init, the MPU_CTRL writes); arch/arm/common/kickos_arch_mpu_commit_default.cc (the cpsid bracket); arch/arm/common/arch_arm_pmsav8.cc (the v8-M commit, same bracket, same CTRL value); docs/design-teensy-mpu-hang.md

- **`grant-refuses-kernel-reserved-blocks`** (Rule 7) -- The grant path MECHANICALLY refuses any MMIO/RAM grant that overlaps a kernel-owns-for-life block (timebase, IRQ controller, every access-permission controller -- the MPU/PMP twin AND any bus-side gate such as the K64F AIPS PACR pages or the ESP32-C6 HP_APM/HP_TEE -- clock/reset gates), binding EVERY granter including privileged ones (not "trust the granter"). grant_region_admissible (kernel/grant) refuses size-0/wrap, then any reserved-block overlap, then requires: a DEVICE grant be privileged + exactly one MPU descriptor (no rounding) + not a bit-band alias; a RAM grant satisfy the arch's region-admissibility predicate AND be confined to the user arena for EVERY caller (no privileged waiver). That predicate is `arch_ram_region_admissible` (arch/include/kickos/arch/arch.h), which is power-of-two size plus natural alignment where `arch_mpu_region_pow2()` is 1 (PMSAv7, PMP NAPOT) and a granule multiple of `arch_mpu_min_region()` where it is 0 (PMSAv8, SYSMPU, RX RXv3). It is deliberately NOT `arch_mpu_region_encodable`, which answers the same question for an MMIO window and on the sim admits EXACTLY ONE -- the published fake-register base at exactly `0x10000` (`privileged-write-seam-possession-and-allowlist`) -- and fail-closes on every other address and every other shape of that one. domain_for (kernel/domain) runs it on a SHARED grant at the region-commit chokepoint before allocating a domain slot; thread_spawn runs it on every PER-THREAD grant, the caller-owned stack and the DEV window both, because those are regions of the thread and never of its task's domain; and thread_create carries a backstop assert over the whole composed set. Each enforcing chip MUST declare arch_reserved_blocks -- NO fallback TU on purpose, so a forgetful enforcing port fails to LINK (affirmative fail-closed). On a bit-band core (arch_bitband_present() != 0) the overlap test also covers each reserved block's word-per-bit alias image and a device grant into either alias window is refused. grant_reserved_validate asserts at boot that arena + app extents are reserved-disjoint. Under KICKOS_HAVE_MPU=0 the whole module is inline no-op stubs (admissible always true), so call sites are #if-free and pay zero flash.
  - *applies:* memory-domain grant, MMIO isolation, single-ownership; kernel (grant/domain) + enforcing MPU chips (M4)
  - *source:* kernel/include/kickos/grant.h; kernel/grant/grant.cc (grant_hits_reserved/grant_region_admissible/grant_reserved_validate); kernel/domain/domain.cc (domain_for); kernel/syscall/syscall_thread.cc (thread_spawn's stack_base / mem_base / MMIO grant paths) + kernel/syscall/syscall.cc (KOS_SYS_GRANT_PROBE); kernel/thread/thread.cc (thread_create backstop assert); kernel/init/kmain.cc (grant_reserved_validate at boot); arch/include/kickos/arch/arch.h (arch_reserved_blocks/arch_bitband_present)

- **`dev-window-access-is-thread-scoped-its-lifetime-task-scoped`** -- A granted DEV window is a region of the ONE thread that asked for it (`thread_create` composes it beside that thread's private stack), and never a region of its task's domain. That is a deliberate refusal, not an omission: a domain is SHARED, so a task-wide window would hand register access to a peer that never asked for it, to fix a lifetime problem. The lifetime is the task's instead, and it is `task-scoped-death-and-a-cancel-that-reaches-every-park` that delivers it -- when any member of a driver's group dies the rest are cancelled, so the window comes back when the GROUP goes rather than when one thread does. A thread not in an explicit group is alone in its task, so for it the two scopes coincide, which is why this changed nothing for the spawns that predate the task layer. `Thread::mem_base` is the other half of the split and goes the other way: it is the group's, so a member spawned into a task may not bring one (-KOS_EINVAL) and shares its task's domain region instead.
  - *applies:* MMIO isolation, memory domains, thread lifecycle; kernel + every enforcing chip
  - *source:* kernel/thread/thread.cc (thread_create's region composition, dev_window_free); kernel/domain/domain.cc (domain_for, which no longer takes an MMIO window at all); kernel/syscall/syscall_thread.cc (the DEV window's admission and exclusivity, and the member-brings-no-memory refusal); docs/design-task-layer.md

- **`task-scoped-death-and-a-cancel-that-reaches-every-park`** -- A thread that joined an explicit task declared itself part of one unit, so its death ends the group: `sched::exit_current` cancels every live member of the dying thread's task before it releases the task reference, and `kos_task_kill` does the same from a supervisor. Under the implicit default -- a thread that names no task is alone in one -- the scan matches only the dying thread itself, and `thread_cancel` refuses a `dying` thread, so the rule is a comparison and nothing else for every spawn written before tasks existed. That `dying` test is the ONLY thing sparing a thread from its own group's cancel and it must cover both directions, the thread whose exit issued the cancel and a peer already tearing down; a second "except this one" guard beside it is refused as the copy that goes stale. A cancel is TOTAL over `WaitKind` (`thread_abort_park`): every park ends, and where the primitive has a code to carry one it reports -KOS_ECANCELED. The unwind is per-kind and is not a wake -- a mutex waiter does NOT acquire the mutex and the owner's inherited priority is reverted, a semaphore's count is left alone so a later post still hands its token to a genuine waiter, an endpoint park goes through `endpoint_wait_abort`, and a sleeper's deadline is dropped. The DEATH POINT is the next syscall ENTRY (`syscall_dispatch`), deliberately not the exit: breaking the park gives the thread one window to clean up over memory it already holds, and the entry check is what ends a thread that ignored the code or was parked in a primitive with no channel to report through. The one thread this does not reach is one that never asks the kernel for anything again, and no caller may assume it will not be: 0 from `kos_thread_kill`/`kos_task_kill` means the request was accepted, never that the thread is gone.
  - *applies:* thread lifecycle, scheduler, IPC, driver teardown; kernel (all arches)
  - *source:* kernel/thread/park.cc (thread_abort_park/thread_cancel/task_cancel_group); kernel/sched/sched.cc (exit_current); kernel/syscall/syscall.cc (the death point); kernel/syscall/syscall_thread.cc (thread_kill/task_kill); tests/unit/taskdeath/group_kill.cc

- **`dev-window-exclusivity-is-bounded-by-the-silicon`** -- A DEV window has exactly ONE holder: `thread_spawn` refuses a second grant overlapping a live one with `-KOS_EBUSY`, and the test is a RANGE overlap (`dev_window_free` -> `grant_ranges_overlap`), not an exact-base compare, so a partial overlap cannot slip past. The window is a region of the asking THREAD and never of its task's domain (`dev-window-access-is-thread-scoped-its-lifetime-task-scoped`), so `dev_window_free` scans live THREADS; a thread that is EXITED, INACTIVE or `dying` is not a holder, and the `dying` arm is what lets a supervisor woken by the teardown's EPIPE respawn into the window at once instead of racing the corpse. That is what lets two unprivileged drivers share one peripheral MODULE through disjoint per-channel windows: on `xmc4800`, `xmcuart`/`xmcuartirq` hold `[0x40030000,0x400301FF]` (USIC0 CH0) and `xmcssc` holds `[0x40030200,0x400303FF]` (CH1). The module-level clock gate and reset are NOT reachable from either: `CGATCLR0`/`PRCLR0` are in the SCU, which `arch_reserved_blocks` withholds from every grant, and `kickos_xmc_usic_init()` ungates USIC0 from `arch_init`.
  **The per-channel window is NOT a complete isolation boundary, and the silicon is why.** `KSCFG` is a CHANNEL register at channel_base + `0x0C`, so it is inside each channel's granted window, and it is `rw` from user mode -- but `KSCFG.MODEN` gates the whole MODULE (XMC4700/4800 RM, USIC V2.16, section 18.9 p.18-165: "If the module clock is disabled by KSCFG.MODEN = 0, the module cannot be accessed by read or write operations (except register KSCFG that can always be accessed)"). So the holder of CH0 can stop CH1, and the holder of CH1 can stop CH0, and no kernel check can prevent it without taking a register the driver legitimately needs for its own bring-up.
  This is an ACCEPTED HARDWARE FLOOR, not a defect to fix: isolation is as perfect as the hardware permits, and where the silicon puts a module-wide control inside a per-channel window, two drivers on one module must trust each other. The kernel's guarantees stop at the window boundary. A chip that wants stronger separation has to put its channels in separate blocks.
  Consequence for the console: `arch_console_reclaim_window` on `xmc4800` returns CH0 only, so `xmcssc` holding CH1 does not defer a console reclaim, which is correct -- but a reclaim reprogramming CH0 cannot restore a module a CH1 holder has gated.
  - *applies:* MMIO isolation, memory domains; kernel + every chip granting a sub-block window
  - *source:* kernel/thread/thread.cc (dev_window_free); kernel/syscall/syscall_thread.cc (thread_spawn's -KOS_EBUSY); kernel/include/kickos/grant.h (grant_ranges_overlap); arch/arm/chip/xmc4800/regs/usic.h (KSCFG at 0x0C, KSCFG_MODEN); arch/arm/chip/xmc4800/chip_xmc4800.cc (arch_reserved_blocks, the SCU block); system/init/xmc4800-relax/service_list.cc (the two disjoint windows)

- **`privileged-write-seam-possession-and-allowlist`** -- The seams that perform a privileged peripheral act on an unprivileged caller's behalf -- `arch_periph_enable` (`KOS_SYS_PERIPH_ENABLE`, the clock-ungate + bus-side unprotect for a block) and `arch_periph_reg_write` (`KOS_SYS_PERIPH_REG_WRITE`, one store to one register) -- are gated on POSSESSION, never on an authority bit. The predicate is `caller_holds_mmio_block(base)`: the caller must hold a LIVE region carrying `ARCH_MPU_DEV | ARCH_MPU_R | ARCH_MPU_W` whose base equals the requested base EXACTLY. Containment does NOT count, so a window covering several blocks is not a licence to act on a block it merely contains. A **privileged** caller short-circuits the walk and passes unconditionally, as in `cap_check_authority`; the only privileged thread in a running image is `idle`, which calls no syscalls. The register-write seam takes the STRONGER predicate `caller_holds_mmio_reg(base, offset)`: the region matched by the exact base must ALSO CONTAIN `[base + offset, +4)`. Without that span the possession check bounds nothing but the base -- a 32-byte window at a block's start reaches every register the chip table names anywhere in that block (MEASURED: a holder of 32 bytes at `0x40000000` passed the gate at offsets `0x40`, `0x1000` and `0x0FFFFFFF`). The offset must also be 4-ALIGNED and `base + offset` must not wrap; both are `-KOS_EINVAL`, refused ahead of possession because they are malformed requests rather than possession failures. Possession rather than a capability because where the silicon puts a block's controls inside the window, holding the window already carries the authority; a bit would be a second, forgeable name for the same fact. Failing the gate is `-KOS_EPERM`. **Possession must never become blanket write access to the block**, because that is precisely what the bus classification withholds -- so `arch_periph_reg_write`'s per-chip backend is an ALLOWLIST of exact `(base, offset)` pairs and anything it does not name is `-KOS_EINVAL`. A per-BLOCK entry would hand back exactly what the silicon refuses and turn the seam into a privilege-escalation primitive keyed on a grant. The granularity is therefore the REGISTER, never a range, and an absent entry is a DECISION, not an omission (`xmc4800`'s U0C0 has no entry because the kernel owns the console channel's baud and enable). **"One register" is not "only the authority the driver needs"**, so each entry ALSO carries a per-entry VALUE MASK: `(value & ~mask) != 0` is `-KOS_EINVAL`, REFUSED WHOLE and never trimmed, because a silently dropped configuration bit is the failure class the read-back exists to catch. On `xmc4800`, `CCR` grants `MODE[3:0] | RIEN | AIEN` -- 6 bits of 32, with `RIEN`/`AIEN` deliberate because `xmcssc` arms them last -- and withholds `TBIEN`, `HPCEN`, `PM`, `RSIEN`, `DLIEN`, `TSIEN` and `BRGIEN`; `FDR` grants `STEP | DM`, and `BRG` every writable field, where a mask withholds only read-only and reserved bits and so buys little. `static_assert`s pin each composed grant, so a field-mask edit cannot widen it silently. A tabled block must also be CLOCKED. The contract now REQUIRES it (`arch/include/kickos/arch/arch.h`), though no backend enforces it: a store into a clock-gated block faults INSIDE the privileged store and reaches `kfault_terminate`, i.e. whole-system death from one syscall -- an unprivileged caller's one-syscall system-kill primitive. Not live today only because `kickos_xmc_usic_init()` runs unconditionally from `arch_init` so USIC0 is never gated; a `U1C0`/`U2C0` entry (gated at reset behind `CGATCLR1`) would arm it. TWO backends exist in-tree: `xmc4800` (real MMIO) and the SIM, which assumes NO fixed host address: it tries FIVE candidate bases in order with `MAP_FIXED_NOREPLACE` (`0x40000000`, `0x100000000`, `0x400000000`, `0x10000000000`, `0x100000000000` -- 1 GiB to 16 TiB) and PUBLISHES whichever landed as the only base the seam and the encoder answer for, the grantable window being `0x10000` (64 KiB) inside a mapping twice that, so its allowlist can carry one entry OUTSIDE the grantable window to reproduce the containment hazard on the host. The sim one is what puts the MECHANISM under a CI gate -- allowlist match, mask compare, refuse-not-trim, containment, alignment and wrap are each mutation-proved. Two arms move the other way once the window is 64 KiB, and the retraction belongs here: `grant_reserved`'s `DEV_UNPRIVILEGED(0x40000000, 0x1000)` case is VACUOUS on the sim, because `arch_mpu_region_encodable` admits the published base at exactly `0x10000` and nothing else, so deleting the `AUTH_MEMORY` refusal it is meant to exercise leaves the same answer (the authority test runs first, encodability refuses the identical request anyway). Conversely the misaligned-offset and wrapping arms, vacuous EVERYWHERE while they ran from a holder (from one both answer `-KOS_EINVAL` regardless), now DISCRIMINATE: they moved to the UNHELD worker, where a dropped check falls through to possession and answers `-KOS_EPERM` instead. What the sim cannot model is the bus classification itself: that an unprivileged store is silently DISCARDED remains a `pvprobe`-only fact, as does any chip's actual mask column. A chip with no backend answers `-KOS_ENOSYS`, never 0: a caller reaching for the seam has a register the bus refuses it, so a success answer would report a store that never happened. Every call site READS THE REGISTER BACK, because the discard is silent in both directions and the read-back is the only evidence a store landed -- and a read-back comparison must mask any field the hardware itself drives (the XMC `FDR` `RESULT[25:16]` case), or a landed store reports as discarded. `arch_periph_reg_write`'s default decline is a ONE-SYMBOL archive member (`arch/common/arch_periph_reg_write_default.cc`), NOT a weak symbol. The load-bearing half is that a chip's definition must live in an ALWAYS-ANCHORED archive member (`chip_<chip>.cc`, force-loaded via `-u g_isr_vector` -> `startup.S` -> `Reset_Handler`), because that member is extracted in link pass 1 before `syscall.cc` makes the symbol undefined. Scan order (`kickos_arch_*` after `kickos_chip_*`) is only a BACKSTOP and has never actually been exercised: MEASURED with arch before chip inside the rescan group, the link still succeeds and resolves CORRECTLY from the anchored member, the map showing zero mentions of the default. A duplicate-definition error is therefore NOT the guarantee -- it is not even a reliable backstop, and no doc should claim it. The anchored member IS the invariant, and a chip putting its definition in a dedicated TU nothing else references gets NEITHER protection and SILENTLY DECLINES at runtime: MEASURED by reversing the group AND moving `arch_idle_wait` into an unreferenced TU, whereupon the link succeeded with ZERO diagnostics while `objdump` showed the fallback's `wfi` where the chip's `nop` belonged. The anchoring is now ENFORCED in-tree, not merely evidenced, by `tests/static/check_seam_defaults.sh` (ctest `seam_defaults`, on every board): its leg 2 requires the fallback member to be ABSENT from the selftest's `-Wl,-Map` link map wherever a backend defines the seam, its leg 3 requires the fallback to be PRESENT and pulled by that exact symbol where none does, and its leg 4 refuses any weak symbol outside `tests/static/weak_allowlist.txt`. This is no longer a one-off for this seam: it is how EVERY optional seam in the tree resolves, `__attribute__((weak))` having been removed from all of them (`arch/CMakeLists.txt` states the rule canonically, under "Seam fallbacks: the lone-TU rule"). Honest about the mechanism -- it is LINKER behaviour, not language semantics, but behaviour every Unix-like linker and MSVC `.lib` shares, unlike `weak`, whose archive interaction is implementation-defined. Adding a second symbol to the default TU breaks the member's other half (it would be extracted unconditionally and collide on every chip with a backend). Membership in the class-2 family requires a MEASURED hardware refusal, never a plausible reading of a manual.
  - *applies:* MMIO isolation, syscall, user/kernel boundary; kernel + per-chip backends (enforcing chips)
  - *source:* arch/include/kickos/arch/arch.h (arch_periph_enable / arch_periph_reg_write); kernel/syscall/syscall_mem.cc (caller_holds_mmio_block / caller_holds_mmio_reg); kernel/syscall/syscall.cc (the KOS_SYS_PERIPH_ENABLE and KOS_SYS_PERIPH_REG_WRITE arms); arch/common/arch_periph_reg_write_default.cc (the lone-TU decline); arch/arm/chip/xmc4800/chip_xmc4800.cc (the U0C1 FDR/BRG/CCR allowlist); tests (selftest periph_enable_unheld / periph_reg_write_unheld, whose arm 3 is the offset bound); user/apps/xmc4800-relax/pvprobe (the silicon discriminator)

## Tickless timer & clock

- **`timer-min-delta-guard`** -- A deadline must never be armed in the past, so the next-event time is floored at KICKOS_TIMER_MIN_DELTA_NS ahead of the clock. `arm_slice` floors an RR quantum where it is born, so a sub-min-delta quantum (including a hostile user value) collapses to the min slice rather than re-arming every tick (interrupt storm). Deadlines handed to arch_timer_arm are ABSOLUTE and immutable for their whole life; a deadline already in the past is an immediate fire, which every backend produces by flooring the programmed delta at one tick (`timer-delta-clamp-before-convert`).
  **The floor belongs where the deadline is BORN, and `ktime_rearm` must not apply one.** `ktime_rearm` runs on every context switch, so a floor recomputed there against a fresh `ktime_now()` re-derives a deadline inside the min-delta window to a DIFFERENT value on every call -- which is precisely the quantity every arch backend dedups on (`g_armed_deadline_ns` on ARM, `g_rx_armed_ns` on RX, the absolute compare on CLINT/POSIX). The dedup then never matches, the one-shot countdown restarts from zero before it can reach the compare, and such a sleeper is held off for as long as switches keep arriving faster than min-delta; on ARM the same reprogram also writes `ICSR.PENDSTCLR` unconditionally, destroying a SysTick expiry latched while `ktime_rearm` held BASEPRI. So the floor is applied ONCE against ONE clock reading at each of the THREE sites where a deadline is born -- `ktime_sleep_until` for a sleeper, `arm_slice` for an RR quantum, `ktime_deadline_arm` for the deadline a timed wait hangs off a park on some other queue -- and `ktime_rearm` passes the absolute deadline through untouched. A new birth site adds a fourth entry here; it does NOT get to re-derive the floor further down.
  - *applies:* tickless timer; kernel + all arches
  - *source:* kernel/time/time.cc (ktime_rearm, ktime_sleep_until, ktime_deadline_arm); kernel/sched/policy_fifo_rr.cc (arm_slice); tests/unit/ktime/ktime_rearm.cc (the host gate: it reads the exact value the backends dedup on, which no on-target arm can see)

- **`rearm-before-switch`** -- ktime_rearm must program the next-event timer for the INCOMING thread before arch_switch, because the outgoing thread will not return to switch_to until it is itself resumed -- so the incoming thread's policy deadline (RR slice) must be armed now, not after the switch.
  - *applies:* tickless timer, context switch; kernel
  - *source:* kernel/sched/sched.cc (the two ktime_rearm calls, in switch_to and start)

- **`rr-quantum-is-wall-clock`** -- A round-robin quantum measures WALL-CLOCK time, not CPU time. `Thread::slice_deadline_ns` is an ABSOLUTE deadline, and policy_on_switch_in re-arms it ONLY when the thread is not RR-with-a-quantum, or the deadline is UINT64_MAX (unset), or it is already past: a deadline still in the FUTURE survives the switch untouched. Re-arming unconditionally on switch-in refunds the whole quantum on every resume, so a thread preempted more often than its quantum never reaches an expiry AT ALL -- round-robin silently degenerates to FIFO and the equal-priority peer starves for as long as the preemption lasts. ONE periodic higher-priority thread is enough to trigger it (a prio-13 driver IRQ thread against prio-10 RR peers is the shipping posture, not a contrived case). The guarantee this buys is that **no equal-priority peer waits longer than one quantum of REAL time**; it deliberately does NOT give each thread quantum_ns of CPU. CPU-time accounting is the alternative and was REFUSED: it needs an on_switch_out hook and a slice_left_ns field, and it weakens the peer-latency bound to "eventually" -- a thread preempted for 10 ms would still be owed its full slice afterwards. A full quantum is granted (arm_slice) in exactly two places, and the distinction is the whole invariant: policy_on_slice_expire ALWAYS re-grants after rotating to the peer -- which is what keeps a sole RR thread with no peer from sitting on a deadline in the past -- while policy_on_switch_in re-grants only when there is no live deadline to preserve. A sub-min-delta quantum is clamped inside arm_slice, see `timer-min-delta-guard`. Corollary, and equally load-bearing: **sched::tick_rr(now) must run BEFORE the sleeper-wake loop** in ktime_on_timer. tick_rr charges the slice to whatever kernel().current names, and sched::wake reschedules and REASSIGNS kernel().current, so running it after the loop charges the wrong thread and DROPS the expiry. On a coarse clock the sleeper and slice deadlines quantise together, which makes that the common case rather than a race. Both halves are mutation-proven: reverting EITHER gives zero slice expiries and an AAABBB interleave where ABABAB is required, measured on qemu-an386 under MPU with a prio-13 periodic thread. A slice-expiry COUNTER is the evidence -- the interleave string alone passes with zero expiries whenever the workers hand each other a semaphore token.
  - *applies:* scheduler policy, tickless timer; kernel (all arches)
  - *source:* kernel/sched/policy_fifo_rr.cc (arm_slice / policy_on_switch_in / policy_on_slice_expire); kernel/sched/sched.cc (tick_rr); kernel/time/time.cc (ktime_on_timer -- tick_rr ordered ahead of the wake loop); kernel/include/kickos/thread.h (Thread::slice_deadline_ns, quantum_ns)

- **`timer-delta-clamp-before-convert`** -- The ns->cycle conversion for the one-shot timer must clamp the delta to the counter's one-shot range BEFORE the ns*freq multiply (else a far-future or UINT64_MAX deadline overflows), and sleep deadlines must saturate to UINT64_MAX on now+ns overflow. A clamped deadline fires early and the kernel re-arms the remainder (harmless extra wake).
  - *applies:* tickless timer, ns<->tick; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/common/arch_arm_common.cc (arch_timer_arm's clamp ahead of the ns*freq multiply); kernel/time/time.cc (ktime_sleep_ns's now+ns saturation); arch/rx/rxv3/arch_rxv3.cc (arch_timer_arm); arch/xtensa/lx6/arch_xtensa.cc (arch_timer_arm)

- **`cycle64-wrap-extend-atomic`** -- The software 32->64-bit extension of the free-running cycle counter (catch-wrap on each read) must run under the critical section so the {read counter, compare to last, bump high} sequence is atomic against a concurrent reader from thread and ISR context. LIMITATION: a wrap not observed within one 2^32-cycle period is missed (M1).
  - *applies:* tickless clock; armv7m (PER CHIP, not the arch layer -- `arch_armv7m.cc` states
    there is deliberately no DWT fallback TU, the DWT being debug-domain), rx (CMTW1),
    xtensa (CCOUNT)
  - *source:* arch/arm/chip/imxrt1062/chip_imxrt1062.cc (gpt_ticks, the wrap-extend read bracketed by arch_irq_save/restore -- on armv7m the extension is per chip, the arch trace clock being a raw DWT read); arch/rx/rxv3/arch_rxv3.cc (g_cyc_high / g_cyc_last, now_cycles); arch/xtensa/lx6/arch_xtensa.cc (now_cycles)

- **`conversions-track-live-clock`** -- All ns/cycle conversions and the SysTick/baud programming must track the LIVE SystemCoreClock (or kickos_rx_timer_hz), not a compile-time constant; the cached reciprocal-multiply / max-delta must be recomputed when the clock value changes. A PLL bring-up that updates SystemCoreClock must therefore keep the timer and clock correct. WHERE that recompute may happen is not free: a STATELESS cache may re-derive itself lazily on observing a changed clock (arch_timer_arm's cached max_delta does), but the monotonic clock's accumulator rate may not, and `clock-anchor-sole-writer-at-rate-edge` is the binding rule for it.
  - *applies:* tickless timer, ns<->tick, SystemCoreClock; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc (ns_to_cycles, off SystemCoreClock); arch/arm/common/arch_arm_common.cc (arch_cpu_clock_hz, and arch_timer_arm's cached max_delta recomputed when the clock moves)

- **`timer-disarm-clears-pend`** -- 'Disarm' must mean no callback will fire: disarming (and reprogramming) the one-shot timer must clear any interrupt request already latched while the line was masked (ARM ICSR PENDSTCLR; RX clears the IR flag), or a stray timer callback fires once on the next IrqLock release.
  - *applies:* tickless timer; armv7m, armv6m, rx
  - *source:* arch/arm/common/arch_arm_common.cc (arch_timer_disarm's ICSR PENDSTCLR); arch/rx/rxv3/arch_rxv3.cc (arch_timer_disarm's ICU IR clear)

- **`clock-retune-coherence-tail`** -- A runtime core-clock retune is ONE ordered sequence and each step is load-bearing in that position: refuse unless the console is KERNEL_OWNED (return the unchanged Hz before anything is masked, because the kernel cannot re-derive a userspace driver's baud); take the IrqLock (single-core, so this quiesces the one timer); arch_timer_disarm; drain the console ring and wait for the TX shift register to go idle; call arch_cpu_clock_set, which internally does the flash-wait-state/voltage step, the divider or PLL walk, the anchor re-price at the rate edge and the SystemCoreClock write, and returns the LANDED Hz; re-derive the console baud; ktime_rearm. The baud step is gated on an ACTUAL move (`hz != 0 and hz != previous`), NEVER on a success flag: a backend that fails its relock and parks the core on a fallback point (K64F fail_to_fei, ~20.97 MHz) still MOVED the clock and rewrote SystemCoreClock, so it returns that non-zero Hz and needs the identical tail. A return of 0 means "this chip cannot change its clock at all" and never "failed but moved". The flush must reach transmission-complete, not TX-buffer-empty, or the byte still clocking out of the shift register is garbled by the new baud. ns-valued sleep deadlines and the RR slice are clock-invariant and are deliberately NOT rescaled, which holds ONLY because the anchor keeps `now` continuous (`clock-anchor-sole-writer-at-rate-edge`).
  - *applies:* tickless timer, clock retune, console baud; kernel + the retuning chips (xmc4800, mk64f)
  - *source:* kernel/time/clock_select.cc (cpu_clock_set, the whole sequence); arch/arm/chip/xmc4800/chip_xmc4800.cc and arch/arm/chip/mk64f/chip_mk64f.cc (arch_cpu_clock_set / arch_console_flush_sync / arch_console_retune); arch/common/arch_cpu_clock_set_default.cc (the 0 "cannot change" fallback); arch/common/arch_console_flush_sync_default.cc + arch/common/arch_console_retune_default.cc (the no-op fallbacks)

- **`clock-anchor-sole-writer-at-rate-edge`** -- The tickless clock's epoch anchor (base_ns, base_ticks, mult_q32) is written ONLY at a rate edge: `init()` at boot, plus `reprice()` inside arch_cpu_clock_set on a retuning chip. arch_clock_now is a PURE read of that triple. The lazy `if (hz != cached_hz) recompute mult` each affected arch_clock_now once carried MUST stay removed: the rate prices the WHOLE accumulated tick count, so a read landing between the SystemCoreClock write and the re-anchor would reprice all of history at the new rate and freeze that phantom forward jump into base_ns PERMANENTLY (seconds to minutes on the shipped ratios, K64F's 120 -> 20.97 MHz being the widest at about 5.7x, and every ns deadline compared against `now` goes with it). reprice() captures base_ns under the OLD rate BEFORE the clock hardware moves, so only the ticks inside the brief masked retune window are mispriced, as frozen skew rather than a jump. The three stores are not atomic as a group, so they need the retune's IrqLock; a synchronous fault handler reading the clock between them is an accepted panic-path-only window.
  - *applies:* tickless clock, ns<->tick, clock retune; every chip whose arch_clock_now converts a hardware tick count (mk64f, xmc4800, stm32f411, stm32f103, stm32f302, sam3x8e)
  - *source:* arch/include/kickos/arch/clk_anchor.h (init / ns_from / reprice); arch/arm/chip/xmc4800/chip_xmc4800.cc and arch/arm/chip/mk64f/chip_mk64f.cc (the g_clk anchor + the reprice at the rate edge in arch_cpu_clock_set); arch/arm/chip/stm32f411/chip_stm32f411.cc (anchor with no retune, sole writer init)

- **`timer-arm-dedup-needs-disarm`** -- arch_timer_arm early-returns when deadline_ns equals the deadline SysTick is already counting (the guard that stops a far deadline being restarted on every reschedule), so after a clock-rate change a bare ktime_rearm() silently leaves SysTick running at the OLD rate: the nearest deadline_ns is usually unchanged, so the arm is deduplicated away. arch_timer_disarm() is what makes a re-arm real, because it clears g_armed_deadline_ns, disables SysTick, and drops a pend latched while masked. Any path that changes the timer's clock basis must disarm first, not poke g_armed_deadline_ns (a file-static, deliberately not externally reachable).
  - *applies:* tickless timer, clock retune; armv7m, armv6m
  - *source:* arch/arm/common/arch_arm_common.cc (arch_timer_arm's dedup guard + arch_timer_disarm); kernel/time/clock_select.cc (the disarm ahead of the retune, the re-arm after it)

## IRQ dispatch

- **`irq-table-no-null-slots`** -- Every IRQ line is seeded (by irq_init, before any driver attaches) with the null-object default handler that masks the line and bumps the spurious counter, so the ISR dispatch path indexes the table with NO null check and an unhandled enabled line cannot storm or be silently dropped.
  - *applies:* IRQ dispatch; kernel + all arches
  - *source:* kernel/irq/irq.cc (irq_default_handler, set_default, irq_init, and kickos_isr_irq's unchecked table index); kernel/init/kmain.cc (irq_init, before console_buffer_init)

- **`one-driver-per-line`** -- A line may be claimed (irq_attach or irq_claim) only while it still holds the null-object default; a second claim fails (false / -KOS_EBUSY) rather than overwriting an existing driver and orphaning its irq_wait forever. No stealing. It is also what orders the console handover: the kernel's own console_tx_deinit must have detached the TX line before any tier-1 claim of it can pass.
  - *applies:* IRQ dispatch; kernel
  - *source:* kernel/irq/irq.cc (irq_attach, irq_claim)

- **`console-returns-to-the-kernel`** -- A console the kernel has handed to a userspace driver must come BACK on every path that ends that driver, or the system goes permanently mute: `console_emit` DROPS every kernel write while `USER_OWNED`, so a dead driver takes the panic banner, the fault dump and ordinary `kprintf` with it. Two triggers reach the same `RECLAIMED` state. A PANIC reclaims from any prior state (`kpanic_enter`), because ownership tracks a publish and not whether the device is garbled. A DRIVER DEATH is NOTED when the published endpoint's `recv_holders` reaches 0 -- keyed on that count and NOT on a thread identity -- but the note alone does NOT reclaim: the precondition is asked of the DEVICE. `console_on_driver_death` defers while any live domain still holds `arch_console_reclaim_window()`, because a driver is a THREAD GROUP and the endpoint's last RECEIVER is the service thread rather than the thread holding the registers; reclaiming on the note alone reprogrammed the UART under a live IRQ thread and silenced its own source. The note stays SET across a refusal and every `exit_current` and voluntary close re-runs the check, so the LAST holder's own exit reclaims. The death path is deliberately TWO halves: the cap layer only NOTES the fact, and `exit_current` acts on it AFTER the whole `cap_teardown` loop and before `domain_release`. Ordering is the point -- reclaiming inside a cap arm would run at an arbitrary index in that loop, possibly while the dying driver's IRQ cap is still live and its TX line still armed, so re-initialising the UART could race an interrupt still firing into `irq_event_isr`. `RECLAIMED` is stored BEFORE the body on both paths, so a fault inside a reclaim body cannot recurse and the body runs exactly once. **What is NOT implied**: a per-chip `arch_console_reclaim` body exists on mk64f, xmc4800, esp32c6 and esp32, so on every other chip the state flips and the polled route is restored but the DEVICE is whatever the driver left. The sim needs no body at all (host fd 1 holds no state), which is why it can gate the state machine without a board. A VOLUNTARY close of the last receiver reclaims too, acted on inside handle_close rather than deferred: there is no teardown loop to finish first, and a note left pending would reclaim the console at an unrelated later thread exit.
  - *applies:* console ownership; kernel + every board that publishes a console
  - *source:* kernel/init/console.cc (ConsoleState, console_note_driver_death, console_on_driver_death, kpanic_enter); kernel/syscall/cap.cc (obj_close_protocol's CAP_ENDPOINT arm at recv_holders -> 0, and handle_close); kernel/sched/sched.cc (exit_current); tests/integration/check_sim_drvdeath.sh

- **`publish-then-prove-before-any-client`** -- A console handover is not complete at the publish: it is complete when the driver is PROVEN to be receiving. The publish must come first, because on a chip where the driver takes the UART the kernel was driving, the kernel has to let go before the driver may touch it (one device, one owner) -- so a span in which kernel-console writes are DROPPED is inherent and is not a defect. What must not happen is a CLIENT running inside that span. So the bring-up tail closes the caller's own WAIT-bearing cap and then probes the route with a ZERO-LENGTH rendezvous on cap 0, the same path every client uses: a rendezvous send returns only once a receiver has taken it, so on success no client can observe an unserved console, and it costs no bytes on the wire. The close-before-probe order is load-bearing: it leaves the driver as the SOLE receiver, so a driver that dies during bring-up takes recv_holders to 0, which both EPIPEs the probe AND reclaims the console -- which is the only reason a bring-up failure is reportable at all rather than structurally mute. A driver that HANGS in bring-up instead of dying parks the probe indefinitely; that is a loud hang rather than a silent boot, and per-chip bring-up polls are bounded by KICKOS_POLL_SPIN_MAX. A failed spawn takes the same route (close first, then report).
  - *applies:* console handover; every board with a userspace console service
  - *source:* user/include/kickos/sys/driver_service.h (console_handover_finish, and bring_up, which is the one caller on every board); system/init/sim/service_list.cc (the two window-thread postures, which hand-roll the same order because their window base is probed); tests/integration/check_sim_drvdeath.sh (case 2)

- **`irq-line-is-a-capability`** -- A tier-1 line binding is a POOLED, REFCOUNTED kernel object named by a `CAP_IRQ` capability, not an integer handle in a bump array. Three consequences a change must not break. (1) MINTING is gated on `AUTH_IRQ` -- namespace-wide, since the caller names a bare line number -- while `wait`/`ack`/`notify` are gated on POSSESSION of the cap plus the matching right at the one chokepoint (cap_resolve_e: `CAP_WAIT` for wait/ack, `CAP_SIGNAL` for notify). No authority bit gates use, and there is no per-line authority: while userspace tier-2 irq_attach exists, it is a wider door over the same namespace, so a finer bit would buy nothing. (2) RELEASE rides the walk that already exists: `cap_teardown` on thread exit, fault-kill and voluntary `handle_close` all reach irq_ref_drop, which at refs -> 0 DETACHES the line then frees the slot. Detach strictly before free is load-bearing -- irq_event_isr holds the binding's ADDRESS as its pre-bound arg, so the slot must stop being reachable from the dispatch table before it returns to the pool. The generational SlotPool then makes every outstanding cap naming that slot inert rather than dangerous. (3) The latency invariant SURVIVES pooling: a SlotPool slot address is stable for the slot's life, so the ISR still does zero lookups, and a parked irq_wait is safe outside the lock because the waiter's own cap pins a reference. The close protocol's IRQ arm is deliberately EMPTY: refs -> 0 with a waiter parked needs a kill primitive, which does not exist, so the leak-never-strand guard asserts instead of waking, and the wake arm lands WITH that primitive.
  - *applies:* IRQ dispatch, capability layer; kernel
  - *source:* kernel/include/kickos/cap.h (CapType); kernel/irq/irq.cc (irq_claim, irq_wait, irq_ack, irq_notify, irq_ref_drop); kernel/syscall/cap.cc (the CAP_IRQ arms of obj_ref_inc / obj_ref_drop / obj_close_protocol / cap_resolve_e); kernel/syscall/syscall.cc (the KOS_SYS_IRQ_CLAIM authority gate); docs/design-m4.6-irq-driver.md section 2

- **`isr-mask-then-wake-wait-rearm`** -- The first-level ISR must mask the line (so it cannot re-fire while its driver services it in thread context) then post the bound notification. The line is re-armed (unmasked) by the driver's NEXT irq_wait, which auto-re-arms the previously-consumed line before blocking -- so a `wait; service` loop alone keeps receiving IRQs (no forgot-to-ack deadlock). Calling irq_wait asserts the previous event was fully serviced (e.g. device W1C done) before the auto-re-arm unmask -- the same service-before-unmask ordering the explicit ack used to carry. irq_ack stays OPTIONAL and idempotent: an early re-arm that only reacts sooner to a still-pending latch -- a raise on a masked line is latched one-deep and redelivered at the next unmask, so neither the ack nor the early re-arm is load-bearing for keeping the event (the latch-and-coalesce contract carries it either way); a double ack, or an ack after the next wait already re-armed, is a no-op. The per-binding needs_rearm flag is set when irq_wait RETURNS (event consumed) -- NEVER in the ISR (ISR-set races the ack;compute;wait unmask -> phantom wake -> empty-FIFO read). **A claim does NOT arm the line**: needs_rearm starts TRUE and the FIRST irq_wait arms it, in the thread that will consume the event, so no window exists in which a line is armed while its owner is not yet running. Two consequences for callers. The first arm ALWAYS discards the pending latch first, whatever the trigger type -- a raise landed before the line had an owner is pre-claim garbage that would otherwise phantom-wake the first wait -- and a LEVEL binding keeps discarding on every rearm, after the driver's own device clear. And a parent that claims a line, delegates it, and then injects onto it must ARM it first (its own ack does), because the delegated child may not have reached its first wait yet and that first arm would discard the raise. The ISR handler runs by index with its arg being the pre-bound binding -- no table search on the hot path (latency invariant).
  - *applies:* IRQ dispatch, ISR wakes pre-bound target; kernel + all arches
  - *source:* kernel/irq/irq.cc (irq_event_isr, rearm_locked, irq_wait, irq_ack); kernel/include/kickos/irq.h (IrqBinding, IrqTrigger); arch/include/kickos/arch/arch.h (the latch-and-coalesce contract above arch_irq_mask); arch/sim/sim.cc (arch_irq_unmask)

- **`line-masking-owned-by-handler`** -- A bound IRQ line must re-deliver on every fire; masking policy is owned by the handler tier, NOT the arch first-level / doorbell dispatcher, which only demuxes the physical source and calls kickos_isr_irq(line). A tier-1 (IRQ-as-event) binding masks on entry (irq_event_isr) and re-arms (unmasks) on the driver's next irq_wait, or earlier via the optional irq_ack; a tier-2 (irq_attach) binding has no re-arm path, so any masking the arch dispatcher imposes strands it -- the line dies after one delivery and later injects are dropped. End-property, not code shape: an arch's dispatcher must not add masking its handler tier never undoes (the xtensa doorbell once did, and a tier-2 waiter hung).
  - *applies:* IRQ dispatch; software-doorbell backends: sim, rv32imac, rxv3, xtensa
  - *source:* kernel/irq/irq.cc (irq_event_isr masks; irq_wait auto-re-arms, irq_ack optional early re-arm); arch/xtensa/lx6/arch_xtensa.cc, arch/riscv/rv32imac/arch_rv32imac.cc, arch/rx/rxv3/arch_rxv3.cc, arch/sim/sim.cc (doorbell dispatchers: demux + deliver only)

## Console

- **`console-single-producer`** -- The buffered console ring is a strict single-producer/single-consumer: the buffered path (arch_console_write) is entered ONLY from thread context with the ring armed and not panicking; ISR context, fault context, panic, and pre-arm boot all fall back to the bounded polled writer (arch_console_write_sync). console_emit is the single routing chokepoint; any new path that logs from a raw ISR must not reach the buffered producer. console_emit consults the three-state ownership axis g_console_state (KERNEL_OWNED buffered/sync as above; USER_OWNED drops the chip path entirely -- RTT still carries it; RECLAIMED polled-only) BEFORE the buffered-vs-sync sub-decision. A device poke while KERNEL_OWNED brackets itself in the g_chip_writers count so kos_console_publish (which flips the state to USER_OWNED last) drains a stale racing writer off the device before returning; console_tx_write's disarm fallback re-reads the state and DROPS the poke unless still KERNEL_OWNED.
  - *applies:* console single-producer ring; kernel + buffered-console chips
  - *source:* kernel/init/console.cc (ConsoleState + g_chip_writers + console_emit, and kpanic_enter's reclaim wiring); kernel/init/console_tx.cc (console_tx_write's disarm re-check, console_tx_deinit); kernel/syscall/syscall.cc (KOS_SYS_CONSOLE_PUBLISH drain); lib/include/kickos/console_tx.h; docs/reference/console.md

- **`console-publish-prime-atomic`** -- The producer's 'copy burst, publish head, enable TX IRQ' must publish head and enable the IRQ together under IrqLock, atomic against the ISR's 'drain to empty, disable IRQ', so there is no lost wakeup; the TX IRQ stays enabled whenever the ring is non-empty and the ISR disables it only on empty. The TX ISR therefore MUST sit in the IrqLock-maskable device band and must never sem_post/switch/block.
  - *applies:* console single-producer ring, ISR band; kernel + buffered-console chips (mk64f, xmc4800)
  - *source:* kernel/init/console_tx.cc (console_tx_write's publish-and-prime, console_tx_isr); lib/include/kickos/console_tx.h (console_tx_backend, console_tx_write, console_tx_isr); docs/reference/console.md

- **`panic-console-probe-independent`** -- Panic/fault output must not depend on the buffered ring or on an external debug probe: kpanic_enter sets g_console_panicking, flushes queued bytes in order via console_tx_flush_sync, then prints through the polled synchronous writer and halts. kpanic_enter calls arch_console_reclaim() and flips the state to RECLAIMED from ANY prior state, not only USER_OWNED: the ownership axis tracks a PUBLISH, never whether the device is GARBLED, and a thread granted the console window can wreck the channel with no publish at all (KERNEL_OWNED). The gate is therefore `state != RECLAIMED`, and the RECLAIMED store happens BEFORE the call -- which makes the reclaim UNCONDITIONAL-ONCE, so a synchronous fault inside the reclaim body re-enters and stops rather than recursing with the old state (a pre-existing recursion hazard the widening closed), and a body that truncates the byte in the shift register cannot cut the banner it just printed. Every chip body must be IDEMPOTENT ABSOLUTE STORES for this to be safe on a device no driver ever touched -- that idempotence is the LOAD-BEARING justification for the widened gate, not an aside. WITNESSED on silicon (`user/apps/xmc4800-relax/conreclaim`, xmc4800-relax, `c5d9b0d`): a KERNEL_OWNED channel gated at `KSCFG.BPMODEN=1, MODEN=0` still delivered its `=== MPU FAULT ===` banner, where the pre-widening behaviour was nothing after the pre-scramble line. kickos_isr_fault funnels through kpanic_enter FIRST so a terminal fault in the userspace driver still reclaims and prints. M2 DEPENDENCY: only a TERMINAL fault exit may reclaim -- a kill-and-resume fault path must NOT, since the driver keeps the device and a dark report there is correct. The synchronous writer must remain a real transport (the fallback TU arch/common/arch_console_write_sync_default.cc aliases arch_console_write, which is correct ONLY on a polled-only chip; a buffered console MUST define its own), never RTT-only.
  - *applies:* console panic-sync; kernel + all chips
  - *source:* kernel/init/console.cc (g_console_panicking + console_emit's routing, kpanic_enter and its reclaim, the kickos_isr_fault funnel); arch/common/arch_console_reclaim_default.cc (the no-op fallback); docs/reference/console.md

## Telemetry

- **`telemetry-emit-atomic-one-lock`** -- Every telemetry emit must assign the sequence number, sample arch_trace_now(), encode, and write to the sink under ONE IrqLock; splitting them lets a preempting context interleave an out-of-order seq/stamp and silently corrupt the host's loss/latency accounting. records_attempted/dropped are RMW under that same lock.
  - *applies:* telemetry record framing; kernel (all arches)
  - *source:* kernel/include/kickos/ktrace.h (ktrace_detail::put and the ktrace_switch / ktrace_syscall_enter / ktrace_syscall_exit / ktrace_irq_enter / ktrace_irq_exit emitters); docs/reference/telemetry.md

- **`telemetry-record-atomic-drop`** -- The telemetry sink is whole-record-or-drop: the ch1 ring checks free space for all n bytes up front and drops the entire record if it won't fit (a half-written binary record would desync the decoder permanently). Records are fixed-length, little-endian, self-delimiting; type tags are nonzero so a zeroed buffer never decodes as valid. One slot is reserved so head==tail is unambiguously empty.
  - *applies:* telemetry record framing, sink; lib/rtt + record.h (all arches)
  - *source:* lib/rtt.cc (kickos_rtt_write_record_ch1); include/kickos/trace/record.h (EventType, TRACE_MAX_RECORD, record_len, the encode_* helpers); docs/reference/telemetry.md

- **`switch-record-from-physical-contexts`** -- The SWITCH {from_tid,to_tid} record must be emitted from the tids read out of the two contexts that PHYSICALLY swapped, never by re-reading g_arch_next or shared scheduler state (a preempting ISR can rewrite the decision between switch_to and the physical swap). trace_tid is stamped once at thread_create and read at the pinned ctx offset; from_tid==0xFFFF on the first switch; multiple wakes in one ISR collapse to exactly one SWITCH record.
  - *applies:* telemetry, context switch; armv7m, armv6m, rx, xtensa, sim
  - *source:* arch/include/kickos/arch/arch.h (arch_trace_stamp_id); arch/arm/armv7m/switch.S (PendSV_Handler's spilled outgoing ctx* and its kickos_trace_switch_done call); arch/sim/sim.cc (trace_switch_arm / trace_emit_switch_in, and isr_frame_leave's deferred swap site); kernel/thread/thread.cc (thread_create's arch_trace_stamp_id); docs/reference/telemetry.md

- **`telemetry-emit-fp-and-fault-free`** -- The context-switch telemetry emit runs in the PendSV/SWINT/L1 tail with the incoming thread's FP state live in registers, so its whole call path is built -mgeneral-regs-only and must touch NO FP register. Fault/NMI handlers must never call ktrace_* (they preempt the BASEPRI/PRIMASK lock and would issue records out of the atomic emit region).
  - *applies:* telemetry FP-register-free ISR paths; armv7m, rx, xtensa
  - *source:* kernel/ktrace/ktrace.cc (kickos_trace_switch_done, the TU built -mgeneral-regs-only); docs/reference/telemetry.md

- **`idle-is-trace-id-zero`** -- Idle must be the first thread created so it receives trace id 0 (the decoder keys CPU% off tid 0 == idle); kmain asserts g_idle_tcb.id==0. The per-Kernel tid counter starts at 0 and, on wrap, skips both 0 (idle-only) and 0xFFFF (the no-thread sentinel).
  - *applies:* telemetry framing, thread identity; kernel
  - *source:* kernel/thread/thread.cc (assign_thread_id); kernel/init/kmain.cc (the g_idle_tcb thread_create + the g_idle_tcb.id == KICKOS_TID_IDLE assert); kernel/include/kickos/thread.h (KICKOS_TID_IDLE / KICKOS_TID_NONE)

- **`telemetry-off-zero-cost`** -- With telemetry compiled out, every ktrace_* entry point is an empty inline (no symbols, hot paths byte-unchanged) and the ctx.trace_tid field and arch_trace_stamp_id seam are elided, so the telemetry-OFF struct layout and switch paths are byte-identical to a build that never had telemetry.
  - *applies:* telemetry; kernel + all arches
  - *source:* kernel/include/kickos/ktrace.h (the telemetry-off empty inlines); arch/arm/armv7m/include/kickos/arch/context.h (arch_context::trace_tid, elided with telemetry); arch/include/kickos/arch/arch.h (arch_trace_stamp_id)

- **`telemetry-gate-emission-only`** -- A `KICKOS_TELEMETRY` gate may contain ONLY record emission. Anything that changes signal/interrupt masking, ordering or object lifetime belongs OUTSIDE it: gate such code and the telemetry-OFF build silently loses a correctness property the telemetry-ON build has, which no gate catches because every emulated tree runs telemetry OFF. The sim's fresh-context IRQ-signal block and its matching trampoline unblock were gated this way, and the resulting context corruption reached CI as an intermittent `sim_stress` failure that no local run reproduced; `arch_shutdown`'s shutdown masking and console drain were gated the same way.
  - *applies:* telemetry conditional compilation; all arches, the sim especially
  - *source:* arch/sim/sim.cc (arch_context_init's sigaddset pair, the trampoline's sigprocmask, arch_shutdown's arch_irq_save and console drain)

- **`trace-clock-u32-anchored`** -- arch_trace_now() is a raw monotonic u32 counter that wraps (armv7m DWT CYCCNT, rx/xtensa cycle/CMTW counters, sim ns/1000 us); absolute time is reconstructed by the decoder from the two SESSION clock anchors (near at init, far at shutdown). A target with no such source must not define KICKOS_HAVE_TRACE_CLOCK and cannot enable telemetry. The closing SESSION + ch1 drain at shutdown must run with IRQs masked so no record lands after the records_attempted snapshot.
  - *applies:* telemetry trace clock, record framing; all arches
  - *source:* arch/include/kickos/arch/arch.h (arch_trace_now); arch/arm/armv7m/arch_trace_now_default.cc (the raw DWT CYCCNT read); arch/sim/sim.cc (arch_trace_now, and arch_shutdown's masked final drain); kernel/include/kickos/ktrace.h (ktrace_session, the two SESSION anchors)

## Scheduler & instance state

- **`instance-scoped-state-no-arch-crossing`** -- All kernel runtime bookkeeping (ready lists, current/idle, sleepq, object pools, IRQ table, telemetry counters) lives in the single Kernel instance reached only via kernel(); the sim arch backend keeps its own parallel SimInstance and never crosses the arch seam. Multiple instances co-reside in one host process, so no cross-cutting global may leak scheduler/telemetry state across emulated MCUs.
  - *applies:* instance scoping, arch seam; kernel + sim
  - *source:* kernel/include/kickos/instance.h (struct Kernel, kernel()); arch/sim/sim.cc (SimContext, SimInstance, sim())

- **`ready-bitmap-tracks-lists`** -- The priority ready bitmap bit p must be set iff ready[p] is non-empty: every push sets the bit, every remove that empties the list clears it. highest_prio() trusts the bitmap (31-clz) to pick the run list, and priority indexes both the ready[] array and a 1u<<prio shift -- so a stale bit or an out-of-range prio is an OOB read/UB.
  - *applies:* scheduler ready structure; kernel (FIFO/RR policy)
  - *source:* kernel/sched/policy_fifo_rr.cc (highest_prio, rq_push_back, rq_remove, policy_pick_next); kernel/syscall/syscall_thread.cc (thread_spawn's prio bounds check, the sole entry for a user-supplied priority)

- **`tcb-link-node-shared-ready-xor-wait`** -- A thread's intrusive `link` node is shared between the ready list and a wait queue (mutually exclusive membership), while timer-list membership uses the SEPARATE tnext link. A wait-queue block must detach_current from the ready list BEFORE pushing onto the wait queue (else it clobbers the links the ready removal needs); a timed wait may be on the timer list and a wait queue simultaneously only because they use different links. That dual membership is what forces the timer expiry to dispatch on `Thread::wait_kind` instead of waking unconditionally: a thread still linked through `link` must be unlinked from its wait queue BEFORE `sched::wake` reuses that node for the ready list, and the deadline must be cancelled at every unpark so the rendezvous and the expiry cannot both claim the same park.
  **The cancel belongs in `sched::wake` and NOWHERE else, because a pop is not an unpark.** `sched::wake` is the one funnel every real unpark reaches, so putting the cancel there makes an unpark that forgets it unwriteable: becoming ready IS that call. The tempting alternative -- cancelling in `wq_pop_highest`, `reply_donor_unpark` and `thread_kill`'s hand-unlink, the three places every unpark already funnelled through -- is WRONG for one case, and silently so. `endpoint_recv` pops a `CALL_SEND_WAIT` caller off an endpoint's `send_waiters` only to `reply_donor_park` it onto the server's `reply_waiters`: that is a PARK-TO-PARK MIGRATION, the thread never becomes ready, and a cancel there strips the single deadline a `KOS_SYS_CALL_TIMED` must keep across BOTH call phases. The failure is invisible to a fast-path test -- the caller simply parks forever in `CALL_REPLY_WAIT` whenever a server takes the request via the slow path -- so the arm that covers it must stage the SLOW path specifically (`call_timeout_reply`). The migration needs no re-arm: it moves the caller through `link` while the delta list uses `tnext`, so the armed deadline is untouched by construction.
  Two kinds are on NO list at all, `WAIT_JOIN` and `WAIT_LIVE_LAST`: the tag is the only thing that finds them, and `sched::exit_current` sweeps the thread pool for it at every exit. `WAIT_LIVE_LAST` carries no deadline by construction (`KOS_SYS_WAIT_LAST` takes none), so it must stay in the timer dispatch's `default: kpanic` arm -- a WaitKind reachable by the timer with no unwind of its own is exactly what that arm exists to catch.
  - *applies:* scheduler / sync queue membership; kernel
  - *source:* kernel/sync/sync.cc (wq_block, wq_pop_highest -- deliberately no cancel); kernel/sched/sched.cc (block_current; wake -- the sole ktime_deadline_cancel site; exit_current's WAIT_JOIN / WAIT_LIVE_LAST sweep); kernel/time/time.cc (ktime_deadline_arm, ktime_on_timer); kernel/syscall/syscall_ipc.cc (endpoint_send / endpoint_recv / endpoint_call timed parks, endpoint_wait_timeout); kernel/syscall/syscall_thread.cc (thread_join's queue-less park); kernel/include/kickos/thread.h (Thread::tnext, Thread::wait_kind)

- **`abandoned-reply-cap-cannot-reach-a-later-call`** -- A `KOS_SYS_CALL_TIMED` that expires in `CALL_REPLY_WAIT` leaves its server holding a live one-shot `CAP_REPLY`, because reclaiming an entry from another thread's table would cross a containment boundary. That cap is a DANGLING NAME for a thread that is still running, and `cap_reply_caller` is what must refuse it: index, generation, `BLOCKED`, `CALL_REPLY_WAIT` and the packed `call_seq` low byte. Four of those five come back TRUE the moment the caller makes another call, and the fifth is only 8 bits wide (`KCAP_REPLY_SEQ_BITS`), so it aliases every 256 calls -- at which point a stale resolve names a thread mid-transaction with someone else. What must stop it there is that the caller is parked on the OTHER server's `reply_waiters`: `reply_donor_unpark` returns FALSE when its unlink finds nothing, and both `endpoint_reply` and the `CAP_REPLY` close arm must treat that as "the caller is gone" -- consume the cap, answer `-KOS_ESRCH`/EPIPE-nothing, and touch NEITHER the caller's `wait_result`, NOR its `call_state`, NOR its `link`, which belongs to that other server's list. The unlink therefore DECIDES and must precede every other write. Getting it wrong is silent and cross-thread: the reply copies its bytes into a buffer belonging to a transaction it has no part in and wakes a thread that is still linked elsewhere, corrupting that list. The expiry unwind additionally rolls `call_seq`, which moves the aliasing call by one and is defence in depth rather than the guard: at `KICKOS_CAP_REPLY_MAX == 1` a server holding an abandoned cap can mint no second one, so the caller's live transaction is ALWAYS on a different server and the unlink is the test that fires. Coverage has to drive the caller through the full sequence period to reach it at all -- an arm that merely makes one further call is refused on the sequence and never consults the guard.
  - *applies:* call/reply capability lifetime; kernel
  - *source:* kernel/sync/sync.cc (reply_donor_unpark's bool); kernel/syscall/syscall_ipc.cc (endpoint_reply, endpoint_wait_timeout's WAIT_EP_REPLY arm and its call_seq roll); kernel/syscall/cap.cc (cap_reply_caller, the CAP_REPLY close arm); user/apps/common/selftest/main.cc (t_reply_abandoned_cap, t_reply_stale_caller)

- **`join-accepts-the-unreclaimed-exit`** -- The thread pool's per-slot generation bumps at RECLAIM (`ThreadPool::alloc`) and NOT at exit, so a handle to a thread that has EXITED but whose slot has not yet been reused still gen-matches and still resolves. Every syscall resolving a thread BY HANDLE must therefore decide that state deliberately, and the two in tree decide it OPPOSITE ways: `KOS_SYS_THREAD_KILL` refuses it `-KOS_EBADF`, there being nothing left to cancel, while `KOS_SYS_THREAD_JOIN` ACCEPTS it and returns 0, because "the target is gone" is precisely what a joiner asked. Getting join's half backwards fails SILENTLY rather than loudly: the joiner parks on a thread whose exit sweep has already run, so it hangs until its deadline or forever. That is why the coverage joins the SAME handle a second time, bounded, immediately after the first join returned and before any spawn can reclaim the slot -- 0 is the pass, `-KOS_ETIMEDOUT` means the state was read as "still running" and `-KOS_EBADF` means it was read as stale. Both joins answer 0, so an arm that reads only the return value cannot say which path either took: the first join is therefore TIMED against a target that sleeps before exiting, and must last at least that sleep, while the second must not -- without those two bounds a target that had already exited would satisfy the whole arm through the early return and the parked path would go untested. `ThreadPool::release` is the third reader of the rule: undoing a claim on a reclaimed EXITED slot reverts the generation bump `alloc` made, precisely so the prior occupant's join-by-handle keeps resolving. Only a REUSE invalidates the handle.
  - *applies:* thread handles; kernel
  - *source:* kernel/include/kickos/thread.h (ThreadPool::alloc, ThreadPool::release, the generation-timing note); kernel/syscall/syscall_thread.cc (thread_resolve and its two callers); user/apps/common/selftest/main.cc (t_thread_join)

- **`sem-post-direct-handoff`** -- Semaphore wakeups are a direct token hand-off: sem_post wakes the highest-priority waiter (FIFO among equals) and does NOT increment count; the woken waiter returns from sem_wait without decrementing. Count is incremented only when there is no waiter. Breaking this double-counts or loses a token.
  - *applies:* synchronization primitives; kernel
  - *source:* kernel/sync/sync.cc (sem_post, sem_wait, sem_trywait)

## App entry & init seam

- **`app-entry-via-init-seam`** -- The kernel's root thread calls exactly one seam symbol `kickos_init_entry(argc, argv)` (`<kickos/sys/init.h>`) once kernel init is complete; the app's `main` is NOT itself pid-1. The provider of that symbol is a build-time-selected CMake target (cache var `KICKOS_INIT_PROVIDER`, default `kickos_default_init`, a `kickos_system` service that passes through `kickos_init_entry -> kickos_default_init_run -> kickos_app_main`). Low barrier is preserved: a plain app writes only `int main` and no manifest; a power user names their own provider target and may delegate to `kickos_default_init_run` to reuse the app-main body.
  - *applies:* boot/init, dependency inversion; kernel + build system + kickos_system
  - *source:* kernel/init/kmain.cc (root_entry -> kickos_init_entry); system/init/common/default_init_entry.cc; system/init/common/default_init_run.cc; system/include/kickos/sys/init.h; CMakeLists.txt (the KICKOS_INIT_PROVIDER block)

- **`init-return-is-shutdown`** -- RETURNING from `kickos_init_entry` is a single-shot system shutdown with that int status: root_entry calls the `kos_shutdown` SYSCALL, which reaches `kickos_terminate` -- drain the buffered console (`console_tx_flush_sync`), then `arch_shutdown(status)`. A persistent init must NEVER return (it parks or loops) -- running off its end shuts the whole system down. The shutdown is a gated syscall, not an unconditional call: it needs `AUTH_SYSTEM`, so a root that has narrowed that bit away (`authority-word-narrows-only`) is REFUSED `-KOS_EPERM`, and root_entry then panics `"root: shutdown refused"` rather than running on. That panic MUST route through the `KOS_SYS_PANIC` syscall (`kos_panic`) and never call `kpanic` directly: root is unprivileged (`root-unprivileged-idle-alone-privileged`) and `kpanic` masks IRQs and reads kernel `.bss`, so a call from root's own frame faults on the panic path itself and LOSES the diagnostic -- measured faulting three ways before the syscall existed. An app whose main returns must therefore keep `AUTH_SYSTEM`; the failure is loud, which is why the bit is not forced back on. **EXITING from `kickos_init_entry` is the same shutdown**, and for the same reason: `KOS_SYS_EXIT` issued by root (`every-syscall-caller-holds-a-pool-slot` (3) is how it is recognised) takes the `kickos_terminate` path with the code unchanged, so plain C `exit()`, `abort()` and a failed `assert` from main end the system with children still alive. Ending the system is a right root holds, so it is the same `AUTH_SYSTEM` gate, but the refusal cannot be REPORTED: `kos_exit` is `noreturn` and `_exit` spins after it, so a returned `-KOS_EPERM` would loop root forever with nothing on the wire, and the arm panics `"root: exit shutdown refused"` instead. That panic calls `kpanic` and not `kos_panic`, unlike root_entry's: the syscall arm already runs privileged in the kernel. What the arm protects is that root's slot never reaches `EXITED`, which the pool shape depends on: `KICKOS_THREAD_SLOTS` is one wider than `KICKOS_MAX_THREADS` on exactly that basis (porting.md), the domain and demand-stack budgets with it, and `ThreadPool::alloc`'s reclaim sweep would clear the `spawner_tag` of every child root had spawned, leaving them permanently uncancellable.
  - *applies:* boot/init lifecycle; kernel
  - *source:* kernel/init/kmain.cc (root_entry's tail: kos_shutdown, then kos_panic on refusal); kernel/init/console.cc (kickos_terminate: console_tx_flush_sync then arch_shutdown); kernel/syscall/syscall.cc (the KOS_SYS_SHUTDOWN and KOS_SYS_EXIT arms, both AUTH_SYSTEM-gated for root); user/src/newlib_stubs.cc (_exit -> kos_exit); system/include/kickos/sys/init.h

- **`ctors-run-before-init-entry`** -- App / libstdc++ / library global constructors run in the kernel root thread (kernel live, thread context so a ctor may issue a syscall like kos_clock_now) BEFORE `kickos_init_entry` is entered -- the normal C++ order. A custom init must not assume its own bring-up precedes those ctors. Every target STATES its app-ctor window: `__kickos_app_init_array_{start,end}` is a STRONG reference, defined by each chip linker script around its `.kickos_app_init_array` bucket and by `arch/sim/start.cc` as a deliberately EMPTY window (a hosted ELF's own runtime has already run the ctors before `main`, so walking them again would double-construct). EMPTY and ABSENT are therefore distinct at LINK time, which is the point: present-but-empty leaves `start == end` so the walk iterates zero times, silently; a script that omits the bucket fails the link with an undefined symbol. These bounds were once WEAK, which collapsed absent into a null the walk skipped -- that is how a monolithic `.init_array` could run every app ctor privileged from the reset handler AND skip the late walk entirely with no diagnostic.
  - *applies:* boot/init ordering, C++ ctors; kernel + all chips + hosted sim
  - *source:* kernel/init/kmain.cc (the __kickos_app_init_array_start / __kickos_app_init_array_end declarations, and root_entry's walk ahead of kickos_init_entry); arch/sim/start.cc (the empty .kickos_app_init_array window)

- **`init-provider-fail-loud`** -- Exactly one target supplies `kickos_init_entry`, chosen by `KICKOS_INIT_PROVIDER`; a missing/unknown provider is a CMake FATAL_ERROR (checked late so a provider defined in user/apps is not false-tripped), never a silent fallback and never a weak symbol. The default provider's entry and run body live in DISTINCT TUs so a delegating override referencing only the run body does not drag in a second `kickos_init_entry`. An installed package freezes the provider it was built with and rejects a consumer override.
  - *applies:* build, entry seam; build system + kickos_system + installed package
  - *source:* CMakeLists.txt (the KICKOS_INIT_PROVIDER cache variable, its link group, and the late not-a-target FATAL_ERROR); system/CMakeLists.txt (the default provider's TUs); cmake/KickOSConfig.cmake.in (the frozen-provider FATAL_ERROR)
