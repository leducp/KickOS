# KickOS invariants

> Reference (code-synced). The cross-cutting properties a change must not break,
> extracted by the M1.x close-out review across the arch seam, kernel, per-arch
> backends, and docs. Each is a *checklist item* for future milestones (M2 above
> all): re-audit the whole arch/chip/board matrix against these, hunting both
> drift (one arch violates what the others uphold) and absence (a backend that
> forgot one). `source` cites where it lives in the code.
>
> **Cite symbols, not line numbers.** A `file:start-end` range is wrong the moment
> anything above it moves, and it fails silently -- the range still resolves, just
> to the wrong code. Several citations here pointed into `syscall.cc` at lines that
> no longer existed after the per-domain split (`syscall_thread.cc`,
> `syscall_ipc.cc`, `syscall_obj.cc`, `syscall_mem.cc`). Prefer
> `file (symbol / the thing it guards)`; keep a line range only for a fixed asm
> frame or a struct-offset pin, where the line IS the fact.
>
> The per-arch `applies:` lists below name armv7m / armv6m / rx / xtensa. The
> **rv32imac** (RISC-V: ESP32-C6 + QEMU `virt`) port implements the same
> context-switch, critical-section (`mstatus.MIE`), deferred-switch (CLINT `msip`),
> tickless-timer, and telemetry (`rdcycle`) contracts and must be audited alongside
> them; its FP-save invariants are N/A (soft-float, no FP register file). Treat a
> missing rv32imac mention in a specific item as "audit it too", not "exempt".

## Context switch & FP save/restore

- **`switch-frame-matches-init`** -- The frame fabricated by arch_context_init must be byte-identical to what the context-switch save path pushes/pops (same order, same slots), and the arch_context field offsets the asm hard-codes (sp@0, npriv@4, resting_npriv@8, trace_tid@12 on armv7m; sp@0/trace_tid@4 on rx; sp/ps/pc/resume_kind/trace_tid on xtensa) must stay pinned by static_assert. A silent struct reorder or frame-layout drift corrupts the saved SP/privilege on the first switch-in.
  - *applies:* context switch; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc:24-31; arch/arm/armv7m/switch.S:11-18,134-151; arch/rx/rxv3/arch_rxv3.cc:34-38,144-204; arch/xtensa/lx6/arch_xtensa.cc:31-39,187-213

- **`npriv-banked-on-switch`** -- CONTROL.nPRIV is saved and restored per switch as if it were a register (ctx.npriv), NOT reset to the thread's resting posture: a thread blocked mid-syscall runs privileged (the SVC trampoline raised it) and must resume privileged. arch_context_init seeds ctx.npriv AND ctx.resting_npriv from the thread's resting privilege.
  - *applies:* context switch + privilege; armv7m, armv6m (rx uses banked PSW.PM the same way)
  - *source:* arch/arm/armv7m/include/kickos/arch/context.h:24-37; arch/arm/armv7m/switch.S:59-77; arch/arm/armv7m/arch_armv7m.cc:152-161

- **`fp-armv7m-lazy-frame`** -- On an FPU-equipped ARMv7-M part the extended FP state is saved/restored conditionally on EXC_RETURN bit4: PendSV must vstmdb {s16-s31} BEFORE stmdb {r4-r11,lr} (higher addresses) on save and vldmia AFTER the callee pop on restore, so a thread with no live FP context carries no FP frame. Breaking the bit4 test or the push/pop ordering corrupts FP state across a switch.
  - *applies:* context switch, FP save/restore; armv7m with __ARM_FP
  - *source:* arch/arm/armv7m/switch.S:52-72

- **`fp-rx-full-context`** -- The RX SWINT switcher saves the full context each switch: R1-R15 (single-precision FP lives in the GPR file), FPSW, both accumulators, and -- under -mdfpu -- the DPFPU file (DR0-DR15 + DPSW/DCMR/DECNT via DPUSHM/DPOPM); arch_context_init fabricates exactly those slots with the DPFPU reset posture (DPSW=0x100, DECNT=1). Dropping -mdfpu must leave the slots carrying zeroes, not desync the frame.
  - *applies:* context switch, FP save/restore; rxv3 (rx72m)
  - *source:* arch/rx/rxv3/arch_rxv3.cc:20-38,158-201

- **`fp-xtensa-caller-saved`** -- On LX6 CPENABLE is global (CP0 enabled for all threads), so FP data registers are NOT banked by that enable. The cooperative (thread-context) switch relies on the compiler spilling caller-saved FP regs; only the preemptive level-1 interrupt frame saves f0-f15+FCR+FSR. A change that assumes the cooperative path saves FP registers is wrong.
  - *applies:* context switch, FP save/restore; xtensa lx6 (esp32)
  - *source:* arch/xtensa/lx6/arch_xtensa.cc:443-454

## Critical section & interrupt-priority bands

- **`irqlock-nesting-safe`** -- IrqLock must record the prior interrupt-mask state and restore exactly that on scope exit (never unconditionally unmask), so nested critical sections compose. Every arch's arch_irq_save/restore returns/consumes the full prior state (BASEPRI word, PSW.IPL field, PS, or the sim's SIGALRM/SIGUSR1 unblocked flags).
  - *applies:* critical section / IrqLock; all arches
  - *source:* kernel/include/kickos/irqlock.h:14-32; arch/arm/armv7m/arch_armv7m.cc:164-181; arch/rx/rxv3/arch_rxv3.cc:207-228; arch/xtensa/lx6/arch_xtensa.cc:233-245; arch/sim/sim.cc:526-559

- **`basepri-write-needs-barrier`** -- On ARMv7-M, raising BASEPRI is not self-synchronizing: arch_irq_save must follow the msr with DSB+ISB, else an interrupt can still be taken under the old mask on the next instruction and preempt a critical section. (RX MVTIPL and Xtensa RSIL are self-synchronizing and correctly omit the dance.)
  - *applies:* critical section; armv7m
  - *source:* arch/arm/armv7m/arch_armv7m.cc:164-176; arch/rx/rxv3/arch_rxv3.cc:207-216

- **`device-irq-in-maskable-band`** -- A device IRQ line's priority MUST be programmed into the IrqLock-maskable band BEFORE the line is enabled, or an IRQ can preempt an IrqLock-held section and corrupt kernel state. Bands: armv7m PRIO_DEVICE=0x30 >= lock 0x20; rx IPL_DEVICE=4 < IPL_LOCK=12; xtensa masks levels 1-3. NVIC IPR / ICU IPR reset to 0 (highest), so the write is mandatory, not optional.
  - *applies:* ISR priority bands; armv7m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc:203-216; arch/arm/armv7m/regs.h:41-50; arch/rx/rxv3/arch_rxv3.cc:353-366; arch/rx/rxv3/regs.h:37-40; arch/xtensa/lx6/arch_xtensa.cc:56-58

- **`deferred-switch-lowest-band`** -- The deferred-switch mechanism (PendSV / RX SWINT / xtensa L1-exit) must sit at the lowest active priority AND below the IrqLock threshold, so a switch requested from an ISR fires only after every other exception tail-chains and only once the requesting critical section releases. armv7m PRIO_PENDSV=0xF0; rx IPL_PENDSW=1 (< IPL_LOCK=12).
  - *applies:* deferred-switch model, ISR bands; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/switch.S:26-29; arch/rx/rxv3/arch_rxv3.cc:429-436; arch/xtensa/lx6/arch_xtensa.cc:216-230

## Deferred switch & blocking model

- **`arch-switch-may-defer`** -- arch_switch MAY not complete synchronously (ARM/RX pend an exception, xtensa flags g_arch_switch_pending when in ISR); the scheduler must not assume the register swap has happened when arch_switch returns. The switch target crosses only through g_arch_next/g_arch_current -- PendSV saves g_arch_current and ignores the `from` argument.
  - *applies:* deferred-switch model; all arches
  - *source:* arch/include/kickos/arch/arch.h:44-48; arch/arm/common/arch_arm_common.cc:61-68; arch/xtensa/lx6/arch_xtensa.cc:216-230; docs/reference/architecture.md

- **`no-block-from-isr`** -- Blocking (sem_wait, sleep, any detach_current/block_current path) is legal ONLY from thread context: it relies on arch_switch completing synchronously. From ISR context the switch would defer and the 'blocked' thread would keep running, so detach_current panics when arch_in_isr() is true.
  - *applies:* deferred-switch model, sync primitives; kernel + all arches
  - *source:* kernel/sched/sched.cc:105-127; kernel/sync/sync.cc:37-48

- **`exit-parks-for-deferred-switch`** -- exit_current must not run off the end after committing the switch-away: on a deferring arch the PendSV/SWINT can only fire once the IrqLock releases, so the EXITED thread (off the ready set, never rescheduled) must park in an arch_idle_wait loop until the pended switch lands. Running past with the switch merely pending is a known-fixed bug class.
  - *applies:* deferred-switch model, thread exit; armv7m, armv6m, rx
  - *source:* kernel/sched/sched.cc:141-171

- **`arch-in-isr-truth`** -- arch_in_isr() must read true in ISR/handler context and false throughout syscall_dispatch and ordinary thread context. RX has no IPSR: its g_in_isr counter is bumped ONLY by the device-IRQ/timer first-level dispatchers, never by the syscall INT path, so dispatch reads false as the contract requires.
  - *applies:* deferred-switch model, syscall contract; all arches (rx software counter)
  - *source:* arch/include/kickos/arch/arch.h:62-63,123-142; arch/rx/rxv3/arch_rxv3.cc:59-62,230-233,400-417; arch/arm/common/arch_arm_common.cc:70-77

## Syscall, privilege & the user/kernel boundary

- **`syscall-in-priv-thread-context`** -- The arch MUST run syscall_dispatch() in privileged THREAD context on the calling thread's own continuation, never in handler/ISR context. A blocking syscall blocks by an ordinary synchronous context switch that freezes the mid-dispatch continuation on the caller's stack and resumes it inline when rescheduled. On ARM the SVC handler redirects to svc_trampoline (privileged thread mode); it does not dispatch inside the handler.
  - *applies:* syscall + privilege + resume-inline; armv7m, armv6m, rx (xtensa: plain call, trivially satisfied)
  - *source:* arch/include/kickos/arch/arch.h:123-142; arch/arm/armv7m/switch.S:111-159; arch/xtensa/lx6/arch_xtensa.cc:432-440; docs/reference/porting.md

- **`trap-return-atomic`** -- Trap/exception return must be atomic with respect to interrupts: no interrupt-takeable window may exist while the return-state (return PC + saved status/privilege) is staged but not yet consumed by the return instruction. Otherwise a nested trap overwrites the staged return PC and the outer return jumps back into its own epilogue at the caller's privilege with the frame half-restored. This is an end-property, not a code shape -- each arch satisfies it by its own mechanism, and a unique path still has to close the window: ARM's exception unstack is hardware-atomic and the syscall trampoline returns by ordinary `bx lr` (no return register live); RX pops PC+PSW in one `RTE`; xtensa sets `PS.EXCM=1` before writing `EPC1`; RISC-V restores `mstatus` (MIE=0) BEFORE `mepc` on the ecall-return path -- which alone reaches the restore with MIE=1, because `.Lecall` sets MPIE=1 to make `syscall_dispatch` interruptible.
  - *applies:* trap/syscall return, critical section; armv7m, armv6m, rx, xtensa, rv32imac
  - *source:* arch/riscv/rv32imac/switch.S (.Lrestore); arch/rx/rxv3/switch.S (RTE); arch/xtensa/chip/esp32/startup.S (PS.EXCM before EPC1); arch/arm/armv7m/switch.S (svc_trampoline `bx lr` + HW exception return)

- **`syscall-restores-resting-priv`** -- On syscall return the SVC trampoline must restore the caller's resting privilege (ctx.resting_npriv), NOT hard-code nPRIV=1: a privileged thread issuing a syscall must drop back to exactly its entry posture, never be demoted to unprivileged.
  - *applies:* syscall + privilege; armv7m, armv6m
  - *source:* arch/arm/armv7m/switch.S:142-159; arch/arm/armv6m/switch.S:117-127; arch/arm/armv7m/include/kickos/arch/context.h:33-37

- **`user-thread-return-via-syscall`** -- An unprivileged thread whose entry returns must route through kickos_user_thread_return (which traps out via the exit syscall); it must NOT run the kernel's kickos_thread_return directly, because exit_current with nPRIV=1 makes IrqLock/BASEPRI a no-op and the switch-path SCS write faults. arch_context_init selects the return address by privilege.
  - *applies:* syscall + privilege, thread exit; armv7m, armv6m, rx
  - *source:* arch/arm/armv7m/arch_armv7m.cc:46-53,124-131; arch/rx/rxv3/arch_rxv3.cc:64-70,164-172; kernel/thread/thread.cc:85-90

- **`privilege-escalation-gated`** -- Spawning a privileged thread must be gated on the CALLER being privileged (-KOS_EPERM otherwise), and that gate is deliberately a raw `Thread::privileged` test and not an authority bit (see `authority-cap-narrows-only`): a capability to create privileged children would be equivalent to holding every authority forever AND being able to hand that on, so narrowing it is meaningless and delegating it is unbounded escalation. There is therefore no path by which an unprivileged thread obtains privilege, and the privileged population cannot grow after boot. The acts that merely need authority are gated on the authority word instead -- irq_attach on `AUTH_IRQ`, ram_alloc on `AUTH_MEMORY` (rejecting with NULL, out of the -KOS_E* scheme, see `syscall-return-abi`) -- so an unprivileged holder passes those and the whole-arena grant stays unreachable regardless.
  - *applies:* user/kernel boundary, syscall; kernel (all arches)
  - *source:* kernel/syscall/syscall_thread.cc (thread_spawn's privileged-child check); kernel/syscall/syscall.cc (the KOS_SYS_IRQ_ATTACH and KOS_SYS_RAM_ALLOC dispatch arms)

- **`root-unprivileged-idle-alone-privileged`** -- Exactly ONE thread in the system is privileged, and it is `idle`. Root is unprivileged on EVERY board, unconditionally: `ThreadAttr::privileged` DEFAULTS to `false` (`kernel/include/kickos/thread.h`), `kmain` sets `root_attr.privileged = false` explicitly, and `idle_attr.privileged = true` is the only assignment of `true` left. There is no build knob, no preset and no porting escape hatch that restores a privileged root -- `KICKOS_ROOT_PRIVILEGED` was deleted, and the name now appears in NO code or build file AT ALL -- not a definition, not a reference, and not even a configure-time refusal (`grep` over `*.txt *.cmake *.h *.cc *.json *.in *.sh` returns nothing). The `FATAL_ERROR` that once refused a stale cache entry was itself deleted, so a stale `-DKICKOS_ROOT_PRIVILEGED=...` is now SILENTLY IGNORED on an in-tree and an out-of-tree configure alike, with nothing but CMake's generic unused-variable warning. (Docs still discuss the name historically, correctly, in many places -- "anywhere in the tree" would be too broad a claim. `master` still defaults the knob `ON`, which is why records taken there report a privileged root; a grep of `master` finds the knob live.) Combined with `privilege-escalation-gated` (the privileged population cannot GROW after boot) the privileged population is therefore fixed at one for the life of the system. **There is no demotion instant**: privilege is a property of the frame `arch_context_init` fabricates and of the region set `thread_create` composes from it, so root is unprivileged from its FIRST instruction -- no window exists in which root runs privileged and then drops. Two consequences a change must not break. (1) Root's `CAP_AUTHORITY` seat is UNCONDITIONAL (`authority-cap-narrows-only`): with no ring to short-circuit `cap_check_authority`, an unseated root would fail every authority gate including its own shutdown. (2) The kernel must never call a kernel-internal function that masks IRQs or touches kernel `.bss` from root's frame -- it faults there and LOSES the diagnostic. That is why returning from `main` panics THROUGH the `KOS_SYS_PANIC` syscall trap and never calls `kpanic` directly, and why the ungated `kos_panic` exists at all. A test asserting anything about a privileged CALLER is unwritable by construction: `idle` runs no tests, which is why `mpu_privileged_guard` was retired rather than fixed, and `user/apps/common/rootfault` makes the stronger claim instead (root TRAPS on a cross-domain write) on every `KICKOS_HAVE_MPU` image.
  - *applies:* kernel init, syscall, user/kernel boundary; kernel (all arches), every board
  - *source:* kernel/init/kmain.cc (idle_attr/root_attr privilege + the unconditional cap_seat_authority); kernel/include/kickos/thread.h (ThreadAttr::privileged default); kernel/syscall/syscall.cc (the KOS_SYS_PANIC arm and its noinline message-buffer helper); user/apps/common/rootfault

- **`user-args-validated-at-boundary`** -- Every user-supplied scalar must be range-checked or clamped at the syscall boundary before use, and an invalid one returns a negative -KOS_E* code (never panics): priority is bounds-checked before it indexes ready lists / shifts a 1u<<prio bitmap; console len is clamped to 4096; injected/attached IRQ lines are checked against [0,KICKOS_MAX_IRQ); an unknown syscall number returns -KOS_EINVAL. The MPU does NOT make this optional now that it enforces. `syscall_dispatch` runs PRIVILEGED, so it is on the wrong side of the very boundary the MPU checks: an unvalidated scalar becomes an out-of-bounds access by the KERNEL, which the region set permits by construction. Enforcement contains a bad *user* pointer only where it exists: with `KICKOS_HAVE_MPU=0` -- the DEFAULT of every hardware board -- there is no region set to check against, so `user_readable_ok` / `user_writable_ok` fall through to `arch_user_text_readable` / `arch_user_data_writable`, whose non-enforcing arm must be a WHITELIST of the chip's linker-defined memories (code/rodata extent, and static RAM up to the arena base -- `__kickos_rom_start/_end`, `__kickos_sram_start`, all STRONG references -- absent from `tests/weak_allowlist.txt` on purpose -- so a chip that omits them fails the LINK). Admitting "anything outside the arena" instead let an unmapped address through and HARD-FAULTED the kernel inside `kaccess_from_user` (MEASURED on mps2-an386 and mps2-an505: `kos_panic((char const*)0xCCCCCCC0)`, `BFAR=0xccccccc0`). Only these checks contain a bad user *index*.
  - *applies:* user/kernel boundary; kernel (all arches)
  - *source:* kernel/syscall/syscall.cc (KOS_SYS_KCONSOLE_WRITE len clamp; the KICKOS_MAX_IRQ checks on inject/unmask/attach; the dispatch `default:` -KOS_EINVAL); kernel/syscall/syscall_thread.cc (thread_spawn prio bounds vs KICKOS_PRIO_MIN/MAX); kernel/syscall/syscall_mem.cc (user_range_ok / user_readable_ok / user_writable_ok); arch/common/arch_ram_common.cc (arch_user_text_readable / arch_user_data_writable, the non-enforcing whitelist); user/apps/common/panicgate (the wire gate: message, null, wild, oversized)

- **`syscall-return-abi`** -- A syscall that can fail returns its error as the NEGATED code -KOS_Exxx (`system/include/kickos/sys/errno.h`); a success -- a handle, a count, or a byte-count -- is NON-NEGATIVE, so `rc < 0` is unambiguously an error and never aliases a valid handle/count. Magnitudes mirror POSIX errno (EPERM/EBADF/EINVAL/EFAULT/ENOMEM/EPIPE/EDEADLK/EBUSY); the sign is applied at the return site (there is no positive success-variant). EOWNERDEAD is the robust-mutex case: a mutex ACQUIRED while its prior owner died holding it is still returned negative (-KOS_EOWNERDEAD), which a caller must special-case as HELD. Two syscalls stay OUT of the scheme by return type: ram_alloc returns a pointer (every failure is NULL -- a negated errno cast to a pointer would be non-NULL) and cpu_clock_hz/cpu_clock_set return a u32 Hz whose 0 already means unknown/no-silicon-clock.
  - *applies:* user/kernel boundary, syscall ABI; kernel (all arches) + userspace wrappers
  - *source:* system/include/kickos/sys/errno.h; kernel/syscall/syscall.cc (every dispatch return site) + the per-domain implementations it calls (syscall_thread.cc, syscall_ipc.cc, syscall_obj.cc, syscall_mem.cc)

- **`handle-not-pointer-across-boundary`** -- No kernel pointer crosses the user/kernel boundary: kernel objects (semaphores, threads, IRQ bindings) are named by small integer handles resolved through a single validate-and-resolve chokepoint. Semaphore access migrated to per-task capabilities at M3 (see `object-access-via-per-task-cap`); thread and IRQ-binding handles still pack index+generation, and the freeing path bumps the slot generation so a stale handle fails to resolve rather than aliasing a recycled slot (ABA). The kernel must never strlen a user pointer (kconsole_write takes explicit buf,len).
  - *applies:* user/kernel boundary; kernel (all arches)
  - *source:* kernel/syscall/syscall.cc (the KOS_SYS_KCONSOLE_WRITE buf,len arm); kernel/syscall/cap.cc (cap_resolve); kernel/include/kickos/instance.h (the generational slot pools)

- **`object-access-via-per-task-cap`** -- A userspace-named kernel object (semaphore, PI mutex, or IPC endpoint) is reached ONLY through a per-task capability, never a global id: KOS_SYS_SEM_WAIT/SEM_POST (and the mutex/endpoint send/recv syscalls) take a cap handle, and cap_resolve validates index/liveness/type/rights then WRAPs to the global object pool -- two generations guard it, the per-task cap-gen (use-after-close) then the object's own object-gen (use-after-destroy), both u16. Resolve-and-use run under ONE continuous IrqLock, so a concurrent handle_close cannot free the object between resolve and use. An ISR NEVER resolves a cap: irq_attach resolves once (requires CAP_SIGNAL) and stores the GLOBAL object handle, which irq_sem_post re-resolves from the pool per fire (current() in ISR context is a random interrupted thread's table). B1 placement contract: a freshly spawned child table is all-CAP_EMPTY with cap-gen 0, so handle == index on a fresh table; a spawn-delegated cap i lands at child index i+1 (index 0 reserved), rights narrowed subset-only (child.rights = parent.rights & mask, never widened, requires CAP_TRANSFER), and the whole caps list is validated before the child slot is claimed. Cap handles are opaque, and the old global sem id is gone. The NAME `kos_sem_destroy` survives as a source-compatibility alias of `kos_handle_close` (`user/include/kickos/sys.h`) -- so it no longer means "destroy this semaphore" but "drop MY cap", and the object outlives the call whenever another holder remains. Rights are enforced at cap_resolve alone; memory R/W/X stays in the MPU descriptor, not the cap.
  - *applies:* user/kernel boundary, capability object model; kernel (all arches)
  - *source:* kernel/include/kickos/cap.h; kernel/syscall/cap.cc (cap_resolve/handle_close/cap_teardown); kernel/syscall/syscall.cc (the KOS_SYS_SEM_*/MUTEX_* dispatch arms); kernel/syscall/syscall_ipc.cc (endpoint_send/recv/call/reply); kernel/syscall/syscall_thread.cc (thread_spawn's B1 delegation); kernel/sched/sched.cc (cap_teardown on exit)

- **`own-create-skips-reserved-cap-index`** -- The well-known cap indices [0 .. KICKOS_CAP_FIRST_DYNAMIC) (today [0..4); index 0 = KOS_CAP_STDOUT) are FROZEN reserved slots (`system/include/kickos/sys/cap_index.h`). An own-create (sem/mutex/endpoint create) scans placement from KICKOS_CAP_FIRST_DYNAMIC (cap_install), so it can NEVER land on -- and alias -- a reserved index. A reserved slot is written ONLY by the kernel (cap_install_defaults seats stdout and is the sole writer of index 0) or by explicit spawn delegation (delegated cap i lands at index i+1, filling 1..3); cap_install_at rejects index 0 outright. Never renumber a frozen entry; append by raising the last reserved index and KICKOS_CAP_FIRST_DYNAMIC together, the cap.h static_assert guaranteeing >=1 dynamic slot survives.
  - *applies:* user/kernel boundary, capability naming; kernel (all arches)
  - *source:* system/include/kickos/sys/cap_index.h; kernel/syscall/cap.cc (cap_install -- the placement scan from KICKOS_CAP_FIRST_DYNAMIC; cap_install_at -- rejects index 0; cap_install_defaults -- the sole writer of index 0)

- **`authority-cap-narrows-only`** -- Axis-3 authority is a VALUE in the capability table that only ever shrinks. Shape: the `CAP_AUTHORITY` entry at the reserved index KOS_CAP_AUTHORITY carries the `CapAuthority` word in `CapEntry.obj` and `rights` == 0 -- the two families are separate enums in separate fields, so neither constrains the other's numbering and nothing has to keep them disjoint. It is POOLLESS (no object, no refcount): resolve it by reading the slot and type-checking it (cap_check_authority reads index KOS_CAP_AUTHORITY directly; the kernel seats it, so there is no handle or cap-gen to match), NEVER via cap_resolve_e, which would chase the authority word as a pool handle. NON-DELEGABLE BY TYPE: thread_spawn's delegation copy takes `obj` and `type` verbatim, so it must refuse a CAP_AUTHORITY source with -KOS_EPERM AHEAD of the CAP_TRANSFER test -- the empty rights byte alone must not be relied on, because the word rides in the copied `obj` and would land as a forged seat at child index i+1 (index 2 is reachable whenever cap_count >= 2). Monotone in both directions: a spawn seats only bits the caller itself holds (cap_check_authority, else -KOS_EPERM; bits outside CAP_AUTH_ALL are -KOS_EINVAL) and KOS_SYS_CAP_NARROW applies `word &= mask`, which can only CLEAR -- narrowing to 0 must also clear the entry's TYPE, or cap_check_authority would read a zero word off a live entry. KOS_SYS_CAP_NARROW is deliberately UNGATED (an authority required in order to drop authorities could never be given up) and refuses any non-CAP_AUTHORITY cap with -KOS_EINVAL (an object cap's rights are not narrowable in place: dropping CAP_WAIT from an endpoint cap would need obj_close_protocol's recv_holders accounting). Every gate is a cap_check_authority call site and is true when the caller is privileged OR holds the bit, so a privileged caller passes regardless of its slot -- but `idle` is the only privileged thread (`root-unprivileged-idle-alone-privileged`) and it calls none of them, so in practice the BIT decides every gate. The kernel seats root's cap UNCONDITIONALLY, and the ordering is load-bearing twice: AFTER thread_create, which zeroes the cap table and would wipe the seat, and BEFORE sched::start, so the seat precedes root's first instruction. Root's slot is therefore always live and a narrow against it always resolves. -KOS_EBADF is still reachable and must still be tolerated, for a DIFFERENT reason than an unseated root: narrowing a slot to 0 also clears its TYPE, so a SECOND narrow finds CAP_EMPTY, cap_lookup returns nullptr, and the caller gets -KOS_EBADF on a slot it legitimately emptied itself.
  - *applies:* user/kernel boundary, capability authority model; kernel (all arches)
  - *source:* kernel/include/kickos/cap.h (CapAuthority, CapEntry, CAP_AUTH_ALL); kernel/syscall/cap.cc (cap_check_authority / cap_seat_authority / cap_narrow_authority); kernel/syscall/syscall_thread.cc (thread_spawn's authority validation + the CAP_AUTHORITY refusal in the delegation loop); kernel/syscall/syscall.cc (the KOS_SYS_CAP_NARROW arm + every cap_check_authority gate); kernel/init/kmain.cc (the unconditional root seat, ordered between thread_create and sched::start)

- **`privilege-only-boundary-m1`** -- The M1 posture: the user/kernel boundary was privilege-only (CONTROL.nPRIV / PSW.PM + SVC trap) with arch_mpu_apply a no-op on every MCU backend, so an unprivileged thread could read/write kernel memory. **SUPERSEDED at M2** (see below): the MCU backends now enforce -- K64F SYSMPU + XMC PMSA + RX72M MPU + ESP32-C6 PMP all proven on silicon (selftest under enforcement + a cross-domain mpu_fault trap on each; the C6 proof covers SRAM/domain isolation -- its peripheral APM open is a follow-on); xtensa/no-MPU parts stay privilege-only. Historical: code written before M2 must not assume isolation.
  - *applies:* user/kernel boundary, MPU; armv7m, armv6m, rx, xtensa (sim enforces via mprotect; xtensa has no per-task MPU)
  - *source:* superseded -- see `mpu-apply-on-every-switch-in` for the enforcing backends

- **`mpu-apply-on-every-switch-in`** -- The running thread's MPU region set must be (re)loaded on every switch-in and at first start, replacing the whole active set; region granting must be fail-closed (a region not a page-aligned/pow2 sub-range the backend can describe is skipped, never applied). Mechanism: `arch_mpu_apply` stashes the set at the switch decision; the arch/chip `kickos_arch_mpu_commit` programs the hardware from the switch epilogue after the physical swap (the deferred-commit seam, `../design-mpu-commit-deferred.md`). A privileged thread gets a permissive background (the whole arena / supervisor-all); an unprivileged thread gets only its explicit set (app code RX + app-data RW-NX + domain region(s) + its private stack). ENFORCED on MCU at M2: SYSMPU (K64F), PMSAv7/v6-M (XMC4800, STM32F411, i.MX RT1062, RP2040 -- the shared armv7m/armv6m PMSA backend), PMSAv8 (RP2350, its own base+limit/MAIR backend), PMP/NAPOT (RISC-V), RX MPU -- K64F/XMC/RX/C6/RP2040/RP2350/RT1062 proven on silicon; sim via mprotect. A chip declares itself enforcement-capable by shipping `arch/<family>/chip/<chip>/mpu.cmake`; KICKOS_HAVE_MPU=1 without one is a configure FATAL_ERROR, never a silent no-op. A chip MAY also declare thread-INVARIANT fixed regions (`kickos_arm_mpu_fixed`, programmed once into the LOW descriptor slots so per-thread grants in the high slots still override them) -- required on a speculating core, where an unbacked-but-Normal aperture stalls the core fault-lessly.
  - *applies:* context switch, MPU, user/kernel boundary; kernel + sim + the MCU MPU backends (M2)
  - *source:* kernel/sched/sched.cc:31-38,80-85; kernel/thread/thread.cc (region-set build); arch/arm/common/arch_arm_common.cc (arch_mpu_apply stash + kickos_arch_mpu_commit/kickos_arm_mpu_program, PMSA); arch/arm/chip/mk64f/chip_mk64f.cc (kickos_arch_mpu_commit, SYSMPU); arch/riscv/rv32imac/arch_rv32imac.cc (arch_mpu_apply stash + kickos_arch_mpu_commit, PMP); arch/rx/rxv3/arch_rxv3.cc (arch_mpu_apply stash + kickos_arch_mpu_commit, RX MPU); arch/sim/sim.cc (arch_mpu_apply mprotect)

- **`grant-refuses-kernel-reserved-blocks`** (Rule 7) -- The grant path MECHANICALLY refuses any MMIO/RAM grant that overlaps a kernel-owns-for-life block (timebase, IRQ controller, every access-permission controller -- the MPU/PMP twin AND any bus-side gate such as the K64F AIPS PACR pages or the ESP32-C6 HP_APM/HP_TEE -- clock/reset gates), binding EVERY granter including privileged ones (not "trust the granter"). grant_region_admissible (kernel/grant) refuses size-0/wrap, then any reserved-block overlap, then requires: a DEVICE grant be privileged + exactly one MPU descriptor (no rounding) + not a bit-band alias; a RAM grant satisfy the arch's region-admissibility predicate AND be confined to the user arena for EVERY caller (no privileged waiver). That predicate is `arch_ram_region_admissible` (arch/include/kickos/arch/arch.h), which is power-of-two size plus natural alignment where `arch_mpu_region_pow2()` is 1 (PMSAv7, PMP NAPOT) and a granule multiple of `arch_mpu_min_region()` where it is 0 (PMSAv8, SYSMPU, RX RXv3). It is deliberately NOT `arch_mpu_region_encodable`, which answers the same question for an MMIO window and on the sim admits EXACTLY ONE -- the published fake-register base at exactly `0x10000` (`privileged-write-seam-possession-and-allowlist`) -- and fail-closes on every other address and every other shape of that one. domain_for (kernel/domain) runs it at the region-commit chokepoint before allocating a domain slot; the thread_spawn caller-owned-stack path runs the same predicate and thread_create carries a backstop assert. Each enforcing chip MUST declare arch_reserved_blocks -- NO fallback TU on purpose, so a forgetful enforcing port fails to LINK (affirmative fail-closed). On a bit-band core (arch_bitband_present() != 0) the overlap test also covers each reserved block's word-per-bit alias image and a device grant into either alias window is refused. grant_reserved_validate asserts at boot that arena + app extents are reserved-disjoint. Under KICKOS_HAVE_MPU=0 the whole module is inline no-op stubs (admissible always true), so call sites are #if-free and pay zero flash.
  - *applies:* memory-domain grant, MMIO isolation, single-ownership; kernel (grant/domain) + enforcing MPU chips (M4)
  - *source:* kernel/include/kickos/grant.h; kernel/grant/grant.cc (grant_hits_reserved/grant_region_admissible/grant_reserved_validate); kernel/domain/domain.cc (domain_for); kernel/syscall/syscall_thread.cc (thread_spawn's stack_base / mem_base / MMIO grant paths) + kernel/syscall/syscall.cc (KOS_SYS_GRANT_PROBE); kernel/thread/thread.cc (thread_create backstop assert); kernel/init/kmain.cc (grant_reserved_validate at boot); arch/include/kickos/arch/arch.h (arch_reserved_blocks/arch_bitband_present)

- **`privileged-write-seam-possession-and-allowlist`** -- The seams that perform a privileged peripheral act on an unprivileged caller's behalf -- `arch_periph_enable` (`KOS_SYS_PERIPH_ENABLE`, the clock-ungate + bus-side unprotect for a block) and `arch_periph_reg_write` (`KOS_SYS_PERIPH_REG_WRITE`, one store to one register) -- are gated on POSSESSION, never on an authority bit. The predicate is `caller_holds_mmio_block(base)`: the caller must hold a LIVE region carrying `ARCH_MPU_DEV | ARCH_MPU_R | ARCH_MPU_W` whose base equals the requested base EXACTLY. Containment does NOT count, so a window covering several blocks is not a licence to act on a block it merely contains. A **privileged** caller short-circuits the walk and passes unconditionally, as in `cap_check_authority`; the only privileged thread in a running image is `idle`, which calls no syscalls. The register-write seam takes the STRONGER predicate `caller_holds_mmio_reg(base, offset)`: the region matched by the exact base must ALSO CONTAIN `[base + offset, +4)`. Without that span the possession check bounds nothing but the base -- a 32-byte window at a block's start reaches every register the chip table names anywhere in that block (MEASURED: a holder of 32 bytes at `0x40000000` passed the gate at offsets `0x40`, `0x1000` and `0x0FFFFFFF`). The offset must also be 4-ALIGNED and `base + offset` must not wrap; both are `-KOS_EINVAL`, refused ahead of possession because they are malformed requests rather than possession failures. Possession rather than a capability because where the silicon puts a block's controls inside the window, holding the window already carries the authority; a bit would be a second, forgeable name for the same fact. Failing the gate is `-KOS_EPERM`. **Possession must never become blanket write access to the block**, because that is precisely what the bus classification withholds -- so `arch_periph_reg_write`'s per-chip backend is an ALLOWLIST of exact `(base, offset)` pairs and anything it does not name is `-KOS_EINVAL`. A per-BLOCK entry would hand back exactly what the silicon refuses and turn the seam into a privilege-escalation primitive keyed on a grant. The granularity is therefore the REGISTER, never a range, and an absent entry is a DECISION, not an omission (`xmc4800`'s U0C0 has no entry because the kernel owns the console channel's baud and enable). **"One register" is not "only the authority the driver needs"**, so each entry ALSO carries a per-entry VALUE MASK: `(value & ~mask) != 0` is `-KOS_EINVAL`, REFUSED WHOLE and never trimmed, because a silently dropped configuration bit is the failure class the read-back exists to catch. On `xmc4800`, `CCR` grants `MODE[3:0] | RIEN | AIEN` -- 6 bits of 32, with `RIEN`/`AIEN` deliberate because `xmcssc` arms them last -- and withholds `TBIEN`, `HPCEN`, `PM`, `RSIEN`, `DLIEN`, `TSIEN` and `BRGIEN`; `FDR` grants `STEP | DM`, and `BRG` every writable field, where a mask withholds only read-only and reserved bits and so buys little. `static_assert`s pin each composed grant, so a field-mask edit cannot widen it silently. A tabled block must also be CLOCKED. The contract now REQUIRES it (`arch/include/kickos/arch/arch.h`), though no backend enforces it: a store into a clock-gated block faults INSIDE the privileged store and reaches `kfault_terminate`, i.e. whole-system death from one syscall -- an unprivileged caller's one-syscall system-kill primitive. Not live today only because `kickos_xmc_usic_init()` runs unconditionally from `arch_init` so USIC0 is never gated; a `U1C0`/`U2C0` entry (gated at reset behind `CGATCLR1`) would arm it. TWO backends exist in-tree: `xmc4800` (real MMIO) and the SIM, which assumes NO fixed host address: it tries FIVE candidate bases in order with `MAP_FIXED_NOREPLACE` (`0x40000000`, `0x100000000`, `0x400000000`, `0x10000000000`, `0x100000000000` -- 1 GiB to 16 TiB) and PUBLISHES whichever landed as the only base the seam and the encoder answer for, the grantable window being `0x10000` (64 KiB) inside a mapping twice that, so its allowlist can carry one entry OUTSIDE the grantable window to reproduce the containment hazard on the host. The sim one is what puts the MECHANISM under a CI gate -- allowlist match, mask compare, refuse-not-trim, containment, alignment and wrap are each mutation-proved. Two arms move the other way once the window is 64 KiB, and the retraction belongs here: `grant_reserved`'s `DEV_UNPRIVILEGED(0x40000000, 0x1000)` case is VACUOUS on the sim, because `arch_mpu_region_encodable` admits the published base at exactly `0x10000` and nothing else, so deleting the `AUTH_MEMORY` refusal it is meant to exercise leaves the same answer (the authority test runs first, encodability refuses the identical request anyway). Conversely the misaligned-offset and wrapping arms, vacuous EVERYWHERE while they ran from a holder (from one both answer `-KOS_EINVAL` regardless), now DISCRIMINATE: they moved to the UNHELD worker, where a dropped check falls through to possession and answers `-KOS_EPERM` instead. What the sim cannot model is the bus classification itself: that an unprivileged store is silently DISCARDED remains a `pvprobe`-only fact, as does any chip's actual mask column. A chip with no backend answers `-KOS_ENOSYS`, never 0: a caller reaching for the seam has a register the bus refuses it, so a success answer would report a store that never happened. Every call site READS THE REGISTER BACK, because the discard is silent in both directions and the read-back is the only evidence a store landed -- and a read-back comparison must mask any field the hardware itself drives (the XMC `FDR` `RESULT[25:16]` case), or a landed store reports as discarded. `arch_periph_reg_write`'s default decline is a ONE-SYMBOL archive member (`arch/common/arch_periph_reg_write_default.cc`), NOT a weak symbol. The load-bearing half is that a chip's definition must live in an ALWAYS-ANCHORED archive member (`chip_<chip>.cc`, force-loaded via `-u g_isr_vector` -> `startup.S` -> `Reset_Handler`), because that member is extracted in link pass 1 before `syscall.cc` makes the symbol undefined. Scan order (`kickos_arch_*` after `kickos_chip_*`) is only a BACKSTOP and has never actually been exercised: MEASURED with arch before chip inside the rescan group, the link still succeeds and resolves CORRECTLY from the anchored member, the map showing zero mentions of the default. A duplicate-definition error is therefore NOT the guarantee -- it is not even a reliable backstop, and no doc should claim it. The anchored member IS the invariant, and a chip putting its definition in a dedicated TU nothing else references gets NEITHER protection and SILENTLY DECLINES at runtime: MEASURED by reversing the group AND moving `arch_idle_wait` into an unreferenced TU, whereupon the link succeeded with ZERO diagnostics while `objdump` showed the fallback's `wfi` where the chip's `nop` belonged. The anchoring is now ENFORCED in-tree, not merely evidenced, by `tests/check_seam_defaults.sh` (ctest `seam_defaults`, on every board): its leg 2 requires the fallback member to be ABSENT from the selftest's `-Wl,-Map` link map wherever a backend defines the seam, its leg 3 requires the fallback to be PRESENT and pulled by that exact symbol where none does, and its leg 4 refuses any weak symbol outside `tests/weak_allowlist.txt`. This is no longer a one-off for this seam: it is how EVERY optional seam in the tree resolves, `__attribute__((weak))` having been removed from all of them (`arch/CMakeLists.txt:11-71` states the rule canonically). Honest about the mechanism -- it is LINKER behaviour, not language semantics, but behaviour every Unix-like linker and MSVC `.lib` shares, unlike `weak`, whose archive interaction is implementation-defined. Adding a second symbol to the default TU breaks the member's other half (it would be extracted unconditionally and collide on every chip with a backend). Membership in the class-2 family requires a MEASURED hardware refusal, never a plausible reading of a manual.
  - *applies:* MMIO isolation, syscall, user/kernel boundary; kernel + per-chip backends (enforcing chips)
  - *source:* arch/include/kickos/arch/arch.h (arch_periph_enable / arch_periph_reg_write); kernel/syscall/syscall_mem.cc (caller_holds_mmio_block / caller_holds_mmio_reg); kernel/syscall/syscall.cc (the KOS_SYS_PERIPH_ENABLE and KOS_SYS_PERIPH_REG_WRITE arms); arch/common/arch_periph_reg_write_default.cc (the lone-TU decline); arch/arm/chip/xmc4800/chip_xmc4800.cc (the U0C1 FDR/BRG/CCR allowlist); tests (selftest periph_enable_unheld / periph_reg_write_unheld, whose arm 3 is the offset bound); user/apps/xmc4800-relax/pvprobe (the silicon discriminator)

## Tickless timer & clock

- **`timer-min-delta-guard`** -- The tickless one-shot timer must never be armed for a compare that may already be in the past: ktime_rearm floors the next deadline at now+KICKOS_TIMER_MIN_DELTA_NS. A sub-min-delta RR quantum (including a hostile user value) collapses to the min slice rather than re-arming every tick (interrupt storm).
  - *applies:* tickless timer; kernel + all arches
  - *source:* kernel/time/time.cc:94-101; kernel/sched/policy_fifo_rr.cc:62-81

- **`rearm-before-switch`** -- ktime_rearm must program the next-event timer for the INCOMING thread before arch_switch, because the outgoing thread will not return to switch_to until it is itself resumed -- so the incoming thread's policy deadline (RR slice) must be armed now, not after the switch.
  - *applies:* tickless timer, context switch; kernel
  - *source:* kernel/sched/sched.cc:31-37,75-85

- **`timer-delta-clamp-before-convert`** -- The ns->cycle conversion for the one-shot timer must clamp the delta to the counter's one-shot range BEFORE the ns*freq multiply (else a far-future or UINT64_MAX deadline overflows), and sleep deadlines must saturate to UINT64_MAX on now+ns overflow. A clamped deadline fires early and the kernel re-arms the remainder (harmless extra wake).
  - *applies:* tickless timer, ns<->tick; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/common/arch_arm_common.cc:89-123; kernel/time/time.cc:126-133; arch/rx/rxv3/arch_rxv3.cc:258-296; arch/xtensa/lx6/arch_xtensa.cc:305-338

- **`cycle64-wrap-extend-atomic`** -- The software 32->64-bit extension of the free-running cycle counter (catch-wrap on each read) must run under the critical section so the {read counter, compare to last, bump high} sequence is atomic against a concurrent reader from thread and ISR context. LIMITATION: a wrap not observed within one 2^32-cycle period is missed (M1).
  - *applies:* tickless clock; armv7m (DWT), rx (CMTW1), xtensa (CCOUNT)
  - *source:* arch/arm/armv7m/arch_armv7m.cc:38-44,62-76; arch/rx/rxv3/arch_rxv3.cc:48-53,90-104; arch/xtensa/lx6/arch_xtensa.cc:70-74,141-155

- **`conversions-track-live-clock`** -- All ns/cycle conversions and the SysTick/baud programming must track the LIVE SystemCoreClock (or kickos_rx_timer_hz), not a compile-time constant; the cached reciprocal-multiply / max-delta must be recomputed when the clock value changes. A PLL bring-up that updates SystemCoreClock must therefore keep the timer and clock correct.
  - *applies:* tickless timer, ns<->tick, SystemCoreClock; armv7m, armv6m, rx, xtensa
  - *source:* arch/arm/armv7m/arch_armv7m.cc:54-56,78-107; arch/arm/common/arch_arm_common.cc:39-47,94-119

- **`timer-disarm-clears-pend`** -- 'Disarm' must mean no callback will fire: disarming (and reprogramming) the one-shot timer must clear any interrupt request already latched while the line was masked (ARM ICSR PENDSTCLR; RX clears the IR flag), or a stray timer callback fires once on the next IrqLock release.
  - *applies:* tickless timer; armv7m, armv6m, rx
  - *source:* arch/arm/common/arch_arm_common.cc:124-137; arch/rx/rxv3/arch_rxv3.cc:298-302

## IRQ dispatch

- **`irq-table-no-null-slots`** -- Every IRQ line is seeded (by irq_init, before any driver attaches) with the null-object default handler that masks the line and bumps the spurious counter, so the ISR dispatch path indexes the table with NO null check and an unhandled enabled line cannot storm or be silently dropped.
  - *applies:* IRQ dispatch; kernel + all arches
  - *source:* kernel/irq/irq.cc:42-74,173-189; kernel/init/kmain.cc (irq_init, before console_buffer_init)

- **`one-driver-per-line`** -- A line may be claimed (irq_attach or irq_register) only while it still holds the null-object default; a second claim fails (-1/false) rather than overwriting an existing driver and orphaning its irq_wait forever. No stealing.
  - *applies:* IRQ dispatch; kernel
  - *source:* kernel/irq/irq.cc:81-98,110-138

- **`isr-mask-then-wake-wait-rearm`** -- The first-level ISR must mask the line (so it cannot re-fire while its driver services it in thread context) then post the bound notification. The line is re-armed (unmasked) by the driver's NEXT irq_wait, which auto-re-arms the previously-consumed line before blocking -- so a `wait; service` loop alone keeps receiving IRQs (no forgot-to-ack deadlock). Calling irq_wait asserts the previous event was fully serviced (e.g. device W1C done) before the auto-re-arm unmask -- the same service-before-unmask ordering the explicit ack used to carry. irq_ack stays OPTIONAL and idempotent: an early re-arm that only reacts sooner to a still-pending latch -- a raise on a masked line is latched one-deep and redelivered at the next unmask, so neither the ack nor the early re-arm is load-bearing for keeping the event (the latch-and-coalesce contract carries it either way); a double ack, or an ack after the next wait already re-armed, is a no-op. The per-binding needs_rearm flag is set when irq_wait RETURNS (event consumed) -- NEVER in the ISR (ISR-set races the ack;compute;wait unmask -> phantom wake -> empty-FIFO read). irq_register arms the first IRQ (needs_rearm starts false). The ISR handler runs by index with its arg being the pre-bound binding -- no table search on the hot path (latency invariant).
  - *applies:* IRQ dispatch, ISR wakes pre-bound target; kernel + all arches
  - *source:* kernel/irq/irq.cc:35-52,146-192; kernel/include/kickos/irq.h:31-42; arch/include/kickos/arch/arch.h:144-160; arch/sim/sim.cc:715-725

- **`line-masking-owned-by-handler`** -- A bound IRQ line must re-deliver on every fire; masking policy is owned by the handler tier, NOT the arch first-level / doorbell dispatcher, which only demuxes the physical source and calls kickos_isr_irq(line). A tier-1 (IRQ-as-event) binding masks on entry (irq_event_isr) and re-arms (unmasks) on the driver's next irq_wait, or earlier via the optional irq_ack; a tier-2 (irq_attach) binding has no re-arm path, so any masking the arch dispatcher imposes strands it -- the line dies after one delivery and later injects are dropped. End-property, not code shape: an arch's dispatcher must not add masking its handler tier never undoes (the xtensa doorbell once did, and a tier-2 waiter hung).
  - *applies:* IRQ dispatch; software-doorbell backends: sim, rv32imac, rxv3, xtensa
  - *source:* kernel/irq/irq.cc (irq_event_isr masks; irq_wait auto-re-arms, irq_ack optional early re-arm); arch/xtensa/lx6/arch_xtensa.cc, arch/riscv/rv32imac/arch_rv32imac.cc, arch/rx/rxv3/arch_rxv3.cc, arch/sim/sim.cc (doorbell dispatchers: demux + deliver only)

## Console

- **`console-single-producer`** -- The buffered console ring is a strict single-producer/single-consumer: the buffered path (arch_console_write) is entered ONLY from thread context with the ring armed and not panicking; ISR context, fault context, panic, and pre-arm boot all fall back to the bounded polled writer (arch_console_write_sync). console_emit is the single routing chokepoint; any new path that logs from a raw ISR must not reach the buffered producer. console_emit consults the three-state ownership axis g_console_state (KERNEL_OWNED buffered/sync as above; USER_OWNED drops the chip path entirely -- RTT still carries it; RECLAIMED polled-only) BEFORE the buffered-vs-sync sub-decision. A device poke while KERNEL_OWNED brackets itself in the g_chip_writers count so kos_console_publish (which flips the state to USER_OWNED last) drains a stale racing writer off the device before returning; console_tx_write's disarm fallback re-reads the state and DROPS the poke unless still KERNEL_OWNED.
  - *applies:* console single-producer ring; kernel + buffered-console chips
  - *source:* kernel/init/console.cc:47-127 (state axis + g_chip_writers + console_emit), 204-220 (kpanic_enter reclaim wiring); kernel/init/console_tx.cc:108-124 (disarm re-check), 247-258 (console_tx_deinit); kernel/syscall/syscall.cc (KOS_SYS_CONSOLE_PUBLISH drain); lib/include/kickos/console_tx.h; docs/reference/console.md

- **`console-publish-prime-atomic`** -- The producer's 'copy burst, publish head, enable TX IRQ' must publish head and enable the IRQ together under IrqLock, atomic against the ISR's 'drain to empty, disable IRQ', so there is no lost wakeup; the TX IRQ stays enabled whenever the ring is non-empty and the ISR disables it only on empty. The TX ISR therefore MUST sit in the IrqLock-maskable device band and must never sem_post/switch/block.
  - *applies:* console single-producer ring, ISR band; kernel + buffered-console chips (mk64f, xmc4800)
  - *source:* kernel/init/console_tx.cc:70-127; lib/include/kickos/console_tx.h:36-62; docs/reference/console.md

- **`panic-console-probe-independent`** -- Panic/fault output must not depend on the buffered ring or on an external debug probe: kpanic_enter sets g_console_panicking, flushes queued bytes in order via console_tx_flush_sync, then prints through the polled synchronous writer and halts. kpanic_enter calls arch_console_reclaim() and flips the state to RECLAIMED from ANY prior state, not only USER_OWNED: the ownership axis tracks a PUBLISH, never whether the device is GARBLED, and a thread granted the console window can wreck the channel with no publish at all (KERNEL_OWNED). The gate is therefore `state != RECLAIMED`, and the RECLAIMED store happens BEFORE the call -- which makes the reclaim UNCONDITIONAL-ONCE, so a synchronous fault inside the reclaim body re-enters and stops rather than recursing with the old state (a pre-existing recursion hazard the widening closed), and a body that truncates the byte in the shift register cannot cut the banner it just printed. Every chip body must be IDEMPOTENT ABSOLUTE STORES for this to be safe on a device no driver ever touched -- that idempotence is the LOAD-BEARING justification for the widened gate, not an aside. WITNESSED on silicon (`user/apps/xmc4800-relax/conreclaim`, xmc4800-relax, `c5d9b0d`): a KERNEL_OWNED channel gated at `KSCFG.BPMODEN=1, MODEN=0` still delivered its `=== MPU FAULT ===` banner, where the pre-widening behaviour was nothing after the pre-scramble line. kickos_isr_fault funnels through kpanic_enter FIRST so a terminal fault in the userspace driver still reclaims and prints. M2 DEPENDENCY: only a TERMINAL fault exit may reclaim -- a kill-and-resume fault path must NOT, since the driver keeps the device and a dark report there is correct. The synchronous writer must remain a real transport (the fallback TU arch/common/arch_console_write_sync_default.cc aliases arch_console_write, which is correct ONLY on a polled-only chip; a buffered console MUST define its own), never RTT-only.
  - *applies:* console panic-sync; kernel + all chips
  - *source:* kernel/init/console.cc:42,54,116-140 (state routing + panicking flag), 229-252 (kpanic_enter + reclaim), 298-304 (kickos_isr_fault funnel); arch/common/arch_console_reclaim_default.cc (the no-op fallback); docs/reference/console.md

## Telemetry

- **`telemetry-emit-atomic-one-lock`** -- Every telemetry emit must assign the sequence number, sample arch_trace_now(), encode, and write to the sink under ONE IrqLock; splitting them lets a preempting context interleave an out-of-order seq/stamp and silently corrupt the host's loss/latency accounting. records_attempted/dropped are RMW under that same lock.
  - *applies:* telemetry record framing; kernel (all arches)
  - *source:* kernel/include/kickos/ktrace.h:44-134; docs/reference/telemetry.md

- **`telemetry-record-atomic-drop`** -- The telemetry sink is whole-record-or-drop: the ch1 ring checks free space for all n bytes up front and drops the entire record if it won't fit (a half-written binary record would desync the decoder permanently). Records are fixed-length, little-endian, self-delimiting; type tags are nonzero so a zeroed buffer never decodes as valid. One slot is reserved so head==tail is unambiguously empty.
  - *applies:* telemetry record framing, sink; lib/rtt + record.h (all arches)
  - *source:* lib/rtt.cc:92-124; include/kickos/trace/record.h:15-18,35-43,76-85; docs/reference/telemetry.md

- **`switch-record-from-physical-contexts`** -- The SWITCH {from_tid,to_tid} record must be emitted from the tids read out of the two contexts that PHYSICALLY swapped, never by re-reading g_arch_next or shared scheduler state (a preempting ISR can rewrite the decision between switch_to and the physical swap). trace_tid is stamped once at thread_create and read at the pinned ctx offset; from_tid==0xFFFF on the first switch; multiple wakes in one ISR collapse to exactly one SWITCH record.
  - *applies:* telemetry, context switch; armv7m, armv6m, rx, xtensa, sim
  - *source:* arch/include/kickos/arch/arch.h:80-88,205-210; arch/arm/armv7m/switch.S:43-95; arch/sim/sim.cc:106-131,235-251,481-523; kernel/thread/thread.cc:75-79; docs/reference/telemetry.md

- **`telemetry-emit-fp-and-fault-free`** -- The context-switch telemetry emit runs in the PendSV/SWINT/L1 tail with the incoming thread's FP state live in registers, so its whole call path is built -mgeneral-regs-only and must touch NO FP register. Fault/NMI handlers must never call ktrace_* (they preempt the BASEPRI/PRIMASK lock and would issue records out of the atomic emit region).
  - *applies:* telemetry FP-register-free ISR paths; armv7m, rx, xtensa
  - *source:* kernel/ktrace/ktrace.cc:1-8,51-55; docs/reference/telemetry.md

- **`idle-is-trace-id-zero`** -- Idle must be the first thread created so it receives trace id 0 (the decoder keys CPU% off tid 0 == idle); kmain asserts g_idle_tcb.id==0. The per-Kernel tid counter starts at 0 and, on wrap, skips both 0 (idle-only) and 0xFFFF (the no-thread sentinel).
  - *applies:* telemetry framing, thread identity; kernel
  - *source:* kernel/thread/thread.cc:14-29; kernel/init/kmain.cc (the g_idle_tcb thread_create + the g_idle_tcb.id == KICKOS_TID_IDLE assert); kernel/include/kickos/thread.h:48-51

- **`telemetry-off-zero-cost`** -- With telemetry compiled out, every ktrace_* entry point is an empty inline (no symbols, hot paths byte-unchanged) and the ctx.trace_tid field and arch_trace_stamp_id seam are elided, so the telemetry-OFF struct layout and switch paths are byte-identical to a build that never had telemetry.
  - *applies:* telemetry; kernel + all arches
  - *source:* kernel/include/kickos/ktrace.h:142-154; arch/arm/armv7m/include/kickos/arch/context.h:39-45; arch/include/kickos/arch/arch.h:80-88

- **`trace-clock-u32-anchored`** -- arch_trace_now() is a raw monotonic u32 counter that wraps (armv7m DWT CYCCNT, rx/xtensa cycle/CMTW counters, sim ns/1000 us); absolute time is reconstructed by the decoder from the two SESSION clock anchors (near at init, far at shutdown). A target with no such source must not define KICKOS_HAVE_TRACE_CLOCK and cannot enable telemetry. The closing SESSION + ch1 drain at shutdown must run with IRQs masked so no record lands after the records_attempted snapshot.
  - *applies:* telemetry trace clock, record framing; all arches
  - *source:* arch/include/kickos/arch/arch.h:70-88; arch/arm/armv7m/arch_armv7m.cc:192-198; arch/sim/sim.cc:366-419,576-581; kernel/include/kickos/ktrace.h:116-134

## Scheduler & instance state

- **`instance-scoped-state-no-arch-crossing`** -- All kernel runtime bookkeeping (ready lists, current/idle, sleepq, object pools, IRQ table, telemetry counters) lives in the single Kernel instance reached only via kernel(); the sim arch backend keeps its own parallel SimInstance and never crosses the arch seam. Multiple instances co-reside in one host process, so no cross-cutting global may leak scheduler/telemetry state across emulated MCUs.
  - *applies:* instance scoping, arch seam; kernel + sim
  - *source:* kernel/include/kickos/instance.h:1-9,27-92; arch/sim/sim.cc:49-104

- **`ready-bitmap-tracks-lists`** -- The priority ready bitmap bit p must be set iff ready[p] is non-empty: every push sets the bit, every remove that empties the list clears it. highest_prio() trusts the bitmap (31-clz) to pick the run list, and priority indexes both the ready[] array and a 1u<<prio shift -- so a stale bit or an out-of-range prio is an OOB read/UB.
  - *applies:* scheduler ready structure; kernel (FIFO/RR policy)
  - *source:* kernel/sched/policy_fifo_rr.cc:23-59,83-91; kernel/syscall/syscall_thread.cc (thread_spawn's prio bounds check, the sole entry for a user-supplied priority)

- **`tcb-link-node-shared-ready-xor-wait`** -- A thread's intrusive `link` node is shared between the ready list and a wait queue (mutually exclusive membership), while timer-list membership uses the SEPARATE tnext link. A wait-queue block must detach_current from the ready list BEFORE pushing onto the wait queue (else it clobbers the links the ready removal needs); a timed wait may be on the timer list and a wait queue simultaneously only because they use different links.
  - *applies:* scheduler / sync queue membership; kernel
  - *source:* kernel/sync/sync.cc:37-48; kernel/sched/sched.cc:118-127; kernel/time/time.cc:104-113; kernel/include/kickos/thread.h:38-45

- **`sem-post-direct-handoff`** -- Semaphore wakeups are a direct token hand-off: sem_post wakes the highest-priority waiter (FIFO among equals) and does NOT increment count; the woken waiter returns from sem_wait without decrementing. Count is incremented only when there is no waiter. Breaking this double-counts or loses a token.
  - *applies:* synchronization primitives; kernel
  - *source:* kernel/sync/sync.cc:13-34,58-91

## App entry & init seam

- **`app-entry-via-init-seam`** -- The kernel's root thread calls exactly one seam symbol `kickos_init_entry(argc, argv)` (`<kickos/sys/init.h>`) once kernel init is complete; the app's `main` is NOT itself pid-1. The provider of that symbol is a build-time-selected CMake target (cache var `KICKOS_INIT_PROVIDER`, default `kickos_default_init`, a `kickos_system` service that passes through `kickos_init_entry -> kickos_default_init_run -> kickos_app_main`). Low barrier is preserved: a plain app writes only `int main` and no manifest; a power user names their own provider target and may delegate to `kickos_default_init_run` to reuse the app-main body.
  - *applies:* boot/init, dependency inversion; kernel + build system + kickos_system
  - *source:* kernel/init/kmain.cc (root_entry -> kickos_init_entry); system/init/default_init_entry.cc; system/init/default_init_run.cc; system/include/kickos/sys/init.h; CMakeLists.txt (the KICKOS_INIT_PROVIDER block)

- **`init-return-is-shutdown`** -- RETURNING from `kickos_init_entry` is a single-shot system shutdown with that int status: root_entry calls the `kos_shutdown` SYSCALL, which reaches `kickos_terminate` -- drain the buffered console (`console_tx_flush_sync`), then `arch_shutdown(status)`. A persistent init must NEVER return (it parks or loops) -- running off its end shuts the whole system down. The shutdown is a gated syscall, not an unconditional call: it needs `AUTH_SYSTEM`, so a root that has narrowed that bit away (`authority-cap-narrows-only`) is REFUSED `-KOS_EPERM`, and root_entry then panics `"root: shutdown refused"` rather than running on. That panic MUST route through the `KOS_SYS_PANIC` syscall (`kos_panic`) and never call `kpanic` directly: root is unprivileged (`root-unprivileged-idle-alone-privileged`) and `kpanic` masks IRQs and reads kernel `.bss`, so a call from root's own frame faults on the panic path itself and LOSES the diagnostic -- measured faulting three ways before the syscall existed. An app whose main returns must therefore keep `AUTH_SYSTEM`; the failure is loud, which is why the bit is not forced back on.
  - *applies:* boot/init lifecycle; kernel
  - *source:* kernel/init/kmain.cc (root_entry's tail: kos_shutdown, then kos_panic on refusal); kernel/init/console.cc (kickos_terminate: console_tx_flush_sync then arch_shutdown); kernel/syscall/syscall.cc (the KOS_SYS_SHUTDOWN arm's AUTH_SYSTEM gate); system/include/kickos/sys/init.h

- **`ctors-run-before-init-entry`** -- App / libstdc++ / library global constructors run in the kernel root thread (kernel live, thread context so a ctor may issue a syscall like kos_clock_now) BEFORE `kickos_init_entry` is entered -- the normal C++ order. A custom init must not assume its own bring-up precedes those ctors. Every target STATES its app-ctor window: `__kickos_app_init_array_{start,end}` is a STRONG reference, defined by each chip linker script around its `.kickos_app_init_array` bucket and by `arch/sim/start.cc` as a deliberately EMPTY window (a hosted ELF's own runtime has already run the ctors before `main`, so walking them again would double-construct). EMPTY and ABSENT are therefore distinct at LINK time, which is the point: present-but-empty leaves `start == end` so the walk iterates zero times, silently; a script that omits the bucket fails the link with an undefined symbol. These bounds were once WEAK, which collapsed absent into a null the walk skipped -- that is how a monolithic `.init_array` could run every app ctor privileged from the reset handler AND skip the late walk entirely with no diagnostic.
  - *applies:* boot/init ordering, C++ ctors; kernel + all chips + hosted sim
  - *source:* kernel/init/kmain.cc:36-53,144-151; arch/sim/start.cc:14-33

- **`init-provider-fail-loud`** -- Exactly one target supplies `kickos_init_entry`, chosen by `KICKOS_INIT_PROVIDER`; a missing/unknown provider is a CMake FATAL_ERROR (checked late so a provider defined in user/apps is not false-tripped), never a silent fallback and never a weak symbol. The default provider's entry and run body live in DISTINCT TUs so a delegating override referencing only the run body does not drag in a second `kickos_init_entry`. An installed package freezes the provider it was built with and rejects a consumer override.
  - *applies:* build, entry seam; build system + kickos_system + installed package
  - *source:* CMakeLists.txt:345-346,470-477; system/CMakeLists.txt:16-22; cmake/KickOSConfig.cmake.in:37-43
