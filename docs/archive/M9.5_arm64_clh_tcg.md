# M9.5: twelve-core ARM64 CLH experiment under QEMU TCG

This compares ticket and CLH arbitration of the same BKL on twelve ARM64
guest cores. The x86 CLH gain was measured under KVM on physical host cores;
this ARM64 guest runs through multithreaded TCG on an x86_64 host, so its rate
does not measure a physical ARM64 cache hierarchy.

`qemu-arm64-benchsmp12` uses GICv3, 48 thread slots and the capacity budgets
for twelve IPC pairs. Each pinned yield worker completes 50,000 yields. Each
local IPC pair completes 5,000 calls per payload, at 8 and 256 bytes. The
CLH prototype is preserved as [a patch](M9.5_arm64_clh.patch) against the
shipped ticket backend (`git apply --unidiff-zero` in a scratch checkout).
Its `exchange_tail` is an inline `LDAXR`/`STLXR`
retry with no call in the exclusive interval. GCC's generic exchange linked
an out-of-line `__aarch64_swp8_acq_rel` helper at an app address and faulted
when the kernel called it in the earlier four-core prototype.

Both lock images completed the twelve-core yield and IPC workloads. Three
alternating ticket/CLH runs used
`-accel tcg,thread=multi -M virt,gic-version=3 -cpu cortex-a53 -smp 12`.
Guest-clock rates below are medians of three runs with the same 48-thread
configuration and no host affinity restriction.

| Workload | Ticket | CLH | CLH change |
| --- | ---: | ---: | ---: |
| Aggregate yield/s | 259,349 | 263,079 | +1.4% |
| 8-byte local calls/s | 25,428 | 24,681 | -2.9% |
| 256-byte local calls/s | 25,216 | 24,831 | -1.5% |

Raw ticket/CLH yield rates were 272,072/266,119, 259,349/263,079 and
246,535/245,117. The 8-byte call rates were 25,910/24,681,
25,428/25,390 and 23,899/23,734; the 256-byte rates were
25,790/24,831, 25,216/24,854 and 23,367/23,770. The rate drift and
cross-workload disagreement make these differences unsuitable for a physical
ARM64 performance decision. An earlier 32-thread experiment and a separate
set pinned to host CPUs 0-11 also showed no stable IPC gain.

Both lock variants passed the twelve-core `qemu_arm64_bench_lock`,
`qemu_arm64_smp_arrival`, `qemu_arm64_smp_doorbell` and
`qemu_arm64_selftest` gates. The selftest planned 193 arms. The larger
thread pool lets its thirteen-worker placement arms run, while its bounded
spawn-refusal arm may skip after its 24-child limit. The arrival and
doorbell gates now parse the boot banner's hexadecimal core count (`c` for
twelve). The CLH helper refactor rebuilt and completed both workloads.
The generic stress trace gate is registered below twelve cores: that app has
at most twelve live workers and several sleep immediately, so its test cannot
require an unpinned thread to run on all twelve cores. The selftest's
`threads_reach_every_core` arm passed with its synchronized thirteen-worker
crowd, and `bench_smp` completed its pinned worker on every core.

The x86 result remains a reason to test CLH on physical multicore ARM64.
This QEMU result establishes correctness, but no comparable IPC benefit.
The ticket lock therefore remains shipped on ARM64. The captured runs and
exact binaries are retained under ignored `build/m95/a64-12-*`.
