# M9.8 Arm newlib-nano profile

The full pinned newlib remains the default on Arm boards except `microbit`,
the QEMU Armv6-M test board. Conan builds a nano package from the same pinned
source and multilib; configure checks the matching toolchain nano header and
C++ archives, and the link probe confirms `libc_nano.a` comes from the pinned
package. `microbit` requires nano by default and accepts the full package only
with `-DKICKOS_MICROBIT_FULL_NEWLIB=ON` in a separate build directory.

The [raw size cells](M9.8_nano_size.tsv) were measured with Arm GNU 15.3 and
`arm-none-eabi-size` on the tree at commit "Give nano micro:bit a heap for its
per-thread libc scratch". Flash is `.text + .data` and static RAM is
`.data + .bss`. Each full/nano pair uses the same board and app. The nano
micro:bit cells include the 1,024-byte heap nano carves there; the full
micro:bit build carves none. The Blue Pill `errnoprobe` cells were measured the
same way at commit "Fit the errno probe's reclaim arm into 64 KiB boards", whose
reclaim arm touches only `strtok` and `rand` state on a board that takes the
terse diagnostic column; that commit changes no other image in this record.

| Board and image | Full flash | Nano flash | Full static RAM | Nano static RAM |
| --- | ---: | ---: | ---: | ---: |
| Blue Pill `hello` | 34,100 | 34,052 | 8,472 | 6,412 |
| Blue Pill `errnoprobe` | 40,144 | 44,560 | 9,916 | 7,180 |
| Blue Pill `selftest_p2` | 53,204 | 53,156 | 9,416 | 7,356 |
| micro:bit `hello` | 37,308 | 37,240 | 13,032 | 11,132 |
| micro:bit `errnoprobe` | 94,824 | 56,892 | 15,244 | 12,052 |
| micro:bit `selftest_p2` | 61,056 | 60,988 | 14,064 | 12,180 |

The nano profile saves about 2.0 KiB of static RAM on Blue Pill (2.7 KiB in
`errnoprobe`) and, heap included, 1.8 to 1.9 KiB on the emulated micro:bit
(3.1 KiB in `errnoprobe`). In `hello` and `selftest_p2`, which do not exercise
formatted I/O, it saves only 48 flash bytes on Blue Pill and 68 on micro:bit,
since returning the per-thread scratch at thread exit links `_free_r` into these
nano images. In micro:bit `errnoprobe`, whose `asctime` and `localtime` bring
full newlib's formatted I/O into the image, flash falls from 94,824 to 56,892
bytes. Blue Pill `errnoprobe` goes the other way, from 40,144 to 44,560 bytes:
its `strtok` and `rand` keep their state inline under full newlib, while nano
builds it through an allocation whose failure path asserts, and the assertion's
message brings nano's formatted I/O and stdio into the image. The QEMU
Cortex-M3 `initdemo` does use `printf`: its measured flash falls from 47,816 to
42,748 bytes, a 5,068-byte saving. Its fixed RAM allocation masks a static RAM
comparison. The QEMU micro:bit model has 32 KiB SRAM; a physical v1 board has
16 KiB, so the image
passes here do not show these test images fit physical micro:bit RAM.

On the rebased M9.8 branch, a fresh nano micro:bit build passed QEMU hello,
libc exit and all three split selftests. A fresh nano `qemu-m3` build passed
hello, errno, initdemo, libc exit and selftest. The `trap_redzone` callgraph
gate passed for both nano and the explicit full micro:bit comparison, and the
full comparison's hello image booted under QEMU. Supplying the full package
without that override failed at configure. The separate Arm GNU 15.2 CI
toolchain trial passed 36 selected micro:bit gates and its separately polled
hello and reclaim-witness gates before the rebase; the rebase changed no
runtime code.

Nano formatted I/O omits C99 and long-long formats; floating-point formatted
I/O needs explicit linker pulls. Arm's nano C++ archive terminates at the
first throw on the QEMU Cortex-M3 check, so nano does not export `kickos_cxx`.
The normal freestanding `kickos` target remains available. No silicon timing
or full formatted-I/O compatibility claim follows from these checks.
