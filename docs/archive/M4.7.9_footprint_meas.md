# M4.7.9 footprint capture: what a minimal posture earns, and what diagnostics cost

**Captured 2026-08-07 against `origin/master` = 510f52a.** A measurement record, not a decision
list; the rulings that rest on it live in `../design-flash-footprint.md`. Quote a figure from here
with this date. Its sibling capture for this milestone measures TIME rather than space:
`M4.7.9_teardown_latency_meas.md`, what a surviving thread loses when a peer dies.

**The bounded-waits knob measured below was DELETED in M4.7.9, and this capture is the evidence for
that.** Its 988 to 1008 bytes are 2.4% of free flash on the tightest part in the fleet, no board or
preset ever selected the off posture, and its help text over-stated the saving by a factor of ten.
The feature now ships unconditionally, so the rows naming it record a cost that is no longer
optional. The symbol is not spelled here, because it no longer exists in the tree.

**`KICKOS_PANIC_DUMP` gained a Kconfig symbol in M4.7.9, so section 4's "no configuration entity at
all" describes the tree as measured and not the tree today.** It is now an `int` in the "Debug and
test" menu and a board sets it with a plain `CONFIG_KICKOS_PANIC_DUMP=0` defconfig line; the
`-DCMAKE_PROJECT_KickOS_INCLUDE` injection that section describes is no longer needed to measure it.
The -388 recorded below is still the figure for the posture it was taken in, full prose. Against the
short diagnostic column the same knob earns **-272** on bluepill-c8 hello_c, because terse has
already shortened the dump's own format strings and there is less left for the knob to remove.

## Method, and the failure mode it is written against

Every number is `.text` from `readelf -SW` on a real linked ELF, differenced against another real
build of the same board and app differing in exactly one thing.

**No number here is a sum of per-symbol sizes.** The M4.7.8 arm audit reported symbol SIZES as
DELTAS and inflated its answer by about half: when a function changes signature its new symbol
counts as a full add while its predecessor's removal lands in an unread bucket. The tell was
visible (rows summing to 2114 against a stated 1444) and was missed. Where a per-object story is
given below it is a CROSS-CHECK against a measured whole, never the source of the headline.

**Noise band: +/- 8 bytes.** Three clean rebuilds of an identical tree and config gave
`bluepill-c8` / `hello_c` `.text` = 24496, 24496, 24504. Cause isolated: `kickos_app_build_stamp`
compiles `__TIME__` digits into immediates whose encoding size depends on the wall clock (`nm -S`:
0x8c / 0x90 / 0x94). Any delta at or below 8 bytes is noise and is flagged as such.

## 1. The optional-subsystem sweep

### bluepill-c8 (stm32f103, 64 KiB flash), `configs/base`

| feature off | hello_c | gpioblink | gates |
| --- | --- | --- | --- |
| bounded-waits knob (deleted) | -988 | -988 | 4/4 pass |
| `KICKOS_PANIC_DUMP=0` | -388 | -396 | 4/4 pass |
| console -> `none` | -500 | -500 | 4/4 pass |
| **all three, one build** | **-1884** | **-1888** | |
| sum of the three parts | 1876 | 1884 | |

The knobs are disjoint code: sum and combined agree inside the noise band. There is no overlap to
exploit and none to double-count.

### xmc4800-relax (MPU-enforcing, `CONSOLE_BOTH`, real service list), `configs/base`, hello_c

| feature off | delta |
| --- | --- |
| service list -> `none` (drops `xmcuart` + `xmcssc`) | -2624 |
| MPU enforcement, isolated | -1296 |
| bounded-waits knob (deleted) | -1008 |
| console -> `none` | -592 |
| `KICKOS_PANIC_DUMP=0` | -392 |
| cap supply 16 -> 8 | -208 (plus -144 `.bss`) |
| RTT (`both` -> `chip`) | -84, at the noise band |
| pinmap -> `none` | -8, noise |
| **all of the above, one build** | **-5904** (sum of parts 5920, overlap 16) |

**Trap, recorded so it is not re-stepped.** The `xmc4800-relax-flat` preset is NOT a one-thing
change: `boards/xmc4800-relax/Kconfig:10,14` gate the service list and pinmap on
`MEMORY_MODEL_MPU`, so `flat` silently drops both as well. It measures -3932. Forcing the two
providers back on isolates MPU alone at -1296, and 1296 + 2624 + 8 = 3928 against the measured
3932 closes the bundle.

Two-thirds of that 5.9 KiB is not minimalism. It is giving up MPU enforcement and the userspace
console driver, which is a different system rather than a smaller one.

### Candidates that turned out to cost nothing

Measured, not assumed:

- **RTT: 0 bytes.** `rtt.cc.obj` is never extracted from `libkickos_lib.a` (`grep -c rtt.cc.obj`
  on the link map is 0; `nm | grep -i segger` is empty). The standing worry about 5.1 KiB of
  `constinit` buffers in every image is false: 0 flash, 0 RAM.
- **Telemetry / ktrace: 0 bytes** when unselected. `ktrace.cc.obj` contributes nothing. Turning it
  ON costs 1200 bytes on xmc4800-relax.
- **Driver class and service layer**: no `stm32f103` arm exists in `system/driver/CMakeLists.txt`,
  so there is no archive to drop on that board.
- **Cap table**: bluepill-c8 is already at the floor, supply 7 against demand 7.

## 2. What diagnostic strings cost

String-literal bytes in the linked image, read out of the merged `SHF_MERGE|SHF_STRINGS` section
and split on NUL:

| board / app | `.text` | string pool | share |
| --- | --- | --- | --- |
| bluepill-c8 / hello_c | 24496 | 2052 (77 literals) | 8.4% |
| bluepill-c8 / gpioblink | 30420 | 2011 (74) | 6.6% |
| bluepill-c8 / selftest | 59292 | 11214 (430) | 18.9% |
| xmc4800-relax / hello_c | 30368 | 3143 (104) | 10.4% |
| xmc4800-relax / consoledemo | 70764 | 3703 (156) | 5.2% |

Attribution of the kernel's share:

| bucket | bp/hello_c | xmc/hello_c |
| --- | --- | --- |
| `KICKOS_ASSERT` / `KICKOS_UNREACHABLE` | 960 (n=27) | 1305 (n=35) |
| panic and diagnostic prose | 645 (n=27) | 670 |
| `kprintf` format strings | 310 (n=15) | 310 |
| driver bring-up prose | 34 | 755 (n=20) |

**`KICKOS_ASSERT` is the largest single kernel bucket in every image, 47% of kernel strings on
bluepill-c8**, because it stringifies the whole condition expression. The worst single literal is
86 bytes:
`assert: nr + domain_region_count(t->domain) + stack_regions <= KICKOS_MPU_MAX_REGIONS`.

### The measured ceiling for a terse mode

Mechanical transform in a second worktree: asserts reduced to one-character tokens, every literal
first argument of `kpanic`/`kputs`/`kos_print`/`kos::print` reduced to a token, every `kprintf`
format reduced to its `%` specifiers alone (arity and the `format(printf)` attribute preserved).
154 call sites in 34 files.

| board / app | baseline | terse (OS only) | delta |
| --- | --- | --- | --- |
| bluepill-c8 / hello_c | 24496 | 22636 | **-1860** |
| bluepill-c8 / gpioblink | 30420 | 28556 | -1864 |
| xmc4800-relax / hello_c | 30368 | 27860 | **-2508** |
| xmc4800-relax / consoledemo | 70764 | 68232 | -2532 |

**Terse diagnostics alone earn more than the entire knob family** (1860 against 1884 on
bluepill-c8, 2508 against 2000 on xmc4800-relax), and cost no feature.

Cross-check, the step the M4.7.8 audit skipped: measured -1860; string pool 2052 -> 360, i.e. -1692
of literals; residual -168 of code accounted per object (`kmain.cc` -76, `cap.cc` -48,
`syscall_ipc.cc` -20, `pinmux_run.cc` -12, `sync.cc` -8, `arch_armv7m.cc` -4, `syscall.cc` -4,
`console.cc` -4, `build_stamp` +6) = -1862 against -1860 measured, 2 bytes of alignment. The story
sums to the whole.

Stacking terse on the minimal posture: bluepill-c8 hello_c 24496 -> 21068, i.e. -3428 against a
sum of parts of 3744. **The 316-byte gap is the one place in this capture where sum-of-parts
materially over-states**, because `PANIC_DUMP=0` and `CONSOLE=none` remove strings a terse mode
would remove anyway.

## 3. Prose is a contract, and the full transform breaks it

Full ctest suite, baseline against the OS-only terse tree (app strings restored):

- **qemu: 24/24 pass -> 9 fail.** `qemu_mpu_fault`, `qemu_rootfault`, `qemu_ringppb`,
  `qemu_panicgate1..5`, `qemu_selftest`.
- **sim: 32/32 pass -> 12 fail.** `mpu_fault`, `rootfault`, `panicgate1..5`,
  `sim_published_panic`, `sim_driver_death`, `sim_uart_loopback`, `selftest`, `fault_dump`.
- **bluepill-c8 and xmc4800-relax: 0 broken.** Neither registers a prose-dependent gate.

The highest-fanout dependency is `tests/lib/panic.ere`: one regex read by `tests/lib/gate.sh:20`
AND by `CMakeLists.txt:616` as `KICKOS_PANIC_REGEX`, consumed by `assert_no_panic()` in six scripts
and by `FAIL_REGULAR_EXPRESSION` on `sim_stress`. `gate.sh:172-179` additionally sed-parses the
prose `attempted [a-z]* at 0x...` out of `kernel/init/console.cc:336`. Beyond the arms that
actually broke, 35 further prose assertions across 14 scripts are load-bearing, including all nine
of `check_sched_exit.sh`, `check_reboot.sh:28` (`reboot declined: rc=-38`), `check_app_arms.sh:46`
(`PASS (N arms)`), `check_hello.py:58` (`[KickOS] halted.`, a raw `write(1,...)` at
`arch/sim/sim.cc:600`) and `tests/integration/telemetry/check_flood.py:41`.

Knob postures measured against the same 24 qemu arms:

- `KICKOS_PANIC_DUMP=0` -> 3 fail, exactly the three the source comments predict.
- bounded-waits knob OFF -> 0 fail, but only 23 arms register: `qemu_sched_exit` de-registers
  rather than failing.
- `KICKOS_CONSOLE=none` -> 17 fail; the console IS the harness channel.

## 4. Not measured, and why

- **`lib/libc/fmt.cc`**: no knob of any kind exists (`lib/CMakeLists.txt` has zero conditionals).
  It contributes 612 bytes to bluepill-c8 hello_c per the link map and survives `CONSOLE=none`
  because the panic path still calls `kprintf`. No removal delta is reported because any variant
  would change more than one thing.
- **`KICKOS_PANIC_DUMP` has no configuration entity at all**: not a Kconfig symbol, not a CMake
  `option`, not a preset variable. It self-defaults to 1 in five arch files. Measuring it required
  injecting `-DCMAKE_PROJECT_KickOS_INCLUDE=<file with add_compile_definitions>`; passing it via
  `CMAKE_CXX_FLAGS` destroys the toolchain's `-mcpu`/`-mthumb` and the build dies in the assembler.
- **C++ runtime under `FULL_CXX`**: no knob, opt-in per app, 0 in every image measured.
- The terse transform does not cover `emit()`/`emitf()`/`diag()` (tests/tap), `wire_puts()`,
  `ksnprintf` followed by `print(buf)`, or the raw `write(1,...)` in `sim.cc`. The OS-core ceiling
  is near-complete (residual pool 360 bytes, of which 133 is app and libc), but the 9265 bytes of
  app and TAP strings in the selftest image are NOT covered by the measured ceiling.
