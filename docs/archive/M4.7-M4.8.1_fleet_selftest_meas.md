# M4.7.6 to M4.8.1 fleet selftest witnesses

**Three capture sessions, moved here from `../../STATE.md` when M4.8.1 merged.** Each is a silicon
TAP run of the selftest app over the physical fleet (`--preset <board>-st`), and each was taken
against ONE tree. A witness is valid for a TREE, so none of these can be re-earned by re-running
today: a rerun measures the tree it runs on, not this one. **Quote a row with its MILESTONE.** Every
milestone is squashed before it merges, so a hash a bench log stamped is orphaned by construction; the
hashes below are incidental, and a row that carries none is not thereby weaker.

**Which kind of unreproducible this is.** The strong kind for the fleet composition and the weak
kind for the method. The method is written down (`.session/bench.sh`, `.session/bench-fleet.sh`) and
the boards mostly still exist, but the trees these ran on are behind several merges and the arm
counts have moved since, so nothing a rerun produces recovers a row below.

**The live operational lessons these passes taught stay in `../../STATE.md`**, not here: the
service-list trap, the `f302nucleo` log split, the by-hand stream reconciliation on a board with no
ctest gate, and the fleet script's reason for existing all apply to the NEXT capture. What is kept
here is the evidence.

## 1. M4.7.6 and M4.7.7, discharged by ONE run (2026-08-06, `de2801d`)

Both silicon debts were taken together at `de2801d`, the M4.7.7 merge, on a rare day when both
benches were plugged at once. **One run discharges both** because M4.7.6 is an ancestor of that
tree, so a board that boots at all has exercised the `.init_array` deletion that was the whole of
the M4.7.6 risk; a separate `m476` run would only have earned something had this one failed. Six
boards, four ISAs, every enforcement class the fleet had, zero `not ok` anywhere. Logs
`.session/logs/m477-*.log`.

## 2. M4.7.8, all six boards at the FINAL tree (`19b548c` = `d00e342`)

Zero `not ok` anywhere: `rx72m`, `xmc4800-relax`, `frdmk64f` and `esp32c6-wroom` 95 ok enforcing,
`esp32-wroom` 91 ok, `f302nucleo` 51 + 40 ok across its two images. Logs
`.session/logs/m478c-*.log`.

**The captures carry TWO commit hashes**, `19b548c` on the first five boards and `d00e342` on the
last two, because the commits were reworded mid-pass. The trees are byte-identical and the enforcing
boards report the same 95 under both, so it is ONE witness of ONE tree.

**The K64F needed a second attempt earlier in the day**, for a reason worth knowing rather than
retrying blindly: its OpenSDA probe shows a SEGGER licence dialog once per calendar day, the
acknowledgement is date-stamped, and that pass crossed midnight. The board was on the bus and
healthy, and `bench.sh`'s preflight refused by name instead of capturing a 0-byte log.
`CONTEXT.local.md` carries the detail.
