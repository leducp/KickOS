# M9.7 exit measurement

The tree at commit "Price address-space map preflight across translating
backends" is the frozen code image. Five captures of each of the six M8.12
emulator presets carry that tree's clean banner, `bench: done`, and a passing
phase-table gate, and the campaign log records `rc=0` for every run. The
unedited console bodies are in
[`M9.7_exit_captures/`](M9.7_exit_captures/), with their
[`SHA-256 list`](M9.7_exit_captures.sha256) and
[`campaign verdicts`](M9.7_exit_campaign.log). Run
`python3 tools/bench/exit_rows.py docs/archive/M9.7_exit_captures --runs 5`
to reproduce the [table](M9.7_exit_rows.txt), one row per preset. The reader
takes the first field of the last sampled distribution in each image, the p50
bucket; the 8- and 256-byte round trips are the first untagged nanosecond rates.
The distribution cells are in cycles except `e2e-local` and `e2e-cross`,
which are in nanoseconds. The ranges in the table are the five run extrema.

These are **M9 exit readings, not M8.12-to-M9 speedups**. The M9.4 bench-row
split made every phase bracket and distribution sample cheaper. It changes
the instrument on every row, even where the row name and nominal span stayed
the same. None of the `switch`, `lock-hold`, `lock-wait`, `doorbell`, or E2E
distribution deltas against M8.12 is a kernel-only difference. The CALL and
REPLY phase rows also changed workload and span as the scheduler ownership,
cross-core ring and console work landed; they are excluded as historical
deltas. The round-trip time remains an end-to-end workload result, but M9
changed the path and the sampling machinery, so its M8.12 difference cannot
isolate the lock or a single code change. The baseline is retained in
[`M8.12_meas.md`](M8.12_meas.md) for context, with no percentage change table.

Both SMP exit images raised and closed all 1,000 E2E passes, but every
reported sample was `e2e-local`. Their `e2e-cross` cells have `n=0`, which
the reader prints as `-`; no cross-core E2E latency is claimed from this
campaign. The SMP `doorbell` rows have 256 samples and use the current
`p50/max/max` format, which the reader accepts alongside `p50/p99/max`.
An empty final distribution clears an earlier window's sample rather than
silently retaining it.

The independent M9.5 width experiment is the relevant BKL decision evidence:
on twelve pinned x86 guest cores under KVM, CLH arbitration of the **same**
BKL improved twelve local pairs by 23.8% for 8-byte calls in the final
matched batch; the owner-local second exclusion path gained 20.2% with six
cross-core pairs, lost 6.35% when all twelve pairs crossed cores, and cost
at low core count. See the [CLH record](M9.5_x86_clh.md) and
[mixed workload record](M9.5_x86_ipc_mixed.md). On two-core LX6 silicon,
the CLH candidate improved the contended yield rate by 1.2%, and the ticket
backend remained the smaller choice; see the
[LX6 capture record](M9.5_lx6_clh.md). This M9.7 emulator table neither
overrides those decisions nor measures a physical ARM64 or RV64 kernel.

The retained contract is per-core ready-queue ownership with one BKL across
shared-kernel transactions. The static caller-held gate and its compiler
coverage are recorded in `STATE.md`; the separate
[map preflight record](M9.7_map_preflight.md) prices the three translating
backends. QEMU timings include emulator behavior, guest workload and host
scheduling. They are not a decomposition of kernel time on silicon.
