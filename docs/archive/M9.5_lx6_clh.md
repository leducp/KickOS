# M9.5 LX6 ticket and CLH kernel lock on silicon (2026-09-26)

The captures behind the LX6 figures in the
[M9.5 options record](../design-m9.5-bkl-options.md). Board: ESP32-WROOM (ESP32-D0WD-V3, two
LX6 cores at 240 MHz), preset `esp32-wroom-benchsmp`, every capture through `tools/bench/bench.sh`
with `CAP_SECS=300`, all taken 2026-09-26 between 12:29 and 12:40.

Trees: all eight images were built from the M9.5 branch. The ticket `bench` and `selftest`
images come from the clean tree. The CLH images carry an uncommitted change, the LX6 CLH lock
variant, and the two ticket `bench_smp` images carry the `bench_smp` extension to LX6 before it
was committed; each of those banners reads `-dirty`. The CLH variant was not shipped: LX6 keeps
the ticket lock.

`bench_smp` pins one worker to each core, and each worker makes 200,000 `kos_yield` calls.
The ordinary `bench` call/reply sweep runs predominantly on core 0, so its rows do not
measure a contended lock.
